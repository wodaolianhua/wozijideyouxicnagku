# 项目章程 · 大型战争策略游戏

## 一、项目一句话定义

玩家扮演一名真实将领，既能亲自上阵带兵作战，也能以上帝视角宏观指挥大部队；像帝王一样挑选人才、委派庶务，把势力从一隅经营到天下。目标是**逐步做出可玩的原型**，当前阶段先做设计规格与规则骨架。

## 二、架构宪法（不可违背）

整个项目建立在一条主干上：

```
玩家 / 人才 / AI势力  →  统一指令 Order  →  结算器 Resolver  →  世界状态 World State  →  时间推进 Tick  → 回到决策
```

**所有玩法最终都必须能表达为一条 `Order`。** 亲自上阵、派将出征、修城屯田、征兵练兵，全部是同一种指令的不同 `Action` 值。

三条派生铁律：

1. **确定性**：相同 `WorldState` + 相同 `Order` 序列，必须得到完全相同的 `WorldState`。禁止在规则层使用未播种的随机数、系统时间、浮点累加顺序依赖。
2. **单向依赖**：表现层依赖规则层，规则层**绝不**依赖表现层。规则层不得 `import/using` 任何引擎 API（Unity / Three.js / WebAPI）。违反此条 CI 直接构建失败。
3. **AI 与玩家同路**：AI 势力只能通过产出 `Order` 影响世界，绝不允许直接修改 `WorldState`。人才系统同理——人才通过 `Order.AssignPost` 获得岗位，而非直接被赋权。

## 四、目录约定与跨包协作

**类型定义在项目根目录的 `StrategyGame.Contracts/`，是编译通过的 `.cs` 工程**，不是文档。C# 包通过 `ProjectReference` 引用，禁止手抄——手抄会导致类型不匹配、编译失败。

每个包目录还包含一份契约源码副本（`接口契约_共享类型/`），因为**执行者只读自己那一个文件夹**，看不到根目录。

每个包固定包含：

- `README_任务书.md` —— 是什么、边界在哪、交付什么、禁止事项
- `接口契约_共享类型/` —— 契约源码副本（**只读**）+ 使用说明

### 三条协作铁律

1. **类型只能来自契约工程**，禁止手抄或重新声明
2. **文件归属唯一**：每个文件只有一个 owner 包可写，其他包只读（归属表见 `Interfaces.cs` 的 `FileOwnership`）
3. **接口只能新增**：改字段名/签名/删定义必须走变更流程（`00_项目管理/变更申请/`）

详细规则见 `00_项目管理/跨包协作规范.md`。

## 五、当前阶段范围

**做**：设计规格、规则骨架、一个 6 城 3 势力的最小可玩闭环、回合制批量战斗结算、人才指派生效验证。

**不做**（明确延后）：实时 3D 战斗、大世界探索、美术资产、完整数值平衡、多人联机、跨平台。

原型阶段的核心验证问题只有一个：**"像皇帝一样用人"到底是核心乐趣还是附加噱头？** 这个答案决定后续 80% 的开发优先级，所以必须最早拿到。
