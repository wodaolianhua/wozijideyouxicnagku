# 裁决 · 05A 重定 scope：3D 视角切换可玩外壳（取代原 2D PixiJS 第 1 轮）

**日期**：2026-10-30
**提出**：用户确认想要 **3D 第一视角 + 视角切换**（把设计层"双层视角/亲征机制"做成了可视化），并要求**骨架优先、后续功能逐步加**。
**裁决**：批准 05A 第 1 轮从「2D PixiJS 战略 UI（亲征仅占位按钮）」重定为「3D 视角切换可玩外壳」。原 `提示词_第1轮.md`（2D）作废归档，新提示词见 `提示词_第1轮_3D.md`。

---

## 一、范围变更要点（00 拍板）

1. **技术栈**：前端从 PixiJS 改为 **three.js 8.x**（3D 世界渲染）；后端与宿主 API 完全不变（沿用原第 1 轮提示词第 3 节的后端接缝，引擎无关）。
2. **双层视角真实化**：
   - 上帝视角：战略地图（3D 地形 + 城池/部队 mesh + 邻接连线）+ 势力/人才面板 + 回合结算；
   - 亲征视角：第一/三人称，操控君主行走、走近城池/部队浮现交互气泡、军议下令。
   - 不再只是占位按钮（原 R4 口径作废）。
3. **亲征表现**：进入亲征视角后可行走、与城池/部队交互；下达 `Dispatch` 触发**战斗演出（cinematic）**，复用回合制批量结算结果。**不实现 05B 实时战斗逻辑**。
4. **骨架优先**：首轮用 three.js 程序化占位体（盒/胶囊/地形面）搭出可玩外壳，**零外部资源即可运行**。
5. **资产槽（asset slot）机制**：渲染对象从 `05A_表现层_战略UI/src/web/assets/` 按固定文件名加载 GLTF/GLB；文件缺失/损坏 → 回退占位体，**绝不因缺失资源崩溃**。执行 AI 必须在汇报里列「资产槽清单」（实体 → 文件名 → 放置路径）。用户可自行放入建模文件替换占位。
6. **性能红线（验收硬门槛）**：大地图必须 `InstancedMesh` 批量渲染重复实体 + 视锥剔除 + 分块/LOD；目标在 Intel UHD730 核显下 6 城 + 部队 + 地形稳定帧率。性能不达标打回。
7. **部门体系（含科技部门）+ 时代演进（封建 → 热武器 → 飞船）**：本轮**不做**。游戏应设若干大部门（科技/军事/内政/外交/经济等），由科技部门驱动研发，推动从封建→热武器→未来飞船的时代演进——本质是按部门划分的职能系统，**不是独立「科技树」功能**。列入后续独立功能轮次，细节见 `00_项目管理/backlog_后续功能.md`（需先补 01 设计层规格）。
8. **不新增顶层包**：3D 外壳仍在 05A 内；05B 实时战斗逻辑继续延后。是否需要新包由 00 后续裁定。
