## D3 自动补给规则（定死，执行 AI 不得自由发挥）

在 `TurnPipeline` **第 8 步**（现有 `RunSoldierConsumption` 占位处）实现：

1. **时点**：第 7 步到期指令执行之后——当月征兵（Recruit）进池的兵当月即可编入部队。
2. **对象**：该势力所有 `Soldiers > 0` 的部队（0 兵部队视为已覆灭，**不补**），按 `Army.Id` 升序。
3. **分配**：设兵源池 `Resources.Soldier = P`，存活部队数 n：
   - 每队先得 `floor(P / n)`；
   - 余数 `P mod n` 按 Id 升序前若干队每队 +1；
   - 分配后兵源池**清零**（`Resources.Soldier = 0`）。
   - P=0 时什么都不做。
4. **表达**：走现有 delta 机制（`DeltaTarget.Army` + `DeltaField.ArmySoldiers` 增兵；
   `Faction/Resources.Soldier` 归零 delta），不允许在 pipeline 里裸改状态后不留 delta。
5. **饥荒语义随改**：原「兵源池归零即饥荒」在自动补给后会每月误触；
   新触发条件 = **兵源池为 0 且该势力无任何 `Soldiers > 0` 的部队**（无兵可用才饥荒），
   惩罚数值不动（`PlaceholderNumbers.FamineMoraleLoss`）。
6. **不新增** ActionType、不新增配置项、不新增部队编制上限字段，
   `SoldierSafetyThreshold = 500` 等任何数值一律不动。

预期效果（用 06 数据验证，不保证具体数字）：数月后部队兵力可越过 500 安全线，
Dispatch 分支可达，攻陷率/僵持率/士气指标开始有区分度。

## D4 per-faction 计数器（契约 v1.5）

- `WorldState`：**删除** `int ActionsThisMonth`；
  **新增** `Dictionary<int, int> ActionsThisMonthByFaction`（key=势力 Id，value=本月已执行数），
  `Clone()` 必须深拷贝该字典。
- `GameClock` 月初推进时清零该字典（重建或逐键置 0，确定性等价即可）。
- 额度守卫（`IResolver.cs` 现有 TODO 处）按**指令发起势力 Id** 查字典，
  六个 resolver（Recruit/Develop/AssignPost/Fortify/Dispatch/Rest）的计数 delta 全部改为
  per-faction（带 factionId）。`StateApplier` 配套支持。
- `StateSnapshot`/既有测试中对旧字段的引用同步改新口径；
  不允许保留旧字段做兼容（两套计数必成隐患）。
- 拒绝码 `RejectedInsufficientCapacity`（码 9）语义不变，只是按势力独立判定。
