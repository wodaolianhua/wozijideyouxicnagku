# 跨包协作规范

## 这份文档解决什么问题

多个执行者（人或 AI）在**互不知晓对方进度**的前提下同时开发，必须保证最后能组合成功。

本规范定义了三条硬规则。违反任何一条，最终组合一定失败。

---

## 规则 1：类型只能来自契约工程，禁止手抄

### 问题

早期版本把类型定义放在 Markdown 代码块里。结果是每个包都要手抄一遍，抄出来的版本必然不一致——字段名差一个字母、枚举少一个值、构造函数参数顺序不同。这类错误在编译期才暴露，返工成本极高。

### 规则

**所有包共享 `StrategyGame.Contracts` 工程。它是类型的唯一来源。**

| 包 | 如何引用 |
|---|---|
| 03 规则内核 | `ProjectReference` |
| 04 智能体 | `ProjectReference` |
| 06 工程验证 | `ProjectReference` |
| 02 内容数据 | `ProjectReference`（用于配置类型） |
| 05A 表现层（TS） | 不引用，按`线格式规范`对齐 JSON |
| 05B（延后） | 待定 |

csproj 写法：

```xml
<ProjectReference Include="..\..\StrategyGame.Contracts\StrategyGame.Contracts.csproj" />
```

### 禁止

- 禁止在任何包里重新声明 `WorldState` / `Order` / `ResolveResult` 等类型
- 禁止复制粘贴契约代码到自己的包
- 禁止在实现类上重复定义接口方法签名

### 为什么有效

签名对不上，**编译立即失败**，而不是等联调才发现。IDE 的自动补全也能直接看到可实现的接口。

---

## 规则 2：文件归属唯一，禁止多人改同一文件

### 问题

两个包同时修改同一个文件 → 合并冲突；更糟的情况是两边都改了，谁也不知道对方改了什么，代码能编译但逻辑已经错乱。

### 归属表

| 路径 | Owner | 其他包|
|---|---|---|
| `StrategyGame.Contracts/` | 00 项目管理 | 只读，只引用 |
| `StrategyGame.Core/src/WorldState.cs` | 03 规则内核 | 只读 |
| `StrategyGame.Core/src/Order.cs` | 03 规则内核 | 只读 |
| `StrategyGame.Core/src/Resolvers/` | 03 规则内核 | 只读 |
| `StrategyGame.Core/src/TurnPipeline.cs` | 03 规则内核 | 只读 |
| `StrategyGame.Core/src/Config/` | 02 内容数据 | 只读 |
| `StrategyGame.AI/src/` | 04 智能体 | 只读 |
| `assets/data/` | 02 内容数据 | 只读 |
| `StrategyGame.Tools/` | 06 工程验证 | 只读 |
| `StrategyGame.UI/` | 05A 表现层 | 只读 |
| `StrategyGame.Core/src/Tick/` | 06 工程验证（存档回放工具） | 只读 |

### 规则

- **只有 Owner 包可以修改自己名下的文件。**
- 非 Owner 包需要该文件变化时，**提交变更申请**（见规则 3），由 Owner 包执行修改。
- 每个包只能新建自己名下目录里的文件。

### 好处

任何时刻一个文件只有一个写入者，冲突在结构上不可能发生。

---

## 规则 3：接口只能新增，变更走流程

### 规则

- **可以新增**：新增枚举值（用 100以上的编号，见契约）、新增接口方法、新增可选字段
- **不可以**：改字段名、改字段类型、改方法签名、删除定义、修改已有枚举值

### 变更流程

```
1. 写变更申请（放00_项目管理/变更申请/YYYYMMDD-简述.md）
   内容：改什么、为什么、影响哪些包、迁移方式
   
2. 通知所有在岗执行者
   
3. 修改 StrategyGame.Contracts/（唯一入口）
   
4. 各包同步更新自己的实现（编译验证）
   
5. 全量构建通过才算完成
```

### 为什么新增枚举值要编号 100以上

骨架阶段的六个 `ActionType`（0-5）是核心契约，**永久冻结**。后续扩展从 100 起编，这样即使中间插入了新值，已有的编号也不会错位。

## 跨语言约定：JSON 线格式

05A 用 TypeScript，不引用 C# 工程，因此需要一份独立的线格式规范。规范定义在 `StrategyGame.Contracts/Interfaces.cs` 的 `WireFormat` 与 `ApiContract`。

### 序列化规则（固定，不可协商）

| 规则 | 值 | 理由 |
|---|---|---|
| 字段命名 | camelCase | C# `Defense` → JSON `defense` |
| 枚举表示 | **字符串**，不是数字 | 数字枚举顺序调整会让 TS 静默读错值 |
| 未知字段 | 忽略，不报错 | 后端加字段不应导致旧前端崩溃 |
| 空值 | `null` 显式输出，不省略 | 避免 TS 端`undefined` |
| 缩进 | 不缩进（传输用） | 减小体积 |
| 编码 | UTF-8 | |

### API 端点

| 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|
| GET | `/api/state` | — | 世界状态 JSON |
| POST | `/api/order` | Order JSON | ResolveResult JSON |
| POST | `/api/turn/advance` | 空 | TurnResult JSON |
| POST | `/api/game/new` | `{ seed: number }` | 状态 JSON |
| POST | `/api/game/save` | 空 | 存档 JSON |
| POST | `/api/game/load` | 存档 JSON | 状态 JSON |

### 统一响应格式

```json
// 成功
{ "ok": true, "data": { ... } }

// 失败
{ "ok": false, "error": { "code": "NO_RESOURCES", "message": "银两不足", "detail": "需要 500，现有 300" } }
```

### 错误码对照表（05A 必须照此展示，不得自行翻译）

| Code | 含义 | 05A 应做的事|
|---|---|---|
| `INVALID_ACTOR` | 执行者不存在或已阵亡 | 提示并刷新状态 |
| `NO_RESOURCES` | 资源不足 | 显示 detail 中的差额 |
| `INVALID_TARGET` | 目标不存在 | 提示并刷新状态 |
| `TARGET_OCCUPIED` | 目标被占据 | 提示并刷新状态 |
| `NO_POST` | 需先任命人才 | 高亮岗位入口 |
| `NOT_ADJACENT` | 目标不可达 | 高亮可达城池 |
| `COOLDOWN` | 冷却中 | 显示剩余回合 |
| `NOT_IMPLEMENTED` | 功能未开放 | 提示"后续版本开放" |
| `INSUFFICIENT_CAPACITY` | 本月指令已用尽 | 提示"下月再行动" |
| `INTERNAL_ERROR` | 服务端 Bug | 显示通用错误 + 上报 |
| `NETWORK_UNAVAILABLE` | 网络/服务不可用 | **实现重试 + 降级提示** |

### 边界情况约定（三端必须一致）

| 情况 | 约定 |
|---|---|
| 空状态 | 任何 List 可能为空数组，**不会是 null** |
| 未知 Id | Get方法返回 `null`，不抛异常 |
| 时间表示 | `year` 从 1 开始，`month` 从 1 开始 |
| 玩家 Id | 固定为 `0` |
| 无移动目标 | `targetCityId = -1`（不是 0，0 是有效 Id） |
| 数值溢出 | 规则层必须 clamp 到 [min, max]，不溢出为负 |

## 组合验收流程

各包开发完成后，按此顺序组合：

```
1. 全量构建：dotnet build
   ↓ 必须零错误零警告

2. 契约一致性检查：
   - 各包引用的契约版本号是否一致
   - 有无重新声明契约类型（搜索重复类名）
   ↓

3. 契约测试：运行 06 包提供的契约测试套件
   ↓ 全部通过

4. 集成冒烟测试：新开一局 → 玩家下令 → 推进 12 个月 → 无异常
   
5. 确定性验证：同 Seed 跑两次 → 最终状态逐字段相等
   ↓ 这是最终的信任基础
```

任何一步失败，退回对应包。**不要在组合阶段临时改别人的代码**——会导致其他包的下次构建失败。

---

## 给执行者的三条硬性提醒

1. **不确定某个字段叫什么，去看 `StrategyGame.Contracts/`，不要猜。** 猜错一个字母就是编译错误。
2. **不要重新定义契约里已有的类型。** 如果觉得契约设计有问题，提变更申请，不要自己改。
3. **实现接口时，签名必须和契约完全一致。** 包括参数顺序、默认值、可空性。
