# 项目执行索引

## 怎么用这套文档

**每个执行者（人或 AI）只读自己那一个文件夹。** 不需要读全项目，也不要试图读全项目。

每个包目录包含：

| 文件 | 作用 |
|---|---|
| `README_任务书.md` | 是什么、交付什么、怎么验收、禁止做什么 |
| `接口契约_核心契约副本.md` | 核心契约完整副本（数据结构、枚举、API 签名） |

执行顺序：**先读 `README_任务书.md`，再读 `接口契约_核心契约副本.md`，然后开工。**

## 关键路径

```
01 设计规格  ──┬─→ 02 内容数据 ─┐
（硬阻塞）│
               └─→ 03 规则内核 ─┬─→ 04 智能体 ─┐
                                  ├─→ 05A 战略UI ─┐
                                  └─→ 06 工程验证 ─┤
                                                    ↓
                                            第一个可玩原型
                                                    ↓
                                            玩法验证
                                                    ↓
                                            05B 实时战斗
```

**`01` 是硬阻塞——但只阻塞"数值"，不阻塞"结构"。** 具体来说：

| 现在就能开工 | 必须等 01 定稿 |
|---|---|
| 03 的类型引用、接口实现骨架、StateApplier、GameClock、Tick 调度结构 | 03 里所有数值公式与系数 |
| 02 的 JSON 表结构（Schema） | 02 里具体填什么数值 |
| 04 / 05A / 06 的接口实现 | — |

做法：先用占位数值让流程跑通并通过测试，设计定稿后只替换数值，不动结构。**结构先定，数值后填。**

## 三条不可违背的规则

1. **确定性**：相同状态 + 相同指令 = 完全相同的结果。随机必须播种。
2. **单向依赖**：表现层依赖规则层，规则层绝不依赖表现层。规则层不得引用任何引擎 API。
3. **AI 与玩家同路**：AI 只能产出 `Order`，不能直接修改状态。

这三条在多个包的任务书里重复出现，因为它们是整个架构的承重墙。

## 契约变更

**真实契约在项目根目录的 `StrategyGame.Contracts/`，是编译通过的 `.cs` 工程**，不是文档。

C# 包通过 `ProjectReference` 引用它，不手抄（手抄会导致类型不匹配、编译失败）。
TypeScript 的 05A 按 `Interfaces.cs` 里的 `WireFormat` / `ApiContract` 对齐 JSON。

校验与分发：

```bash
cd E:/xinyouzi/StrategyGame.Contracts && dotnet build   # 必须零错误零警告
bash E:/xinyouzi/分发契约.sh                              # 同步副本到各包
```

变更流程：

1. 写变更提案到 `00_项目管理/变更申请/`
2. 通知所有在岗执行者
3. 修改 `StrategyGame.Contracts/`（唯一入口）
4. 各包同步更新实现，全量 `dotnet build` 通过
5. 运行 `分发契约.sh` 同步副本

**注意**：因为每个执行者只读自己那个文件夹，他们看不到变更通知。契约变更后必须重新分发，否则会出现接口不一致导致的编译失败。

## 多执行者如何保证组合成功

见 `跨包协作规范.md`。三条核心规则：

1. **类型只能来自契约工程**（ProjectReference），禁止手抄
2. **文件归属唯一**，每个文件只有一个 owner 包可写，其他包只读
3. **接口只能新增**，修改走变更申请流程

## 建议的启动顺序

1. 先让一个人（或一个 AI 会话）做 `01_设计规格层`——尤其是 `5_指令字典.md`
2. **同时**可以开 `03` 写结构骨架（占位数值），不必等 01 完成
3. 指令字典定稿后，`02` 填数值，`03` 填公式
4. `03` 完成即可开 `04` / `05A` / `06` 三条线
5. 四条线汇合出原型，玩一次，做玩法验证
6. 验证通过再启动 `05B`
