## 契约版本史

| 版本 | 引入的机制 | 解决的问题 |
|---|---|---|
| v1.0 | Markdown 代码块写类型定义 | —（此形式已废弃） |
| v1.1 | **真实 .cs 契约工程 + ProjectReference** | 手抄导致类型不一致、编译失败 |
| v1.2 | **万分比定点刻度铁律 + BaseKill 字段 + 整数事件 ID** | 攻陷分支不可达、小数装不进 int、字符串 ID 跨语言歧义 |

## v1.0 → v1.1：为什么改用真实工程

v1.0 把类型定义写在 Markdown 代码块里。**这个做法有致命缺陷**：
每个包都要手抄一遍，抄出来必然不一致，导致编译失败。

| | v1.0（旧） | v1.1 起（现行） |
|---|---|---|
| 契约形式 | Markdown 代码块 | 真实 .cs 源码工程 |
| 获取方式 | 手抄 | ProjectReference |
| 一致性保证 | 无，靠人自觉 | **编译器强制** |
| 编译期发现不一致 | 不能 | **能** |
| 新增枚举编号 | 未规定 | 扩展从 100 起，0-5 永久冻结 |

## v1.2 变更明细

### 1. 万分比定点刻度铁律（影响 02 / 03 全部包）

**所有比率类字段一律用万分比整数（100% = 10000），禁止小数、禁止百分数。**

背景：03 包发现 `守方损失 = 守军 × lossRate × 0.6` 数学上不可达
（需 lossRate ≥ 1.667，但击退阈值只有 0.70）。根源是设计层用小数，
而契约字段是 int，0.6 根本装不下——执行者被迫自行发挥，埋雷。

现在刻度统一，且战斗、经济两条系统共用同一套刻度。

| 字段 | v1.1 | v1.2 |
|---|---|---|
| `GrainPerPopPerMonth` | int，装不下 0.08 | **800**（= 0.08） |
| `SoldierPerPopPerMonth` | int，装不下 0.5 | **5000**（= 0.5） |
| `GameEventTemplate.Probability` | 0-100 | **万分比** |
| `BaseLoss` | 百分数 35 | **万分比 3500** |
| `DefenderLossFactor` / `StalemateLossRate` | 在用 | **已废弃**，读但不算 |

**唯一例外**：`ArmyMonthlyGrainPerSoldier` 用 /1000 口径，属历史遗留，已列入待裁决。
执行者**不得自行统一口径**。

**消费方公式写法**：`a * (X / 10000)`，整除截断统一向下取断，
截断方向必须有测试锁定（不同语言的浮点取整结果可能不同）。

### 2. 新增 `BaseKill`（战斗公式重构）

攻方损耗与守方伤亡改为两条**独立**公式，
详见 `01_设计规格层/3_战斗系统设计.md` 第 3.1 / 3.2 节：

```
lossRate = BaseLoss/10000 × (0.5 + 城防/1000) × (2 - 2 × commanderRatio)
killRate = BaseKill/10000 × (2 - 城防/1000) × (2 × commanderRatio)
```

### 3. `GameEventTemplate.Id`：string → int

全项目实体 ID 统一为正整数。理由：跨语言 JSON 序列化时
`string` / `number` 混合类型易产生隐式转换歧义。

## 权威契约在哪里

```
  StrategyGame.Contracts.csproj
  Enums.cs  全部枚举定义
  Models.cs               全部数据结构定义

```

## 怎么引用（C# 包）

```xml
<ProjectReference Include="..\..\StrategyGame.Contracts\StrategyGame.Contracts.csproj" />
```

**禁止重新声明契约里已有的类型。** 重声明会导致类型不匹配，编译失败。

## 怎么对齐（TypeScript 的 05A 包）

05A 不直接引用 C#，而是按 `Interfaces.cs` 中的 `WireFormat` 与 `ApiContract` 对齐 JSON：

- 字段 camelCase（`Defense` → `defense`）
- 枚举序列化为**字符串**而非数字
- 端点路径与响应格式见 `ApiContract.Endpoints`
- 错误码见 `ApiContract.ErrorCodes`

## 冻结约定

`ActionType` 的 0-5（Recruit / Fortify / Develop / Dispatch / AssignPost / Rest）是**永久冻结**的核心契约，任何人不得修改数值或含义。后续扩展从 100 开始编号，避免中间插入导致已有编号错位。

## 三条不可违背的规则（复述）

1. **确定性** — 相同状态 + 相同指令 = 完全相同结果，随机必须播种
2. **单向依赖** — 规则层不依赖表现层，不引用引擎 API
3. **AI 与玩家同路** — AI 只产出 `Order`，不直接改状态
