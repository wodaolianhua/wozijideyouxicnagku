# 指令字典（Order Dictionary）

> **这是设计层与代码层的直接交界面。** 03 包的每个 `IResolver` 实现都对应本文档的一条指令。
>
> **必须穷尽。** 如果某个玩法无法表达为一条 `Order`，说明架构有缺口，需要重新设计。

---

## 通用约定

### 三种执行者，同一种结构

```
ActorType.Player      ActorId = 0        玩家亲自操作
ActorType.Officer     ActorId = OfficerId  人才代管
ActorType.AiFaction   ActorId = FactionId  AI 势力决策
```

**三种执行者产生完全相同的 `Order` 结构。** 这是设计决策 D1 的直接体现——AI 与玩家同路。

### 参数语义（所有指令通用）

| 参数 | 含义 |
|---|---|
| `TargetId` | 主目标 |
| `SecondaryTargetId` | 次目标，默认 -1 |
| `Amount` | 数量，具体含义见各指令 |
| `ExecuteYear/ExecuteMonth` | 执行时间，即时指令填当前月 |

### 返回码

所有指令失败时返回 `ResolveResultCode` 中对应的拒绝码，并附中文 `Message`。

**禁止静默失败**——玩家点了没反应是最糟的体验。

### 每月人力上限

单个势力每月最多执行 `MaxOrdersPerFactionPerMonth` 条指令（基准 5 条）。
超额返回 `RejectedInsufficientCapacity`。

**设计意图**：让玩家每月必须做取舍，不能把所有事都做了。

## P0 六条指令

---

### 1. `ActionType.Recruit`（征兵）

| 项 | 说明 |
|---|---|
| **语义** | 在目标城池补充兵源 |
| **TargetId** | 城池 Id |
| **SecondaryTargetId** | -1 |
| **Amount** | 征兵数量 |
| **执行者** | Player / Officer / AiFaction 均可 |

**前置校验**（按顺序检查，命中即返回）：

| 顺序 | 条件 | 失败码 |
|---|---|---|
| 1 | 城池存在 | `RejectedInvalidTarget` |
| 2 | 城池归属执行者势力 | `RejectedInvalidTarget` |
| 3 | 有足够银 | `RejectedNoResources` |
| 4 | 有足够粮 | `RejectedNoResources` |
| 5 | 当月人力未满 | `RejectedInsufficientCapacity` |

**资源消耗**：
```
银消耗 = Amount × RecruitCostSilverPerSoldier   (基准 3)
粮消耗 = Amount × RecruitCostGrainPerSoldier    (基准 2)
```

**产出**：
- `StateDelta`: Faction.Resources.Soldier +Amount
- `StateDelta`: Faction.Resources.Silver −银消耗
- `StateDelta`: Faction.Resources.Grain −粮消耗
- `EventRecord`: Category=Military，"XX 城募得新兵 N 人"

**注意**：征兵增加的是**可用兵源**，不是立即出现的部队。玩家还需要 `Dispatch` 把兵源变成实际部队。

### 2. `ActionType.Develop`（屯田）

| 项 | 说明 |
|---|---|
| **语义** | 投入资源提升城池农业等级 |
| **TargetId** | 城池 Id |
| **Amount** | 投入银两 |
| **执行者** | 全部 |

**前置校验**：

| 顺序 | 条件 | 失败码 |
|---|---|---|
| 1 | 城池存在且归属本势力 | `RejectedInvalidTarget` |
| 2 | FarmLevel < 上限 | `RejectedInvalidTarget` |
| 3 | 银两充足 | `RejectedNoResources` |
| 4 | 人力未满 | `RejectedInsufficientCapacity` |

**资源消耗**：银 = Amount

**产出**：
```
FarmLevel += Amount / DevelopCostSilverPerLevel    (基准 150银/级，向下取整)
```
- `StateDelta`: City.FarmLevel
- `StateDelta`: Faction.Resources.Silver −Amount
- `EventRecord`: Category=Economy

**影响**：粮产 = 人口 × GrainPerPopPerMonth × (1 + FarmLevel × 0.15)

### 3. `ActionType.Fortify`（修城防）

| 项 | 说明 |
|---|---|
| **语义** | 投入资源提升城防等级 |
| **TargetId** | 城池 Id |
| **Amount** | 投入银两 |
| **执行者** | 全部 |

**前置校验**：同 Develop，但检查 `FortifyLevel < 上限`。

**产出**：
```
FortifyLevel += Amount / FortifyCostSilverPerLevel   (基准 200银/级)
Defense = FortifyLevel × 城防基础值                 (上调同步)
```

**影响**：城防直接进入攻城战公式的 `defenseFactor`。

**设计意图**：修城防让"龟缩"变得可行，与战斗系统里的野战优势形成取舍。

### 4. `ActionType.Dispatch`（出兵）

**这是最重要的一条指令。** 宏观调兵与亲自上阵都走它。

| 项 | 说明 |
|---|---|
| **语义** | 将兵力从出发城调往目标城，并可能发动进攻 |
| **TargetId** | 目标城池 Id |
| **SecondaryTargetId** | 出发城池 Id |
| **Amount** | 投入兵力 |
| **执行者** | 全部（`Officer` 表示由人才统率，`Player` 表示玩家亲征） |

**前置校验**（顺序敏感）：

| 顺序 | 条件 | 失败码 |
|---|---|---|
| 1 | 出发城与目标城都存在 | `RejectedInvalidTarget` |
| 2 | 出发城归属本势力 | `RejectedInvalidTarget` |
| 3 | 两城相邻 | `RejectedNotAdjacent` |
| 4 | 兵源充足（`Amount` 不超过 Soldier） | `RejectedNoResources` |
| 5 | 目标城未被围困 | `RejectedTargetOccupied` |
| 6 | 人力未满 | `RejectedInsufficientCapacity` |

**关键分支**：如果 `ActorType == Player` 且玩家当前未亲征，此指令为**亲征**：
- 设置 `Player.IsPersonallyCommanding = true`
- 设置 `Player.CommandingArmyId`
- 该部队 `OfficerId = -1`（统帅位被玩家占据，不叠加任何人才加成）

**战斗结算**：完全按 `3_战斗系统设计.md` 的双公式执行，此处只列速查。

```
攻方统帅 = GetEffectiveCommand(armyId)      // 玩家亲征则取 Player.Command
守方统帅 = 守城部队的统帅值，未设则 0

defenseFactor  = 目标城 Defense / 1000.0
commanderRatio = 攻方统帅 / (攻方统帅 + 守方统帅)      // 双方皆 0 时取 0.5，不带 +1
lossRate = (BaseLoss / 10000) × (0.5 + defenseFactor) × (2 - 2 × commanderRatio)
killRate = (BaseKill  / 10000) × (2 - defenseFactor) × (2 × commanderRatio)

攻方损失 =投入兵力 × lossRate
守方损失 = min(投入兵力 × killRate, 守城兵力)
```

**判定顺序（不可调换）**：

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | `lossRate ≥ 0.70` | **击退**：攻方退回出发城 |
| 2 | `守方损失 ≥ 守城兵力` | **攻陷**：城易主 |
| 3 | 其他 | **未决**：目标城标记 `Siege`，下月不可再 Dispatch，返回 `RejectedTargetSieged` |

> ⚠️ **原写法有两处错，已修正**：
> ① `commanderRatio` 曾写作 `攻/(攻+守+1)`，那个 `+1` 会把比值强行拉向 0.5，
> 恰好抹掉强将/弱将的差异。**除零用"皆 0 时取 0.5"解决，不用 `+1`。**
> ② 曾写作「守城兵力归零 且 lossRate < 0.70 → 攻陷」在`lossRate ≥ 0.70 → 击退」**之前**，
> 两者同时满足时结果取决于判定顺序。改为先判击退。

**产出**：
- 攻方兵力变更 `StateDelta`
- 守方兵力变更 `StateDelta`
- 攻陷时：城池归属变更 `StateDelta`
- `EventRecord` 记录战果
- 未决时：目标城 `Siege` 标记（供 `RejectedTargetSieged` 判定）

**耗粮**：驻军每月耗粮，公式见 `4_数值框架.md`「粮耗压力」一节，
在 Tick 粮耗步骤结算。注意 `ArmyMonthlyGrainPerSoldier` 的单位口径仍在待裁决，
**在裁决前一律沿用 4_数值框架.md 写的口径，不要自行改动**。

### 5. `ActionType.AssignPost`（任命人才）

**这是"用人"玩法的入口。**

| 项 | 说明 |
|---|---|
| **语义** | 将人才放到某个岗位 |
| **TargetId** | 人才 Id |
| **SecondaryTargetId** | 岗位所在城池 Id |
| **Amount** | -1（未用） |
| **执行者** | 全部 |

**前置校验**：

| 顺序 | 条件 | 失败码 |
|---|---|---|
| 1 | 人才存在且存活 | `RejectedInvalidActor` |
| 2 | 人才归属本势力 | `RejectedInvalidActor` |
| 3 | 城市存在且归属本势力 | `RejectedInvalidTarget` |
| 4 | 人才当前未任职 | `RejectedTargetOccupied` |
| 5 | 人力未满 | `RejectedInsufficientCapacity` |

**产出**：
```
Officer.Post         = 对应 PostType
Officer.PostCityId   = SecondaryTargetId
Officer.PostedSinceMonths = 0
```

**关键机制**：换任需要 `PostTakeEffectMonths` 个月（基准 1）才生效。
生效前不提供任何加成——**这让频繁换将有代价**。

**岗位与加成**：

| 岗位 | 加成来源 | 效果 |
|---|---|---|
| CityGovernor城守 | Governance | 城市综合加成 |
| FortifyOverseer 军师佐政 | Governance | 城防提升效率 |
| FarmOverseer 屯田使 | Governance + Agriculture | 粮产加成 |
| General 将军 | Command | 统帅值（影响战斗） |
| Scoutmaster 斥候 | Command | 侦察范围（P2） |

**专长匹配**：专长与岗位匹配时提供额外加成（`SpecialtyBonus` 配置）。
例：Agriculture 专长 + FarmOverseer 岗 → 粮产 +30%。

**验收标准**：换人之后结算结果必须可观测地变化。这是"用人"能否成为乐趣的核心检验。

### 6. `ActionType.Rest`（休整）

| 项 | 说明 |
|---|---|
| **语义** | 恢复部队士气 |
| **TargetId** | 部队 Id |
| **Amount** | -1 |

**前置校验**：

| 顺序 | 条件 | 失败码 |
|---|---|---|
| 1 | 部队存在且归属本势力 | `RejectedInvalidTarget` |
| 2 | 本月未休整过 | `RejectedCooldown` |

**产出**：
```
Morale += MoraleMax × 0.3
HasRestedThisMonth = true
```

**注意**：这个 `Cooldown` 是设计成"每月只能休整一次"，防止反复休整刷士气。

## 验收标准

- [ ] 每条指令的前置校验按指定顺序检查（顺序敏感：先查存在，再查归属）
- [ ] 每条指令都有明确的 `StateDelta` 产出清单
- [ ] 每条指令失败时返回正确的结果码与中文 Message
- [ ] `Dispatch` 的亲征分支正确实现：设置 `IsPersonallyCommanding`，部队 `OfficerId = -1`
- [ ] `Dispatch` 的三种战斗结果（攻陷/击退/未决）全部实现且可达
- [ ] `AssignPost` 实现 `PostTakeEffectMonths` 延迟生效
- [ ] 所有资源消耗来自 `BalanceConfig`，无硬编码
- [ ] **无"待定"占位符**
