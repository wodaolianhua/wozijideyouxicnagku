# 战斗系统设计（原型阶段：回合制批量结算）

> **本阶段不做实时战斗。** 本文设计回合制批量结算——一次 `Dispatch` 指令，几个月内算完，产出结果。
> 实时战斗（05B）会在玩法验证通过后单独设计，届时以本文的公式为基础做扩展。
>
> **所有公式必须给出可代入的具体数字。** 不允许出现"待定"。数值依据写在一旁的表格里。

---

## 一、设计目标

原型阶段的战斗只需要回答一个问题：**这次攻城该不该打、能不能打赢、代价多大。**

不做的事：逐秒战斗、动作判定、技能释放、兵种克制链。

### 为什么回合制是对的

| |回合制（现在） | 实时战斗（05B） |
|---|---|---|
| 能否被 Tick 推进 | 能 | **不能** |
| 无头模拟能否跑 | 能 | 不能 |
| 存档复杂度 | 低 | 高（要存战局中间态） |
| 状态回滚 | 容易 | 困难 |
| 玩家决策频率 | 每月一次 | 秒级 |

回合制是原型的正确选择，不是妥协。

## 二、基础模型

### 攻守对比

一场攻城战的结果只取决于四个输入：

```
守方防御力 D_def = 城防值 + 城防等级加成 + 守将加成
攻方攻击力 D_atk = 兵力 × 统帅加成 × 地形加成 × 特长加成
```

### 三种结果

| 结果 | 触发条件 | 后果 |
|---|---|---|
| **攻陷** | 战损率< 阈值且守城兵力归零 | 城易主，攻方获得城池 |
| **击退** | 战损率 ≥ 阈值 | 攻方损失部分兵力，被退回原城 |
| **鏖战未决** | 双方都没达到条件 | 双方各损少量，下月可再战 |

**必须有"未决"结果**：如果只有胜/负两种，AI 会陷入反复攻击同一座城直到打下来或全军覆没。加入未决让"打不下来就走"成为理性选择。

## 三、公式

### 3.1 攻城战总战损率

```
baseLoss       = 0.35                    # 基础战损，攻守双方都要承担
defenseFactor  = 城防值 / 1000.0         # 城防越高，攻方损耗越大
commanderRatio = 攻方统帅 / (攻方统帅 + 守方统帅)   # 统帅对比
lossRate       = baseLoss × (0.5 + defenseFactor) × (2 - 2 × commanderRatio)
```

**取值校验**（重要，防止公式失控）：

| 情况 | defenseFactor | commanderRatio | lossRate |
|---|---|---|---|
| 均势攻城（统帅 50 vs 50，城防 500） | 0.5 | 0.5 | 0.35 |
| 强将攻城（统帅 75 vs 50，城防 500） | 0.5 | 0.6 | 0.28 |
| 弱将攻城（统帅 40 vs 50，城防 500） | 0.5 | 0.44 | 0.43 |
| 死攻坚城（统帅 50 vs 50，城防 1500） | 1.5 | 0.5 | 0.78 |

**设计意图**：
- 均势攻城战损 35%，意味着**攻方兵力至少要有守方的 3倍才稳妥**
- 强将能把战损从 0.35 压到 0.28，这就是"用人的价值"的量化体现
- 攻坚城战损 78%，几乎必败——所以要先屯田发展，不能急着打

### 3.2 双方兵力损失

```
攻方损失 = 攻方投入兵力 × lossRate
守方损失 = 守城兵力 × lossRate × 0.6      # 守方躲在城内，损失较低
```

守方损失系数 0.6 的理由：守方有城墙保护。如果守方损失和攻方一样，守城就变得毫无意义，"龟缩不战"会成为最优解——那就不是战争游戏了。

### 3.3 统帅加成

```
统帅值 = 基础值 × (1 + 专长加成 + 岗位加成)
```

| 来源 | 效果 |
|---|---|
| Officer.Command | 基础统帅值（0-100） |
| PlayerProfile.Command | 玩家亲征时的统帅值 |
| Siege 专长 | 攻城战 lossRate ×0.85 |
| Cavalry 专长 | 野战 lossRate ×0.85 |
| Logistics 专长 | 该部队每月士气衰减 -50% |
| Agriculture 专长 | 不影响战斗，但所在城粮产 +30% |

**关键**：玩家亲征时**不叠加任何 Officer 加成**（见设计决策 D9）。玩家赢在个人能力，人才赢在组合。

### 3.4 攻陷判定

```
守城兵力 - 守方损失 <= 0  且  lossRate < 0.7
    → 攻陷，城易主

lossRate >= 0.7
    → 击退，攻方退回原城，损失已计算

以上都不是
    → 未决，双方各损 10% 兵力，下月可再战
```

### 3.5 野战（两军对撞）

不涉及城池时使用：

```
lossRate_野战 = baseLoss × 0.6 × (2 - 2 × commanderRatio)
```

野战战损比攻城低（0.21 vs 0.35），因为没有城墙消耗。**这让"避开坚城、诱敌野战"成为可行策略**——地形与战术有实际价值。

## 四、经济与战斗的关系

这是本设计的关键部分：**战斗不是孤立的，它和经营系统互相咬合。**

```
屯田 → 粮产 → 征兵 → 兵力 → 攻城 → 得城池 → 更多人口 → 更多粮产
                    ↑                                    │
                    └────────修城防 ←──────────────────┘
                          （让下一次攻城更难被打）
```

### 粮耗压力

部队每月消耗粮食：

```
月耗粮 = 兵力 × 0.02
```

**设计意图**：5000 人每月耗 100 粮。而一座 3000 人口的城屯田满级只产348 粮
（详见 `4_数值框架.md`），意味着养5000 人需要一座城的全部产出还多。

如果屯田跟不上，玩家会陷入"越打越穷"。这是有意的——**它逼玩家不能无脑扩张，必须算清楚账**。

**校验**：三城满屯、养 3 万兵，月耗 600 粮，产出约 1000 粮。看起来还有余，
但一旦战败损失城池，产出会立刻腰斩，压力骤增。

### 兵源与灾荒

```
本月兵源产出 = 人口 × SoldierPerPopPerMonth × (Stability / 100)
Soldier归零后连续 3 个月 → 饥荒事件
```

如果 `Stability` 掉太低（民心动摇），兵源产出下降 → 更容易陷入饥荒。**这是"打太多仗会亡国"的机制保证**，让扩张有天然刹车。

## 五、胜负判定

| 条件 | 结局 |
|---|---|
| 玩家仅剩 1 座城 | 失败 |
| 玩家全部城池易主 | 立即失败 |
| 玩家拥有大陆 80% 以上城池 | 立即胜利 |
| 存活满 72 个月（6 年） | 按城池数排名结算 |

**关于目标时长**：用户期望约 5 年（60-72 回合）。因此：
- 60 个月：及格线——多数玩家应该在此前后分出胜负
- 72 个月：硬上限——超时强制按城池数结算，避免拖成消耗战

## 六、与实时战斗（05B）的衔接

原型阶段的战斗是"一次结算"，实时战斗是"一段过程"。衔接方案：

```
Dispatch 指令
    ↓
Resolver 判断：这是普通攻城还是需要实时战斗？
    ↓
├── 普通攻城 → 用本文的公式批量结算（当前实现）
│
└── 实时战斗 → 打开战斗场景（05B）
                 ↓
             战斗结束，产出 StateDelta
                 ↓
             StateApplier 统一写回（与回合制走同一条路径）
```

**关键约束**：实时战斗的结果也必须以 `StateDelta` 形式产出，走和回合制**完全相同**的写回路径。不能让实时战斗成为旁路。

**公式复用**：实时战斗的伤害模型应该与本文的战损率公式保持一致（同一套系数，不同的表现形式）。如果实时战斗自己写一套伤害计算，就会出现"回合制说打赢、实时打输了"的荒谬情况。

## 七、验收标准

- [ ] 三个结果（攻陷/击退/未决）全部可达，有单元测试覆盖
- [ ] 均势攻城战损率在 0.35 ± 0.05
- [ ] 强将攻城能显著降低战损（0.28 或更低）
- [ ] 攻坚城（城防 1500）战损率超过 0.7，会被击退
- [ ] 玩家亲征时确认不叠加 Officer 加成
- [ ] 粮耗会导致"越打越穷"，有测试验证
- [ ] 兵源枯竭会触发饥荒事件
- [ ] 全部系数来自 `BalanceConfig`，代码中无硬编码魔法数字
- [ ] 无文档中出现"待定"

## 八、待02 包填写的数值

以下数值本文给出公式，但具体取值依赖 `4_数值框架.md`：

| 系数 | 当前暂定值 | 最终依据 |
|---|---|---|
| `baseLoss` | 0.35 | 使均势攻城需 3 倍兵力才稳妥 |
| 守方损失系数 | 0.6 | 让"龟缩"不是最优解 |
| 攻陷阈值 lossRate | 0.7 | 超过则认为无法攻破 |

| Siege / Cavalry 减伤 | ×0.85 | 专长要有实际价值但不夸张 |
| Agriculture 粮产加成 | +30% | 一个专长改变一座城的产出量级 |

这些数值**必须全部写入 `assets/data/config.json`**，代码中不得出现。
