# 数值框架

> **本文件的每个数值都必须有依据说明。** "拍脑袋填的"会在后期平衡时变成灾难——
> 因为没人记得这个数为什么是这个数，只能从头试。
>
> 基准线来自 `1_世界观设定.md`：没落贵族起点，2 座城，约 5 年，自适应难度。

---

## 一、平衡目标（先定目标，再定数值）

没有目标就无法判断"数值好不好"。先定目标：

| 指标 | 目标 | 为什么 |
|---|---|---|
| 一局时长 | 60-72 回合（5-6 年） | 用户期望值 |
| 玩家胜率（普通难度） | 25%-45% | 低于 50% 因为玩家需要动脑，高于说明 AI 太弱 |
| 平均存活回合 | ≥ 60 | 太低说明玩家容易早期被灭 |
| 首回合终局比例 | ≈ 0 | 有明显开局崩盘或滚雪球 |
| 玩家资源量级 | 始终低于 AI 10%-20% | 没落贵族设定 |

**"玩家资源低于 AI"是硬性要求。** 如果玩家后期资源反超，说明经营系统出了问题。

## 三、经济数值

### 定点整数刻度（全局强制）

**所有系数一律用万分比整数，禁止小数。** 理由：战斗系统已经全程定点，
经济系统如果用浮点会出现"两次结算差1 粒粮"的漂移，破坏确定性铁律。

| 含义 | 小数写法（仅用于文档推导） | 契约写法 |
|---|---|---|
| 100% | 1.0 | 10000 |
| 50% | 0.5 | 5000 |
| 30% | 0.3 | 3000 |
| 8% | 0.08 | 800 |
| 15% | 0.15 | 1500 |

**唯一的例外是 `ArmyMonthlyGrainPerSoldier`**，它用 /1000 口径（详见其 XML 注释），
这是历史遗留，已列入待裁决。执行者**不得自行统一或改口径**。

**除法必须做整除截断，且必须在测试里锁定截断方向**（统一向下取整）。
浮点取整在不同语言里结果可能不同，这是跨语言协作的隐患。

### 粮产

```
每城月粮产 = 人口 × (GrainPerPopPerMonth / 10000) × 屯田等级加成 × (人才加成 / 10000)
GrainPerPopPerMonth = 800    （= 0.08）
屯田等级加成 = 10000 + FarmLevel × 1500   （每级 +15%）
人才加成 = Agriculture 专长 13000，否则 10000
```

**推导过程**（保留推导，避免后人重复踩坑）：

| 阶段 | GrainPerPopPerMonth | 8000 人口城月产 | 问题 |
|---|---|---|---|
| 初稿 | 2（=20000） | 160000 粮 | 远超耗粮，压迫感消失 |
| 修正一 | 0.15（=1500） | 12000 粮 | 仍然偏高 |
| 修正二 | 0.08（=800） | 6400 粮 | **根因不是系数，是人口基数太大** |
| 定稿 | 800+ 人口降到千级 | — | 见下 |

**最终校验**（人口基数：玩家城 3000，中原城 4500，边疆城 2500）：
- 3000 人口城 = 3000 × 0.08 = **240 粮/月**
- 三级屯田 = 240 × 1.45 = **348 粮/月**
- 三级屯田 + Agriculture 专长 = 240 × 1.45 × 1.3 = **452 粮/月**

**这才是合理的压迫感**：前期只能养几千兵，打一次大仗就要饿肚子。

### 兵源

```
月兵源 = 人口 × (SoldierPerPopPerMonth / 10000) × (Stability / 100)
SoldierPerPopPerMonth = 5000    （= 0.5）
```

**推导**：

| 阶段 | 值 | 3000 人口、Stability 60 | 问题 |
|---|---|---|---|
| 初稿 | 0.10（=1000） | 18 兵/月，一年 216 兵 | 前期完全打不了仗 |
| 定稿 | 5000 | 90 兵/月，一年 1080 兵 | 符合"没落贵族有个家底" |

**关键校验**：`Stability` 从 55 掉到 30（战败、失城），
月兵源从 82 掉到 45，**近乎腰斩**。这是"打太多仗会亡国"的机制保证，
也是自适应难度下调数值的抓手之一。

### 银

| 用途 | 成本 |
|---|---|
| 征兵（每兵） | 3 银 + 2 粮 |
| 修城防（每级） | 200 银 |
| 屯田（每级） | 150 银 |
| 赏赐人才 | 100 银（增加忠诚） |

**校验**：初始 800 银，可以修 4 级城防或屯 5 级田。**每一个选择都很贵**，这正是没落贵族该有的感觉。

## 五、民生数值

### 5.1 稳定度 Stability（城池属性，0-100）

| 项 | 值 | 依据 |
|---|---|---|
| 稳定度初始 | 60 | 处境不稳但不崩溃 |
| 月自然恢复 | +5 | 没出事就慢慢回稳 |
| 跌城 | −15 | 失一城，民心大动 |
| 战后（胜） | +3 | 打赢了涨脸 |
| 战后（败） | −8 | 打败仗，士气和民心都跌 |
| **Stability < 30** | 兵源产出减半 | 民心动摇 |
| **Stability < 15** | 触发饥荒 / 动乱事件 | 崩溃线 |

**归属**：`Stability` 是**城池属性**，不是势力属性。
一座城失守只影响那座城，不是全势力崩盘。这样才有"弃一城保三城"的空间。

### 5.2 士气 Morale（部队属性，0-100）

**士气是部队的属性**，挂 `Army.Morale`，不挂城池。
一场仗打下来，部队的士气会变；士气低会直接影响战力。

#### 5.2.1 月度恢复规则（三条互斥，按顺序判定）

```
本月参战                        → 不恢复，只结算战斗增减（见 5.4）
本月未参战 且未达腐化阈值        → morale += 3     正常休整
本月未参战 且已达腐化阈值        → morale -= 6     和平腐化
```

| 事件 | Morale 变化 | 依据 |
|---|---|---|
| 初始 | 60 | 有战意但不亢奋 |
| 休整（未达腐化阈值） | +3 / 月 | 休整就回 |
| **恢复只在未参战月生效** | — | **见下，这是本系统最关键的约束** |
| **和平腐化**（连续未参战 ≥ 4 月） | **−6 / 月** | 和平久了军队会废，逼玩家不能无限期放置 |
| **攻城攻陷** | +10 | 大胜提振 |
| **攻城击退** | −12 | 被打退，士气重挫 |
| **攻城未决** | −3 | 拉锯，消耗耐心 |
| **野战击退** | −12 | 同上 |
| Logistics 专长部队 | 休整恢复 +6（翻倍） | 辎重充足，士气稳 |

**⚠️ 为什么"恢复只在未参战月生效"是硬约束**

若参战月也发恢复 +3，连续攻城（僵持每月 −3）就被 +3 完全抵消，
**无脑连续攻城士气恒定 60、战损永远最低**，"用人 / 练兵 / 休整"的玩法内核被架空。
这是 v1.2 初稿的真实缺陷，由 03 包执行者代入实算时发现。

定稿后的完整账（契约 v1.4，已被 03 包测试锁定）：

- **连续作战（每月都打、僵持）**：战斗每月 −3，月度结算 0 → 3 月 50→41（端到端测试锁定）
- **每 2 月一战 + 休月轮休**：战月 −3、休月 +3，端到端净 0，在 57↔60 循环，不会自己把自己打崩（但也养不肥）
- **纯和平 12 月**：60→15，腐化构成真实压力（测试锁定 15）

**关键实现约束（契约 v1.4）**：参战信号**不靠计数器推断**。
`MonthsWithoutBattle == 0` 既可能是「刚打完仗」也可能是「新部队开局默认 0」，无法区分。
因此契约 v1.4 新增 `Army.HasEngagedThisMonth`：战斗发生时（攻方与守方）置 true 并把计数器归零；
月度结算**先读标记**——true 走参战分支（不恢复不腐化）并消费即清，false 才把计数器 +1 判恢复/腐化。
新设部队默认 false，开局第一次结算正确走恢复分支。

#### 5.2.2 阈值与强度的实算依据

初稿是「恢复 +3 / 腐化 −2 / 阈值 6」，代入实算发现**腐化完全是死条款**：

| 方案 | 稳态净变化/月 | 连续 12 月无战后 | 结论 |
|---|---|---|---|
| +3 / −2 / 阈值 6（初稿，旧叠加口径） | **+1** | 60 → 72 | 腐化无效，纯和平越养越壮 |
| +2 / −4 / 阈值 6 | −4（互斥口径 60→42） | 60 → 42 | 约 15 月才跌破 30，太慢 |
| +3 / −5 / 阈值 4 | −5（互斥口径 60→24） | 60 → 24 | 可用，但砍了恢复影响战循环 |
| **+3 / −6 / 阈值 4（定稿，互斥）** | **−6** | **60 → 15** | **✓ 见下，03 包测试已锁定 15** |

> 注：初稿行保留旧「叠加」口径（+3 与 −2 同月净算）以记录历史缺陷；
> 定稿起恢复与腐化**互斥**，其余行的 12 月结果按互斥口径重算。

**定稿方案的实算验证**：

- **纯和平 12 月**：60 → 63 → 66 → 69 → 63 → 57 → 51 → 45 → 39 → 33 → 27 → 21 → **15**
  （前 3 月恢复，**第 4 个无战月当月起只 −6、不再 +3**）
  第 10 月跌破 30（战损 +150% 档），腐化构成真实压力
- **每 2 月一战（僵持）+ 休月轮休**：战月战斗 −3、月度结算 0；休月 +3，
  端到端净 0，在 57↔60 循环；计数每战清零、永不达阈值，不腐化也养不肥
- **连续作战（每月僵持）**：每月 −3，3 月 50→41，无脑连攻不再是最优解
- **一局 60-72 回合**：阈值 4 意味着"放着 4 个月不打"就要付代价，
  而60 回合的一局里玩家本来就不可能长期按兵不动

**阈值为什么从 6 降到 4**：阈值 6 意味着整整一年无战才见效，
而玩家很少连续 6 月不动兵。4 个月是"玩家能意识到但会犹豫"的时长。

#### 5.2.3 低士气惩罚

```
士气 ≥ 60：  战力正常，无惩罚（×1.0）
士气 30-59： 战损 +50%   （lossRate × 1.5）
士气 10-29： 战损 +150%  （lossRate × 2.5）
士气 < 10：   战损 +300%  （lossRate × 4.0）
士气 ≤ 0：    哗变 —— 部队解散 30% 兵力并离开势力
```

**这四档也是代入实算定出来的**：初稿 ×1.2 / ×1.5 / ×2.0 代入实测后发现，
士气从 60 掉到 10 **战局结果一次都没变**（仍是攻陷，只是多烧点兵），
士气系统形同装饰。现档 ×1.5 / ×2.5 / ×4.0 能让士气 20 时
均势攻城从攻陷翻成击退，这才让「该休整还是该趁胜追击」成为真实决策。

**关键平衡约束**：士气倍率会叠加到 `lossRate` 上，
所以计算顺序必须是 `lossRate = 公式值 × 士气倍率`，**再**拿去和
`SiegeThresholdLoss` 比。实现时**绝不要写 `min(lossRate, 1.0)`**——
那样会被钳制，低士气反而不受影响，整个系统白做。

**哗变的判定时机**：取「结算前/后」两者的较小值判定。
若只看结算后，士气归零后下月即被恢复拉回，永远不会 ≤ 0，哗变变成不可达分支
——这是 03 包在实现中踩到并修掉的真实缺陷。
设计语义是「士气崩溃的部队当月就散」，不给它一个月的恢复缓冲。

### 5.3 灾荒

```
部队月耗粮 = 兵力 × (ArmyMonthlyGrainPerSoldier / 10000)
全势力粮储归零 且 连续 3 个月 → 饥荒事件
```

**重要澄清**（这一条纠正了早期文档的算术错误）：
早期文档写"348 粮养 3.4 万人"，实际是 **1.74 万人**
（348 ÷ 0.02 = 17400）。早期文档的结论"扩张即穷"是错的。

**粮不是真正的瓶颈，兵源才是**：
3000 人口城每月只产 **90 兵源**（= 3000 × 0.5 × Stability/100），
要攒到 5000 兵需要约 4 年。所以：

| 约束 | 真实压力 |
|---|---|
| 兵源 | 90/月，攒 5000 兵要 4 年 —— **这是真正的瓶颈** |
| 粮草 | 348 粮能养 1.74 万兵 —— 相对宽松 |
| 失城 | 人口归零 → 粮产 + 兵源一起腰斩 —— **第二个真正的瓶颈** |

**设计意图**：压迫感不来自"饿肚子"，来自**"人不够"**和**"打下地也守不住"**。
这个转向很重要：如果只靠粮，AI 和玩家拼的是数值；
靠兵源，拼的是**时间管理和用人效率**——这才是这个游戏该有的核心竞争维度。

### 5.4 战斗时士气如何流转

```
战斗结算
  ├─ 攻陷：攻方部队 Morale += 10
  ├─ 击退：攻方部队 Morale −= 12
  ├─ 未决：攻方部队 Morale −= 3
  └─ 守方无论结果：Morale −= 4   # 守城部队即便守住也受伤
```

守方统一 −4 是为了避免"龟缩无损"——
如果守方击退时不掉士气，玩家就会发现"死守"是零成本策略。

**部队合并规则**：两支部队合并时，Morale 取**加权平均**（按兵力），
不是取平均也不是取最大值。合并成一支大军的士气应该被稀释。

## 七、难度档位配置

```
Easy:   AI 资源 ×1.3，AI 决策保守（只屯田征兵，不主动进攻）
Normal: 基准值，AI 会评估威胁会防守
Hard:   AI 资源 ×0.85，AI 主动扩张并针对玩家弱点
```

**铁律**：难度只影响**开局加载的 BalanceConfig**，运行中不得改变。

严禁让 AI "看玩家弱就放水"——那会破坏确定性，导致无头模拟跑两次结果不同、存档回放失效。

难度等级存进 `WorldState.Difficulty`，确保存档与回放能重现同一难度。
