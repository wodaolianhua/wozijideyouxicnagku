# 数值框架

> **本文件的每个数值都必须有依据说明。** "拍脑袋填的"会在后期平衡时变成灾难——
> 因为没人记得这个数为什么是这个数，只能从头试。
>
> 基准线来自 `1_世界观设定.md`：没落贵族起点，2 座城，约 5 年，自适应难度。

---

## 一、平衡目标（先定目标，再定数值）

没有目标就无法判断"数值好不好"。先定目标：

| 指标 | 目标 | 为什么 |
|---|---|---|
| 一局时长 | 60-72 回合（5-6 年） | 用户期望值 |
| 玩家胜率（普通难度） | 25%-45% | 低于 50% 因为玩家需要动脑，高于说明 AI 太弱 |
| 平均存活回合 | ≥ 60 | 太低说明玩家容易早期被灭 |
| 首回合终局比例 | ≈ 0 | 有明显开局崩盘或滚雪球 |
| 玩家资源量级 | 始终低于 AI 10%-20% | 没落贵族设定 |

**"玩家资源低于 AI"是硬性要求。** 如果玩家后期资源反超，说明经营系统出了问题。

## 二、初始状态配置

### 势力对比（普通难度）

| 项 | 玩家 | 中原霸主 | 边疆异族 |
|---|---|---|---|
| 城池数 | 2 | 2 | 2 |
| 每城人口 | 8000 | 12000 | 6000 |
| 人才数量 | 3-4 | 5-6 | 4-5 |
| 平均 Command | 45 | 68 | 60 |
| 平均 Governance | 48 | 65 | 40 |
| 初始粮 | 1200 | 2600 | 1500 |
| 初始银 | 800 | 2000 | 900 |
| 初始兵源 | 300 | 800 | 600 |

**依据说明**：

- 玩家城池少人口少 → 兵力上限低，必须靠用人弥补
- 玩家初始资源约为中原的 45% → 每个决策都很肉疼
- 边疆 Governance 低（40）但 Command 高（60）→ 强在打仗弱在治理，与中原形成镜像

## 三、经济数值

### 粮产

```
每城月粮产 = 人口 × GrainPerPopPerMonth × 屯田等级加成 × 人才加成
GrainPerPopPerMonth = 2     （基准）
屯田等级加成 = 1 + FarmLevel × 0.15   （每级 +15%）
人才加成 = Agriculture 专长 +30%，否则为基准
```

**校验**：8000 人口、无屯田、无人才 = 16000 粮/月。这远超前面的月耗粮（5000 人 = 100 粮）。

**发现问题**：粮产太高，压迫感消失。修正：

```
GrainPerPopPerMonth = 0.15
```

**修正后校验**：
- 8000 人口城 = 1200 粮/月
- 三级屯田 = 1200 × 1.45 = 1740 粮/月
- 5000 兵月耗 100 粮 → 1200 粮可养12 万人

仍然偏高。真正的问题是**人口基数太大**。修正为：

```
GrainPerPopPerMonth = 0.08
人口基数改为千级：玩家城 3000，中原城 4500，边疆城 2500
```

**最终校验**：
- 3000 人口城 = 240 粮/月
- 三级屯田 = 348 粮/月
- 养5000 人（月耗100 粮）→ 348 粮养 3.4 万人

**这才是合理的压迫感**：前期只能养几千兵，打一次大仗就要饿肚子。

### 兵源

```
月兵源 = 人口 × SoldierPerPopPerMonth × (Stability / 100)
SoldierPerPopPerMonth = 0.10
```

**校验**：3000 人口、Stability 60 → 18 兵源/月。

一年才216 兵。**这个太低了**，会导致前期完全打不了仗。

修正：
```
SoldierPerPopPerMonth = 0.5
```
**校验**：3000 人口、Stability 60 → 90 兵源/月，一年 1080 兵。

这样前期可以组建一支千人大军，符合"没落贵族有个家底"的设定。

### 银

| 用途 | 成本 |
|---|---|
| 征兵（每兵） | 3 银 + 2 粮 |
| 修城防（每级） | 200 银 |
| 屯田（每级） | 150 银 |
| 赏赐人才 | 100 银（增加忠诚） |

**校验**：初始 800 银，可以修 4 级城防或屯 5 级田。**每一个选择都很贵**，这正是没落贵族该有的感觉。

## 四、战斗数值

完整公式见 `3_战斗系统设计.md`，此处只列系数：

| 系数 | 值 | 依据 |
|---|---|---|
| baseLoss | 0.35 | 均势攻城需 3 倍兵力才稳妥 |
| 守方损失系数 | 0.6 | 让"龟缩不战"不是最优解 |
| 攻陷阈值| 0.70 | 超过则认为攻不破 |
| 未决双方损失 | 0.10 | 再打一次有代价但不致命 |
| 野战损失系数 | 0.60 × baseLoss | 无城墙消耗，野战更划算 |
| Siege 减伤 | ×0.85 | 专长有实际价值但不夸张 |

## 五、民生数值

| 项 | 值 | 依据 |
|---|---|---|
| 稳定度初始 | 60 | 处境不稳但不崩溃 |
| Stability 月变化 | ±自然恢复 5，跌城时 -15 | 掉城会动摇民心 |
| Morale 月变化 | 自然恢复 3，长期无战 -2 | 和平会腐化，战争会提振 |
| Stability < 30 | 兵源产出减半 | 民心动摇 |
| Stability < 15 | 触发饥荒/动乱事件 | 崩溃线 |

**粮耗与灾荒**：
```
部队月耗粮 = 兵力 × 0.02
Soldier 归零后连续 3 个月 → 饥荒事件
```

**设计意图**：扩张有天然刹车。玩家不能无脑打，打多了自己先崩。

## 六、忠诚度数值

| 项 | 值 | 依据 |
|---|---|---|
| 老部下初始忠诚 | 65 | 一起落难的旧人，有情谊 |
| 月衰减 | 1 | 一年掉 12 点 |
| 叛逃阈值 | 25 | 有缓冲空间，不会突然跑人 |
| 赏赐增加忠诚 | +8| 100 银换 8 点 |
| 新招揽人才初始忠诚 | 40 | 关系尚浅，需要培养 |

**关键**：忠诚必须**有升有降**。玩家必须持续维护，否则会失去所有人才。

## 七、难度档位配置

```
Easy:   AI 资源 ×1.3，AI 决策保守（只屯田征兵，不主动进攻）
Normal: 基准值，AI 会评估威胁会防守
Hard:   AI 资源 ×0.85，AI 主动扩张并针对玩家弱点
```

**铁律**：难度只影响**开局加载的 BalanceConfig**，运行中不得改变。

严禁让 AI "看玩家弱就放水"——那会破坏确定性，导致无头模拟跑两次结果不同、存档回放失效。

难度等级存进 `WorldState.Difficulty`，确保存档与回放能重现同一难度。
