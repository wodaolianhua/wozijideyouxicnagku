## 1. 工作原理（先读懂，不然必踩坑）

- 前端 `WorldScene.ts` 的 `slots.get(file)` 从 **`assets/${file}`** 加载，即运行时由
  WebHost 从 **`server/.../wwwroot/assets/`** 目录伺服（URL：`/assets/xxx.glb`）。
- `client/assets/` 只是**源目录**；`vite.config.ts` 设了 `publicDir: false`，**vite 不会自动拷贝**。
  → 所以最终生效的是 **`wwwroot/assets/`** 里的文件。
- **加载失败/文件缺失 → 自动回退程序化占位体，整局不崩溃**（这是铁律，已验证）。
- 文件名**必须完全匹配**插槽名（区分大小写），否则插槽找不到、继续用占位。

### ⚠️ 接入步骤（每次放一个模型都照这个来）
1. 把最终 GLB 复制到 **`server/StrategyGame.WebHost/wwwroot/assets/<插槽名>.glb`**
   （建议同时在 `client/assets/` 留一份源，方便以后改）。
2. 跑 `dotnet run` 起服 → 浏览器开 `http://localhost:5178` → 看该实体是否变成你的模型。
3. 比例/朝向/脚底不对就改模型重放，**不用改代码**（除下方"城市染色 方案B"）。

## 2. 四个插槽（尺寸/姿态/染色规则，全部实测自 mesh 源码）

| 槽名（文件名，必须一字不差） | 代表什么 | 尺寸 / 姿态 | 染色规则（关键！） |
|---|---|---|---|
| `city_castle.glb` | 城池（地图 6 座） | 占地半径 ≤ 12.4；总高 ≤ 12.6；城名标签在 y≈16.5；按人口整体缩放 0.92–1.28；Y 向上、底部坐落在 y=0 | **⚠️ 全网格被染成势力色**（汉青/魏蓝/蜀红）。写实石头城堡放进去会变纯色要塞 → 见 §3 方案 A/B |
| `lord.glb` | 玩家君主（亲征跟随） | 高 ≈ 2.3、脚在 y=0、Y 向上；低面数人物即可 | **不染色**，你做的颜色原样保留 |
| `army_infantry.glb` | 部队代表模型 | 半径 ≤ 3.1、高 ≤ 5.4；驻城偏移 +x13.5/+z7.5 | **只染命名为 `flag` / `ring` 的子网格**；其余保留你的颜色；**放 GLB 后不再是一排小兵，变单个代表模型** |
| `terrain.glb` | 整张地面（建议最后做） | 大平面，Y 向上 | **不染色**；但会失去程序化高度/植被（代码仍叠加植被层） |

## 3. 城市染色陷阱（必须二选一，再接入城池）

当前 `CityMesh.ts` 把 GLB **所有子网格** `flagParts` 统一染成势力色（见 `update()` 遍历 `flagParts` 改 `material.color`）。
因此：

- **方案 A（不改代码，推荐先试）**：把城堡做成**素胚 / 单色剪影**，靠造型区分，
  颜色交给势力——6 座城自动变成 6 种颜色的要塞，风格统一还好看。
- **方案 B（想要石头质感 + 独立旗色）**：改 `CityMesh.ts` 三行——
  把 `flagParts` 的收集从"全部 mesh"改为"只收集命名为 `Flag` 的子网格"，其余保留你的石材材质。
  → 属 05A 小改动，走**新对话 + 提示词**（不要在原对话改），且必须先确认本指南 §5 的命名约定。

## 5. 给建模/执行 AI 的硬约束

1. **最终文件必须直接进 `wwwroot/assets/`（名=插槽名）**；预览/源文件放独立工作区，不得混进插槽路径。
2. **lord 槽加载 `lord.glb`，不是 `monarch.glb`**——交付前必须改名。
3. 城市若走方案 B，GLB 里**把旗子子网格命名为 `Flag`**，其余保留石材材质。
4. 坐标：Y 轴向上、模型底部中心在原点 (0,0,0) 坐落在地面；尺寸严守 §2（别戳穿标签、别悬空/陷地）。
5. 格式：GLB 单文件（贴图内嵌）；低面数（城池 <3000 三角、人物 <5000）。
6. **绝不在 `client/src` / `server` 源码里硬编码业务数据**；资产只替换外观。
