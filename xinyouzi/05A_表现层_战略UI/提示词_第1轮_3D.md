## 3. 后端 API（00 定死，前端照此对接；JSON 一律 System.Text.Json 默认 camelCase）

> 与原第 1 轮完全一致，引擎无关，照搬：

- 通用：`WorldState` 直接序列化。启动即 `app.Urls.Add("http://localhost:5178")`；静态文件 + 默认页走 `wwwroot/`。
  会话对象单例（静态字段 + `lock`），所有端点串行访问。
- **POST /api/new-game** body `{"seed":12345}`（缺省 12345）：`new SimulationHost(seed, 120)`，置 `State.Factions[0].IsPlayer = true`。返回 `{"state":...,"meta":...}`。
- **GET /api/state** → `{"state":...,"meta":...}`；`meta = { monthsElapsed, isFinished, winnerFactionId, gameOverReason, upstreamGameOverMonth, upstreamGameOverReason, pendingCount }`。
- **POST /api/order** body `{"action":"Recruit|Fortify|Develop|Dispatch|AssignPost|Rest","targetId":N,"secondaryTargetId":N,"amount":N}`：
  仅入队不结算；`OrderId` 由后端从 **100000** 起自增；构造链 `Order.CreatePlayerOrder(...)` → 设 `ExecuteYear/ExecuteMonth/OrderId` → `State.PendingOrders.Add(order.ToPendingOrder())`；返回 `{"queued":true,"pendingCount":N}`；action 无法解析 → 400；后端不做合法性预校验（码 8 原样放行）。
- **POST /api/tick**（锁内按序）：若 `host.IsFinished` → 400；快照本月将结算队列 → `host.RunMonth()` → `turn.Results` 与快照顺序对应（断言 `results.Count == 快照条数`）→ 本月事件取 `State.EventLog` 增量（**陷阱**：`turn.Events` 是累计量，禁止直接用）→ 返回 `{"year","month","results":[...],"events":[...],"meta","state"}`。
- 除上述端点外不加任何东西。

## 4. 前端要求（three.js 3D，覆盖 README R1–R6 + 重定 scope）

- 技术栈只许 **three.js 8.x + vite + typescript**；禁止 React/Vue/jQuery；禁止 PixiJS（本轮回溯为 3D）。
- `Core/Types.ts`：与后端 JSON 对齐的手写 interface（state/meta/results/events），不引入代码生成。
- **R1 状态镜像**：`GameStateStore` 拉取 `/api/state` 缓存为只读；所有组件/场景从 store 读，不得持私有副本自行修改。
- **R2 指令唯一入口**：所有操作经 `OrderSender` → `GameClient` → `/api/order`。UI 文案讲清「下令成功 ≠ 执行成功：成败看下月结算 code/message」；失败指令必须把中文 `Message` 显示出来。
- **R3 3D 上帝视角（战略地图）**：`WorldScene` 用 three.js 渲染 3D 地形 + 城池 mesh（按城 Id 取 `assets/` 模型，缺则占位盒）+ 部队 mesh + 邻接连线（按 `AdjacentCityIds`）。
  **坐标**：契约 `City` 无坐标字段——00 裁决允许 UI 内置一张**仅布局用**静态坐标表（按城 Id），写进汇报；城名/归属/人口/城防/首都一律从 state 读。
  相机为可旋转/缩放的轨道相机（OrbitControls 或自写）；选中城高亮并标出相邻城；点击/悬停显示关键信息。
- **R4 双层视角（真实化，核心）**：提供「上帝视角 / 亲征视角」切换入口。
  - 上帝视角：宏观地图 + 全部势力信息，可下达宏观指令（征兵/屯田/修城/任命/休整）。
  - 亲征视角：第一/三人称，玩家操控君主 mesh 行走（`Player/Controls.ts`：键鼠 WASD/拖拽转视角 + 触屏虚拟摇杆）；走近己方城池/部队浮现交互气泡，右下「交互」键打开该目标操作面板；「军议」→ 选中己方军团 → 选目标城 → 地面升起行军箭头 → 点「下令进军」发出 `Dispatch`。
  - **性能优先于花哨**：先保证可走、可交互、可下令，视觉打磨靠资产槽后续替换。
- **R5 回合结算**：`/api/tick` 后 HUD 覆盖层展示本月 `events`（中文 Message）+ 玩家指令成败（code/message）+ 数值变化（`deltas` 的 targetType/field/old→new）；「继续」进入下月。
- **R6 人才面板**：`Ui/Hud.ts` DOM 覆盖层列出 Name/Specialty/Command/Governance/Loyalty/Post/PostCityId；
  任命/换任用 `AssignPost`（语义照 04 范例：`TargetId=OfficerId、Amount=-1、SecondaryTargetId=岗位所在城Id`）；赏赐置灰（见第 0 节）。
- **资产槽（asset slot）机制**：`assets/` 下的模型按固定文件名加载（如 `city_castle.glb`、`lord.glb`、`army_infantry.glb`、`terrain.glb`）；
  **加载失败/文件缺失 → 必须回退到程序化占位体，且整局不崩溃**。每个槽在汇报列「资产槽清单」（实体 → 文件名 → 放置路径 → 当前是否占位）。
- **性能红线（验收硬门槛）**：重复实体（士兵/植被等）用 `THREE.InstancedMesh` 批量渲染；开启视锥剔除；
  地形/大场景做分块或 LOD；目标在 Intel UHD730 核显下 6 城 + 部队 + 地形稳定可玩帧率。性能不达标打回。
- 势力配色写进 `Theme.ts`（汉青/魏蓝/蜀红一类可区分三色）。
- 铁律（验收会抽查）：UI/Scene 层不得对 state 字段赋值、不得有资源/伤害计算公式；业务数据禁止硬编码（布局坐标表唯一豁免）。
