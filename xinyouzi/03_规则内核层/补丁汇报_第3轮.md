## 四、补丁提示词各节逐条回答

**修复一（围城自锁）**：4 个子项全部落地。① L99 `underSiege` 加阵营排除（见第二节）；② `FindDispatchableArmy` 两轮查找，第二轮条件、统帅优先与 Id 破平严格照单，第一轮优先级不变；③ 续攻走到战斗分支后的一切照旧——攻陷走 Capture 进驻易主，再僵持则 Besieging 维持、−3 照结、`HasEngagedThisMonth` 照置（第 2 轮逻辑一行未动），T5 实证两连僵持后城下部队 stance 保持 Besieging、城未易主；④ 顶部校验顺序注释第 5 条已补「同阵营围城部队豁免」。相邻性校验未动，续攻指令仍传相邻出发城（语义为补给方向）。

**修复二（月度标记月初翻转）**：翻转位置在每支部队三分支之前（含参战分支），仅当前值为 true 时产出 delta。两点执行口径说明：
- 补丁原文「对每支 inBattle 部队」按 T7 的构造（未参战部队两标记也必须翻转）理解为「**每支进入月度结算的部队**」；`Soldiers <= 0` 的部队整段跳过（与现有结算范围一致），两标记保持原值——0 兵部队既不能休整也不会哗变，无行为影响（见遗留疑问第 1 条）。
- 「先清后判」第一版实现有遗漏：翻转 delta 产出后，哗变判定仍读了翻转前的标记，导致 T7 段二与改锁后的旧哗变测试失败（191/193）；修正为翻转后局部值参与判定后全过。修正本身由本轮新测试抓住，正是测试要锁的行为。
- 翻转 delta 与哗变置位 delta 在同一列表内按序写回（1→0 → 0→1），反射式 StateApplier 顺序应用，无需改动（裁决预期一致）。
- `DeltaField` 常量：未新增，理由见第二节末尾说明。

**修复三（守军参战信号）**：与攻方对称，在守军战损分摊的同一循环内补发两个 delta，OldValue 取守军当前值；守方士气 −4 仍由 `CalculateDefenderMoraleDelta()` 结算，次月结算走参战分支不恢复不腐化；不在 defenders 列表的部队不置位。T8 锁定：连续被围 4 个月，守军士气只被战斗 −4/月（75→59），无一次 +3、无 −6、计数恒 0、标记逐月消费清零。

**修复四（注释纠错）**：remarks 已整段替换为裁决文本，删除了与裁决描述冲突的旧 TODO(05B) 注释；数值 2 未动；TurnPipelineTests 的既有覆盖继续通过。

**T1-B workaround**：已改真实续攻路径（见第三节第 3 条），未保留复位写法。

## 六、遗留疑问与备案（照实上报，未自行发挥）

1. **「每支 inBattle 部队」的措辞口径**：已按 T7 场景理解为「每支进入月度结算的部队」（含未参战、含休整过的）。`Soldiers <= 0` 的部队整段跳过、不翻转（0 兵部队无休整/哗变行为，无实际影响）。若 00 要求 0 兵部队也翻转，把两段翻转移到 `Soldiers <= 0` 的 `continue` 之前即可（一行位置调整），待裁决。
2. **TurnPipeline 哗变事件过滤为修复二必要配套**：月初翻转 delta 与哗变置位 delta 同走 `ArmyHasMutiniedThisMonth` 字段，原事件循环按字段名发事件，不过滤会让上月哗变者每月初被刷一条假「哗变逃散」事件（现有测试集不覆盖）。本次按原注释本意（「由 0 变 1」）加 `NewValue == 1` 过滤，属实现补全，备案说明。
3. **HasMutiniedThisMonth 的语义在新规则下已弱化**：每月月初翻转后，它不再是跨月防重复的闸门（推月管线每月只结算一次，是否再哗变完全由当月士气决定）；其现存作用是「本结算周期发生过哗变」的信号（含 TurnPipeline 事件判定与 UI 可读性）。契约注释与 01 文档对该字段生命周期的描述是否需要同步改写，请 00 定夺（本轮未动契约/01）。
4. **围城自锁的残留边角**：修复一解决了「有兵的围城部队被锁」，但若围城部队兵耗至 0（两轮查找均要求 `Soldiers > 0`），它仍滞留敌城且无法被调度，城对其本方也仍处于「己方围城中」状态；裁决明确不新增撤围/退回指令，此边角无解法，仅备案（击退分支会送回出发城，不受影响；该状态只能靠敌方反攻或后续机制解除）。
5. **T5/T1-B/T8 的「守军回填」夹具写法**：为维持多月「攻未决」战果稳定（守军会被战斗消耗至 0 → 变攻陷），测试逐月把守军补回 80。这是夹具维护而非语义断言，如 00 认为应改用逐月真实兵力推演，可调整（战果分支会随兵力变化，断言需重算）。
6. **上轮遗留第 5、6 条无进展**（非 03 侧可动）：01 侧 `4_数值框架.md` 5.2.2 示例轨迹与定稿不一致；`assets/data/config.json` 在 02 包，需同步阈值 4 / 腐化 6 / 野战乘数 5000 三个值。上轮遗留第 7 条（UnstableMoraleLoss 用途）已由本轮修复四收口。
