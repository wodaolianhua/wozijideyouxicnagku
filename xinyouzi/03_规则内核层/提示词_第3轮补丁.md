## 修复一：围城自锁（最优先）

**症状**：僵持（未决）后攻方滞留目标城、姿态 Besieging；① `Validate` 的 underSiege 判定不分阵营，围城者自己也被拦截；② `FindDispatchableArmy` 只认出发城（PositionCityId == SecondaryTargetId），身处目标城的围城部队永远找不到 → 部队与城双死锁，而僵持事件文案写着「下月可再战」，直接矛盾。

**裁决：同阵营豁免 + 围城部队就地续攻。不新增指令、不改契约。**

改 `src/Resolvers/DispatchResolver.cs`：

1. `Validate` 的 underSiege 判定（约 L99）加阵营排除——**只有敌对阵营的 Besieging 部队才算围困**：

```csharp
bool underSiege = state.Armies.Any(a =>
    a.PositionCityId == order.TargetId
    && a.Stance == ArmyStance.Besieging
    && a.OwnerFactionId != factionId);
```

2. `FindDispatchableArmy`（约 L520）加第二轮兜底：第一轮维持现状（从 `SecondaryTargetId` 出发城找）；**找不到时**，第二轮在己方部队中找 `PositionCityId == order.TargetId && Stance == Besieging && Soldiers > 0` 的部队（同样统帅优先、Id 破平），即让已经在城下围城的部队就地再战。相邻性校验（SecondaryTargetId 与目标相邻）保留不动——续攻指令仍传相邻城，语义为补给方向。
3. 确认续攻走到战斗分支后：攻陷则按现 Capture 分支进驻易主；再僵持则 Besieging 维持、−3 照结、`HasEngagedThisMonth` 照置（第 2 轮补丁逻辑不动）。
4. 顶部校验顺序注释（第 5 条「目标城未被围困」）补一句「同阵营围城部队豁免」。

## 修复二：月度标记月初翻转

**症状**：`HasRestedThisMonth` 只在出兵时清零→纯休整部队一生只能休整一次；`HasMutiniedThisMonth` 从不清零→哗变一生一次。两者语义都是「同一月内防重复」。

**裁决：在 `MoraleSystem.ResolveMonthlyMorale` 对每支 inBattle 部队做月度结算之前，先产出两个清零 delta（仅当当前为 true 时）**：`ArmyHasRestedThisMonth 1→0`、`ArmyHasMutiniedThisMonth 1→0`，然后再走三分支。反射式 StateApplier 会自动写回，无需改它。

- 先清后判：本月士气若仍 ≤ 0（如参战分支不恢复），**允许再次哗变**——这是预期行为，加测试锁住。
- RestResolver / DispatchResolver 对这两个字段的现有写法一律不动。
- DeltaField 若缺 `ArmyHasRestedThisMonth` 常量，在 Types.cs 补齐（值与契约属性名同名）。

## 修复三：守军参战信号（本轮收口）

**症状**：守军参战不置 `HasEngagedThisMonth`、不清零计数→被围城的头 3 个月守军反而每月 +3 回血，第 4 月起又在打仗的同时被腐化 −6。

**裁决：守方与攻方对称。** 在 `DispatchResolver` 战斗分支遍历 `defenders` 分摊战损的同一个循环里，为每个参战守军补发两个 delta：`ArmyHasEngagedThisMonth →1`、`ArmyMonthsWithoutBattle →0`（OldValue 取守军当前值）。守方士气 −4 已由 `CalculateDefenderMoraleDelta()` 结过，次月结算走参战分支，不恢复不腐化。没有参战的部队（不在 defenders 列表）不置位。

## 修复四：UnstableMoraleLoss 注释纠错

上一轮 TODO 注释加错了位置。该常量**现用途**是 `EconomySystem.ResolveMoraleAndStability` 中 Stability < 30 时势力民心额外流失（数值 2，TurnPipelineTests 已锁定），与 05B 无关。把 remarks 改为准确描述：「现用途：低稳定度民心流失（EconomySystem，测试锁定）。05B 实时战斗若需士气流失模型，**新增独立配置项，禁止挪用本项**。」**数值不动。**

## 新测试（4 条，期望总数 189 + 4 = 193 全过）

- **T5 围城续攻**：Dispatch 僵持成功后，次月同势力再对同一目标下 Dispatch（SecondaryTargetId 仍传相邻城）→ `IsSuccess`，且出战的是城下那支 Besieging 部队（断言其兵力再次被扣 / 不再返回 `RejectedTargetSieged`）。
- **T6 第三方仍被拦**：僵持后，第三方势力对该城下 Dispatch → `RejectedTargetSieged`。
- **T7 月初翻转**：构造 `HasRestedThisMonth=true`、`HasMutiniedThisMonth=true` 的部队，结算一次 → 两标记均归 false 且有对应 delta；再造「上月已哗变、本月 `HasEngagedThisMonth=true`、士气 ≤0」→ 再次产出哗变兵力 delta（一生一次 bug 消除）。
- **T8 守军不回血**：经 DispatchResolver 打一场有守军的战斗 → 守方 `HasEngagedThisMonth=true`、计数 0；次月 MoraleSystem 结算 → 守方士气不变（不 +3）、标记消费清零；连续被围 4 个月 → 始终不腐化（无 −6、计数保持 0）。
