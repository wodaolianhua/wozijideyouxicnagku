## 1. 背景：为什么打这个补丁

04 智能体层首轮流验被驳回，连带暴露你包内 **D12 核心链路（用人→粮产可观测变化）是占位假实现**。
00 裁决原文（与你直接相关的 C 条）：

> **C. D12 核心链路在 03 侧是占位假实现**
> - `EconomySystem.ResolveGrainIncome` 的人才修正 = **在岗人数 × 5 个百分点**
>   （`PlaceholderNumbers.GovernanceBonusPerPostedOfficer`），与专长、岗位、Governance 全无关。
>   农业专家和庸才当差，粮产逐字段相等。换人无可观测后果 = D12 判失败。
> - `config.json` 的 `specialtyBonus`（Agriculture:FarmOverseer=2500 等）02 已备好、
>   ConfigValidator 已校验，但**全项目没有任何代码消费它**。
> - `City.FarmLevel` 屯田等级**不进粮产公式**；`ResolverBase.GetGovernanceModifier`
>   同样是"数人头×5%"占位（Develop/Fortify/Recruit 的银耗都在用，方向还是反的——在岗越多越贵）。

设计依据（01 原文，内联，禁止再去翻 01）：

> `5_指令字典.md` 第 5 条：
> - CityGovernor 城守：Governance → 城市综合加成
> - FortifyOverseer 军师佐政：Governance → 城防提升效率
> - FarmOverseer 屯田使：Governance + Agriculture → 粮产加成
> - 换任需 `PostTakeEffectMonths` 个月才生效，**生效前不提供任何加成——频繁换将有代价**。
> - 验收标准原文：**"换人之后结算结果必须可观测地变化。"**
>
> `4_数值框架.md`「粮产」：
> ```
> 每城月粮产 = 人口 × (GrainPerPopPerMonth / 10000) × 屯田等级加成 × (人才加成 / 10000)
> 屯田等级加成 = 10000 + FarmLevel × 1500   （每级 +15%）
> ```

**本轮目标**：把裁决公式落成真实代码 + 具体数字断言。兵源公式、战斗、士气一律不碰。

## 2. 裁决定稿公式（本轮唯一权威，逐字实现）

一城一岗（`AssignPostResolver` 已强制：任意在岗人才即占位），以该城**已生效**在岗人才
（`PostedSinceMonths >= BalanceConfig.PostTakeEffectMonths`）为加成唯一来源：

```
城市人才加成(万分比) = G × officer.Governance + 专长加成
  G = PlaceholderNumbers.GovernancePointToBonusPerMille（新常量，基准 50 = 每点政务 +0.5%，标 TODO(数值)）
  专长加成 = config.SpecialtyBonus["{专长枚举名}:{实际岗位枚举名}"]
             ?? config.SpecialtyBonus["{专长枚举名}:Any"] ?? 0
  枚举名用 C# 的 ToString()，例如 "Agriculture"、"FarmOverseer"，与 config 键完全一致

每城月粮产 = 人口 × GrainPerPopPerMonth/10000
           × (10000 + FarmLevel × 1500)/10000
           × (10000 + 城市人才加成)/10000
势力月粮产 = 所辖各城【逐城向下取整】后求和（保持整除截断、确定性）
```

细则（全部是裁决的一部分，不要自由发挥）：

1. **粮产贡献岗位只有 `FarmOverseer` 和 `CityGovernor`**。该城在岗人才实际岗位是
   FortifyOverseer / General / Scoutmaster 时，对粮产贡献 0。
2. "实际岗位"取 `officer.Post`（任命时由 Resolver 按专长推导后写入的存量值），**不要重新推导**。
3. 生效窗口：`PostedSinceMonths < PostTakeEffectMonths` 期间整个人才加成按 0 处理（FarmLevel 照常生效）。
4. 人才筛选条件与 `EconomySystem.ResolveInfrastructure` 现有写法保持一致：
   `PostCityId == city.Id && Post != PostType.None && IsAlive && OwnerFactionId == city.OwnerFactionId`，
   再加生效窗口判定。Resolver 保证每城至多 1 人，取 `FirstOrDefault()` 即可。
5. 城内每一步乘算都做整除截断（顺序：基础粮 → 屯田等级 → 人才加成），全程 `long` 中间值、禁浮点。
6. 城池人口 ≤ 0 的城跳过（与现有空势力跳过风格一致）。势力无任何产粮城时不产出 FactionGrain delta。
7. `EconomySystem.RatioBase`（10000）是全程序唯一万分比基数常量，新代码一律复用它，
   **不得再发明第二个 10000 常量**（Resolver 侧也用它全名引用）。

Develop / Fortify 银耗改为**岗位折扣**（裁决原文："Develop 的成本折扣改用 FarmOverseer、
Fortify 用 FortifyOverseer 取才，公式同上（专长+政务，万分比）"）：

```
折扣(万分比) = 目标城已生效在岗人才【且实际岗位 == 所需岗位】的城市人才加成，否则 0
  Develop 所需岗位 = FarmOverseer
  Fortify 所需岗位 = FortifyOverseer
实付银 = max(0, baseCost × (10000 − 折扣) / 10000)   // 向下取整
baseCost 维持现状：Base{Develop|Fortify}CostSilver × amount / 100
```

Recruit 银耗：**删除政务修正**（现状是"在岗人头越多越贵"的反向占位；征兵在新岗位模型中
没有对应政务岗，城守"综合加成"扩展按裁决留给 06，本轮备案不做）。
即银耗 = `BaseRecruitCostSilver × amount / 100`，粮耗公式与加 2/兵 的附加粮不动。
兵源产出公式（`ResolveSoldierIncome`）**一字不动**。

数值现状提醒（不要当 bug 去改 config）：正式表没有 `Siege:FortifyOverseer` 也没有 `Siege:Any`，
所以攻城专长当军师佐政时专长加成查表落空 → 0，只吃 Governance 部分。这是数据现状，按公式自然得 0。

## 3. 逐文件改动清单

### 3.1 新增 `StrategyGame.Core/src/PostEffects.cs`

`internal static class PostEffects`（namespace `StrategyGame.Core`），集中放岗位取才逻辑，
供 EconomySystem 与 ResolverBase 共用，避免两处各写一份查表：

- `Officer? GetEffectiveCityOfficer(WorldState state, City city, BalanceConfig config)`
  按第 2 节细则 4 的条件 + 生效窗口取该城唯一已生效在岗人才，无则 null。
- `int GetBonus(Officer officer, PostType actualPost, BalanceConfig config)`
  = `PlaceholderNumbers.GovernancePointToBonusPerMille * officer.Governance + 专长查表`，
  专长查表先走 `"{specialty}:{post}"` 再走 `"{specialty}:Any"`，都缺返回 0。
- 纯函数、静态、无随机、无 IO；公开成员 XML 注释补齐（本工程开了 XML 文档强约束）。

### 3.2 `src/Systems/EconomySystem.cs`

- `ResolveGrainIncome`：从"势力总人口一次算"改为第 2 节的**逐城循环、逐城截断、求和**，
  每势力仍只产出一条 `FactionGrain` delta（OldValue 为当前粮，NewValue 为当前粮+势力总和）。
- 删除私有 `CalculateTalentModifier`（数人头×5 的旧实现），改走 `PostEffects`。
- 类注释/方法 XML 注释里"人才修正 = 在岗人数"等过时描述同步改成新公式（含 FarmLevel、
  生效窗口、贡献岗位白名单），注释里的示例数字（3000 人口 240 粮）在空岗前提下仍成立，保留。
- 其余方法（兵源、民心、屯田度累积、到岗计数、忠诚衰减、耗粮）一律不动。

### 3.3 `src/IResolver.cs`（ResolverBase）

- **删除** `GetGovernanceModifier(WorldState, int factionId)`（数人头占位，三处调用方本轮全部改完）。
- 新增两个 `protected static` 帮助方法（名字可调，语义不能变）：
  - `GetCityPostDiscount(state, cityId, requiredPost, config)`：取目标城已生效在岗人才，
    仅当其 `Post == requiredPost` 时返回 `PostEffects.GetBonus(...)`，否则 0；城不存在返回 0。
  - `ApplyDiscount(baseCost, discountPerMille)`：
    `Math.Max(0, baseCost * Math.Max(0, RatioBase − discount) / RatioBase)`，
    分母复用 `StrategyGame.Core.Systems.EconomySystem.RatioBase`（全名引用，加 using 也行）。
- `ScaleInteger` **保留不动**（它是通用定点工具；本轮后虽无调用方，也不要删，避免波及面）。

### 3.4 三个 Resolver 的银耗
