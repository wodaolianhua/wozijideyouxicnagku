## 1. 做了什么

本轮把整条游戏链路接起来，交付无头批量模拟器。四件产物全部落地：

| 产物 | 文件 | 说明 |
|---|---|---|
| **SimulationHost** | `src/StrategyGame.Sim/SimulationHost.cs` | 月循环宿主。补上 03 流水线缺的最后一块接线：把 AI 产出的下月指令入队（执行月 = 下一月），并按三方混战口径判定终局。 |
| **SaveSystem** | `src/StrategyGame.Sim/SaveSystem.cs` | JSON 存档。`WorldState`（自带 `Seed` / `Difficulty`）+ `FormatVersion` / `MonthsElapsed` / `NextOrderId` / `RandomState` / `MaxMonths` / `ApplySeedVariance`。 |
| **ReplaySystem** | `src/StrategyGame.Sim/ReplaySystem.cs` | 回放。记录每月**实际入队**的指令全字段，重放时**不接 planner**，逐月恢复随机源状态。 |
| **BatchSimulator + CLI** | `src/StrategyGame.Sim/BatchSimulator.cs`、`src/StrategyGame.Tools/Program.cs` | N 局 × 120 月无头批量模拟，导出 CSV。 |

配套：

- `CsvExporter` / `CsvReader` —— CSV 导出与回读（回读保证「报告数字」与「CSV 数字」同源）。
- `BalanceReportWriter` —— 平衡分析报告生成器（第 7 节）。
- `ReplayViewer` —— 回放可视化输出（任务书交付清单要求）。
- `SimStateComparer` —— 逐字段状态比较器。
- `WorldVariator` —— 种子敏感化（见疑问条 1）。
- `PackagePaths` —— 包路径定位，保证所有输出与临时文件落在 E 盘本包内。

工程布局（全部新建在本包内）：

```
06_工程与验证层/
  src/StrategyGame.Sim/        库：Host / Save / Replay / Batch / CSV / 报告
  src/StrategyGame.Tools/      控制台 Exe：simulate / analyze / replay
```

## 5. 确定性风险（最高优先级）

### 5.1 已锁定的四条（测试覆盖）

| 风险点 | 对策 | 验证 |
|---|---|---|
| 随机源未注入 / 用了 `Random.Shared` | 全链路共用同一个 `DeterministicRandom(seed)`；代码中无 `DateTime.Now` / `Guid` / `Random.Shared` | ✅ |
| 跨局共享随机源或可变对象 | 每局独立 new 宿主；并行下每局独立 rng/planner/pipeline/processor/applier/state | ✅ 并行 CSV 字节一致 |
| Dictionary 遍历顺序依赖 | 一切排序前先 `OrderBy(Id)`；CSV 列顺序写死 | ✅ |
| 读档后随机流错位 | 存档含 `RandomState`，读档 `SetState` 还原 | ✅ |

### 5.2 残留风险（本轮发现，需上游处理）

**R1（高）上游 `SampleData.CreateWorld(seed)` 不消费 seed 生成世界内容。**
`CreateWorld` 只把 `seed` 存进 `WorldState.Seed`，三个势力的初始资源、城池、部队、人才**全部硬编码**。
全链路唯一的随机消费点是 04 的 `BestFitPolicy.SelectBestFor`（「多个人才 Governance 并列时随机取一个」），
而样例数据五个人才的 Governance 互不相同（90 / 95 / 60 / 100 / 50），**永远不并列**。
后果：严格照抄上游时，**1000 局跑出完全相同的一局**，所有平衡指标退化为常数，批量模拟器失去意义。

**06 层的处置**：新增 `WorldVariator`，按 seed 生成的置换把上游样例中**已有的**三档初始资源
（粮/银/兵源 5000-4000-3000 / 500-400-300）重新分配给三个势力。
- 不新增任何数值（三档全部取自 `SampleData.CreateWorld` 原值）；
- 不改上游任何文件、不改 `BalanceConfig`；
- 目的是让三方初始条件对称化，使「基准槽位胜率」测的是 AI 决策质量而非开局强弱。
- 默认**开启**；`--strict-world` 可复现严格照抄上游的基线行为。
- **上游一旦改为真正按 seed 生成世界，`WorldVariator` 应整体弃用。**

**R2（中）上游 `VictoryChecker` 是「玩家口径」，三方全 AI 时不可用。**
它用 `state.GetPlayerFaction()`（`IsPlayer == true` 的势力）作基准；三方全部 `IsPlayer = false` 后
基准势力不存在，上游会在**第 1 个月**给出「玩家全部城池易主，败局已定」的误判。

**06 层的处置**：宿主层按**三方混战口径**自行判定终局（仅剩 ≤1 势力持城 → Elimination；
跑满月数上限 → Stalemate）；上游的 `turn.GameOver` / `GameOverReason` 仍**原样记录**到
`GameResult.UpstreamGameOverMonth` / `UpstreamGameOverReason` 供裁决，**不改上游代码**。

**R3（中）兵源与部队兵力之间无转化环节（P0 结构性缺口，导致 100% 僵持）。**
`ResolveSoldierIncome` 产出的是 `Resources.Soldier`（势力可用兵源池），
`RecruitResolver` 也只加 `Resources.Soldier`；而 `Army.Soldiers`（部队现有兵力）
**只被 Dispatch 战斗损耗与哗变减少，从不增加**。
两者永不相通 → 部队兵力永远卡在初始的 300 / 250 → 低于 `AiFactionPlanner` 的出兵安全线
`SoldierSafetyThreshold = 500` → `AddMilitaryOrders` 分支永不进入 → `Dispatch = 0` → 无攻城 →
120 月全僵持。**这是僵持率 100%、攻陷 0 次的直接原因。**

**R4（低）`TurnResult.Events` 是累计量而非本月增量。**
`TurnPipeline` 第 11 步执行 `result.Events.AddRange(state.EventLog)`，把**整个**事件日志追加进当月结果。
06 层统计哗变/攻陷时改为按 `EventLog` 长度增量统计，避免重复计数。
建议上游澄清 `TurnResult.Events` 的语义，或另加「本月事件」字段。

## 6. 设计问题（只上报，不改上游）

| # | 问题 | 涉及包 | 建议 |
|---|---|---|---|
| D1 | `CreateWorld(seed)` 不消费 seed（R1） | 03 | `SampleData.CreateWorld` 改为真正按 seed 生成世界内容（势力初始资源、城池归属、部队布防等），或 02 包提供带 seed 的世界生成器。 |
| D2 | `VictoryChecker` 玩家口径（三方全 AI 误判）（R2） | 03 | 增设「无玩家势力」分支，或提供 `EvaluateMelee` 多方混战口径；契约层面 `WorldState` 是否需要「基准势力」显式字段待裁决。 |
| D3 | 兵源 → 部队兵力无转化环节（R3） | 03 / 04 / 01 | 设计层需要裁决：征兵产出的兵源如何进入部队？「征兵」与「募兵」是两个概念还是同一条链路？在此之前 AI 出兵分支不可达，所有攻城/士气/战损数值都无法验证。 |
| D4 | `MaxOrdersPerFactionPerMonth` 名义按势力、实为全局单计数器 | 03 | `WorldState.ActionsThisMonth` 是全局单一计数，而上限按势力。三方混战下每月只有 5 条指令能执行（合计），实测 `RejectedInsufficientCapacity` 占 13.65%。`IResolver` 已有 TODO 标注，需裁决是否加 per-faction 字典（属契约变更）。 |
| D5 | 部队士气在无战斗时持续腐化，休整排不上队 | 04 | 实测士气均值 6、低士气占比 90%。`AiFactionPlanner.AddStrategicOrders` 的经济/防守分支先抢占每月指令额度，`Rest` 长期发不出去。建议裁决休整是否应豁免指令额度。 |
| D6 | 事件系统工厂签名拿不到势力 Id | 03 / 00 | `Func<WorldState, OfficerEventSystem>` 无法区分势力，`RunOfficerEvents` 给三方抽同一份事件。本轮 `eventSystemFactory` 传 null 跳过（第 8 节备案 2），接线方式待裁决。 |
