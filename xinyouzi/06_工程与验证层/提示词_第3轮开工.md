## 1. 你要做什么

把整条游戏链路接起来，做出**无头批量模拟器**——改 JSON→跑 1000 局→出 CSV 对比报告，
这是项目数值迭代速度的分水岭。本轮四件产物：

1. **SimulationHost**：月循环宿主（03 的流水线缺的最后一块接线，见第 3 节）。
2. **SaveSystem**：JSON 存档/读档，必须含 **Seed** 与 **Difficulty**。
3. **ReplaySystem**：记录每月指令并逐条重放，结果与原模拟**逐字段相等**，重放时**不再调用 AI**。
4. **BatchSimulator + CLI**：N 局 × 120 月无头批量模拟，导 CSV；
   `dotnet run --project StrategyGame.Tools -- simulate --games 1000 --seed 12345 --out result.csv`。

## 3. 月循环接线（03 流水线的最后一块，由你补在 06）

03 的 `TurnPipeline.RunMonth(state)` 11 步固定调度，但**它不会把 AI 产出的下月指令自动入队**
——这是 03 有意留给宿主的接缝，由 SimulationHost 闭环。以下事实我已核对源码，照做；
属性名若与你读到的不一致，以 03 源码为准并在汇报中说明。

### 3.1 每局构造（每局独立实例，禁止跨局共享）

```csharp
var config = SampleData.CreateBalance();
var rng    = new DeterministicRandom(seed);                 // StrategyGame.Core，实现契约 IRandom
var applier  = new StateApplier();
var registry = ResolverRegistry.CreateDefault(config, rng);
var processor = new CommandProcessor(registry, applier);
var planner   = new AiFactionPlanner(config, rng);          // StrategyGame.AI
var pipeline  = new TurnPipeline(
    processor, applier, config,
    eventSystemFactory: null,   // 03 自己的测试也接 null；人物随机事件 P0 跳过，写进汇报疑问
    planner: planner);
```

- 一局内所有随机消费共用**同一个** `DeterministicRandom(seed)`（结算器、AI 同流），
  构造顺序固定，保证同 seed 逐字段复现。
- 每局 seed 规则：`gameSeed = baseSeed + gameIndex`（确定性、无 DateTime/Guid）。

### 3.2 每月循环

```
初始 state = SampleData.CreateWorld(gameSeed)，再把三个势力 IsPlayer 置 false
for month in 1..120（或提前 GameOver）:
    var turn = pipeline.RunMonth(state);
    记录 turn.Results（每条指令结算码）、turn.Events、turn.GameOver/Reason
    把 turn.NextMonthOrders 排到【下一个月】执行：
        next = 本月(state.Year, state.Month) 的下一月（12 月进位到次年 1 月）
        每条 order：
            OrderId = 本局自增计数器（从 1 开始，确定性）
            ExecuteYear/ExecuteMonth = next
            state.PendingOrders.Add(order.ToPendingOrder())   // StrategyGame.Core 的 OrderExtensions
        同时把这些 order（含其执行年月）追加进【回放日志】
    if (turn.GameOver) 提前结束，记录存活月数
```

要点：

- **顺序铁律**：RunMonth 内部第 1 步已先推进时间，第 9 步才产 AI 指令，
  所以入队时执行月必须是 state 当前年月的**下一月**；早一个月或同月都会错。
- 第 7 步到期指令由 pipeline 自行 `GetDueOrders`/执行/`RemoveDueOrders`，你不要插手。
- `Order.ToPendingOrder()` 是 `StrategyGame.Core.OrderExtensions` 的扩展方法；
  `Order.CreateAiOrder` 产出的 ExecuteYear/Month 为 0，入队前由你覆盖。
- 拒绝的指令不中断月循环（03 已如此设计）；你负责统计。
- `TurnResult.Snapshot` 是每月 `state.Clone()`，**不要**用它做存档（120 份 clone 只为 UI 用）；
  存档直接序列化当前 state。

### 3.3 「无非法 Order」的真实闸门（本轮核心验收之一）

对 `turn.Results` 中每条结果：

- **`RejectedNotImplemented`（码 8）计数必须为 0**——04 已不再产出 Reward/RecruitOfficer，
  若出现即链路仍有非法行动，测试失败，不许吞。
- 其余拒绝码（资源不足 2、无岗位 5、冷却 7 等）按行动类型计数，写进 CSV/报告：
  它们是 AI 决策质量的数据点，不是崩溃；但**比例异常高要在报告里点名**。
- 字段名以 03 源码 `ResolveResult`/`ResolveResultCode` 为准（读 `IResolver.cs`、契约 Enums.cs）。

## 4. 四个组件的要求

### 4.1 SaveSystem（JSON 存档）

- System.Text.Json（框架内置，**禁止引第三方包**）；序列化整个 `WorldState`，
  它自带 `Seed`、`Difficulty`（D16：自适应难度只调数值不调行为，这两个字段必须随档持久化）。
- 存档附加元数据（建议包一层 `SaveFile { int FormatVersion; WorldState State; int MonthsElapsed; ... }`）：
  至少含已模拟月数、本局自增 OrderId 计数器的当前值、格式版本号（初版 = 1）。
- 读档后状态必须能直接喂给月循环继续跑。
- 注意：`WorldState`/`PendingOrder` 等均为无参构造 + 公共属性，可直接 JSON 往返；
  若发现某字段不能往返（如接口类型），停下写汇报，不许改契约。

### 4.2 ReplaySystem（回放）

- 日志 = 每月**实际入队的指令全字段**（行动、双方 Id、Amount、SecondaryTargetId、执行年月、OrderId）。
- 回放 = 相同初始世界（同 seed、同 IsPlayer 改写）+ 相同构造顺序，
  **不接 planner**（pipeline 的 planner 传 null），逐月把日志里该月的指令入队、RunMonth。
- 断言：回放终局 `StateSnapshot.Capture(state)` 与原模拟终局**逐字段相等**
  （03 有 `StrategyGame.Core.StateSnapshot`，可直接用；其比较口径若不覆盖你新增的统计字段，
  以 state 本体为准）。
- 日志序列化进 JSON（存档与回放日志可以同一文件分节，格式自定但要写注释说明）。

### 4.3 BatchSimulator（无头批量）

- 一局一次 `SimulateGame(seed)` 返回 `GameResult`：seed、胜方 Id（无则 -1）、GameOverReason、
  存活月数、终局三势力城池数/兵力/银粮、各行动发起数、各类拒绝码计数、哗变次数、
  AI 指令总数、NotImplemented 计数。
- 聚合：按 seed 升序处理；允许并行（`Parallel.ForEach` 均可），但**每局独立
  rng/planner/pipeline/processor/applier/state**，禁止共享随机源与可变对象；
  聚合结果按 gameIndex 排序后再写 CSV，保证并行不改变输出顺序。
- 禁止 `DateTime.Now`/`Guid.NewGuid()`/`Random.Shared`；任何排序聚合前先 `OrderBy(Id)`，
  不许依赖 Dictionary 遍历顺序。

### 4.4 CLI（StrategyGame.Tools）

- 参数：`simulate --games <N> --seed <base> --out <csv路径>`；
  N 默认 1000、seed 默认 12345、out 默认 `06_工程与验证层/out/result.csv`（相对包根或
  当前目录均可，但**默认路径必须落在 E 盘本包内**）。
- 控制台打印：进度、总耗时、每局平均耗时、NotImplemented 总数（必须 0）。
- 参数解析用手写即可，禁止引命令行第三方包。

### 4.5 CSV 格式

- 表头英文列名（如 `game_index,seed,winner_faction,game_over_reason,months_survived,...`），
  一��一行，UTF-8 **带 BOM**（`new UTF8Encoding(true)`，否则 Excel 打开中文乱码）；
  文本字段含逗号/引号要做标准转义。
- `game_over_reason` 用稳定标识符（枚举名），不要塞中文长句。

## 5. 确定性红线（破了等于整包作废）

| 检查项 | 要求 |
|---|---|
| 确定性 | 同 seed 跑两局，终局快照逐字段相等（测试断言） |
| 回放 | 不接 planner 的重放与原模拟终局逐字段相等 |
| 存档 | 在第 K 月存档→读档继续，与一口气跑到底的同刻状态逐字段相等 |
| 并行无害 | 串行 64 局与并行 64 局产出的 CSV 内容完全一致 |

常见破坏源（写代码时主动避开）：`DateTime.Now`/`Guid`/`Random.Shared`、Dictionary 直接遍历、
并行共享随机源、用引用类型集合时互相污染。发现**上游**（03/04）有不确定来源，
只记录上报，不改上游代码。
