# 提示词 · 06 第 6 轮 · 平衡调研（只出数据，不改数值）

> 工作模式：本包独立对话，第一句「读 提示词_第6轮_平衡调研.md，照它做」。

## 一、任务目标

跑**无头批量模拟**，产出当前版本（v1.9）的平衡数据报告，供 00 决定下一步是否调数值。

**核心纪律**：本轮**只出数据、不改任何数值**。数值表归 02 包，改动走 00 裁决流程。
你跑完模拟、把指标对照 `docs/平衡性调优指南.md` 的参考区间分析一遍、写出疑似成因即可，**不要改 `BalanceConfig` / `config.json` / 任何 .cs 数值**。

## 二、背景（为什么做这个）

00 观察到：千局模拟里「赤壤吞并苍岭、被动玩家缩到 1 城」，压力偏大。
在动数值之前，先拿一份**当前真实数据**作为基线，避免凭感觉调。

## 三、怎么跑（命令照抄）

在 `06_工程与验证层` 目录下执行：

```bash
dotnet run --project src/StrategyGame.Tools -c Release -- simulate --games 1000 --seed 12345 --months 120 --out out/result_round6.csv
```

说明：
- `--games 1000`：跑 1000 局（默认值，足够统计）。
- `--seed 12345`：基准种子，第 i 局种子 = 12345 + i（可复现）。
- `--months 120`：月数上限（默认值）。
- `--out out/result_round6.csv`：CSV 输出到 `06_工程与验证层/out/result_round6.csv`。
- 报告自动生成：`out/平衡分析_result_round6.md`（与 CSV 同目录）。
- 默认并行，跑完会在控制台打印关键指标。

**如果 1000 局跑太久**（超过 10 分钟），可以降到 `--games 500`，但要在汇报里注明「因耗时降为 500 局」。

## 四、读完报告后要做的事

打开 `out/平衡分析_result_round6.md`，对照 `docs/平衡性调优指南.md` 第 2 节的指标表，
逐条判断每个指标是否在参考区间内。**重点关注**：

1. **基准槽位胜率**（三方 AI 混战口径，非真实玩家）：参考 25%–45%。
2. **平均存活/终局月数**：参考 ≥ 60。
3. **10 回合内终局比例**：参考接近 0。
4. **僵持率（120 月未决）**：参考 20%–40%。
5. **攻陷次数 / Dispatch 尝试次数**：参考 30%–50%。
6. **各类拒绝码占比**：全数列出，异常偏高的点名。
7. **NotImplemented 总数**：**必须为 0**，否则链路有 bug（这个会让命令返回非 0，注意）。
8. **各势力终局城池数分布**：赤壤是否显著多于苍岭/薪火。

## 五、汇报要求（写 `汇报_第6轮_平衡调研.md`）

汇报必须包含：

1. **执行命令与参数**（实际跑的那条）。
2. **跑了多少局、耗时多久、是否有 NotImplemented**。
3. **指标对照表**：每个指标一行，列「实际值 / 参考区间 / 是否偏离 / 疑似成因（具体到函数名或常量名）」。
4. **赤壤 vs 苍岭 vs 薪火 的终局城池数均值与分布**——这是本轮重点，00 要据此判断是否需要调赤壤的扩张能力。
5. **疑似成因清单**：只写「疑似」，不写「建议把 X 调成 Y」。数值调整是 00 的裁决，不是你的判断。
6. **产物路径**：CSV 和报告的完整路径。
