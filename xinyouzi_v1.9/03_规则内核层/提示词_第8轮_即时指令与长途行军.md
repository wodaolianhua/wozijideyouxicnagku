# 提示词 · 第 8 轮（03 规则内核层）：即时指令链路 + 长途行军

> 你是 03 包执行 AI。本文件由 00 大脑维护，你只读不写。做完按文末要求交汇报。
> 本机只装 .NET 10 运行时，各测试工程已带 RollForward，直接 `dotnet test -c Release` 即可。

## 一、背景（为什么做这轮）

游戏原设计是「月回合制」：玩家指令进 PendingOrders 延迟队列，等 `/api/tick` 触发
`TurnPipeline.RunMonth`（11 步流水线）在月尾统一结算。用户（项目负责人）实测后明确否决
这种手感，要求两件事：

1. **点了立刻有结果**：任何指令点击即结算、数字即变、前端即刻有反馈，不许「等下个月」。
2. **全图城池都能打**：取消「只能打相邻城」的硬拒绝，改为按路径距离决定行军时间与补给消耗。

00 已确认两条关键事实，降低本轮风险：

- 后端**已存在即时执行通路**：`StrategyGame.Sim/SimulationHost.ExecuteImmediately(Order)`
  （SimulationHost.cs:286），内部就是 `CommandProcessor.ProcessAndApply(State, order)`，
  走完整的「校验 → StateDelta → StateApplier 写回」链路。目前仅 `AppointDepartment`
  （部门任命）走这条通路（WebHost/Program.cs:166-179 是现成范例）。本轮是把它扩展到
  全部玩家指令，**不是新造旁路**。
- 相邻拒绝在 `Resolvers/DispatchResolver.cs` 的 Validate 阶段，错误码
  `RejectedNotAdjacent`。04 的 AI 规划器目前也依赖相邻规则，**本轮不动 AI**，
  相邻规则对 AI 保持有效，只放开玩家的长途行军。

### 设计裁决（00 已与用户确认方向，执行 AI 不得改口径）

- **月份保留为引擎内部时钟单位，不做连续时间重写**。经济/建筑/AI/战斗全部挂在月 tick 上，
  06 模拟器是 RunMonth×N，第 6/7 轮平衡数据依赖它；删月份等于重写 9 个 System + 模拟器 +
  全部测试并作废平衡成果，收益为零（玩家体感由「即时指令 + 前端时间自动流动」达成，
  05A 已实现自动 tick，默认约 7 秒一个游戏月）。
- 玩家侧从此**不再使用延迟队列**；AI 侧照旧在月 tick 由规划器入队。两条链路并存。

## 二、任务范围（只做这两件事）

### 任务 A：玩家指令即时结算

1. 在 SimulationHost 增加面向全部玩家指令的即时入口（可复用/扩展现有
   `ExecuteImmediately`，必要时重命名为更通用的名字并同步 WebHost 调用点）。
2. 逐个审计玩家可用 ActionType 的 Resolver，确认即时执行安全性：
   - **瞬时型**（Recruit 征兵、Develop 屯田、Fortify 修城、RecruitOfficer 招贤、
     AppointDepartment 任命等）：点击即出 ResolveResult，数字立即写回。
   - **持续型**（Build 建筑、Dispatch 出兵）：立即「开工/开拔」，持续时间从**当前
     游戏年月**起算，而不是 NextMonth。Build 的 `UpgradeMonthsRemaining` 机制保留，
     只是入口从队列改为即时。
   - 重点排查：是否有 Resolver 隐式依赖「月尾上下文」（读 PendingOrders 同批指令、
     假设本月产出已刷新等）。发现依赖就在该 Resolver 内注释说明并处理，不许绕过
     Delta/Applier 铁律直接改状态。
3. WebHost 的 `/api/order`（Program.cs:141-187）：玩家指令统一改走即时入口，
   返回体沿用 AppointDepartment 即时分支的形状（code/message/deltas/state/meta），
   保留 `lock (sessionLock)`。延迟队列分支仅保留给后续 AI 通路。
4. 前端（05A）**本轮不动**，它现在按 `queued:true` 写的乐观 UI 第 10 轮再接线；
   但返回体字段要让前端第 10 轮能平滑切换，不允许删字段，只允许新增。

### 任务 B：长途行军（取消相邻硬拒绝）

1. **DispatchResolver.Validate 删除 `RejectedNotAdjacent` 对玩家指令的拒绝**
   （AI 指令的相邻约束保留：用 order 来源/调用通路区分，不要用脏标记字段）。
2. 在 Core 内新增路径服务（建议 `Pathfinding/MapPathfinder.cs`）：基于
   cities.json 的相邻关系图做 BFS 最短路径，输出「途经城 Id 列表 + 跳数」。
   无路径（理论上全图连通，也要防御）返回明确错误码，新增错误码在 Contracts 定义。
3. 行军模型：
   - 给 Army（Contracts DTO + Core 状态 + DeltaField 常量，Types.cs 现有
     `ArmyPositionCityId`/`ArmyTargetCityId` 范式照抄）新增行军字段：
     行军目标城、到达年/月、路径快照（JSON 或 Id 列表，选可存档的方案）。
   - 行军时间首版 = 跳数 × 每跳月数（每跳月数默认 1，**参数必须进 02 的
     config.json/BalanceConfig，不许硬编码**，铁律 5；暂进不去就放
     PlaceholderNumbers.cs 标 TODO(设计)）。
   - 补给/粮草消耗随距离递增（首版公式：基础消耗 × 跳数，系数同样进 config），
     下单时校验粮草，不足走现有 RejectedNoResources 口径。
   - 军团在 TurnPipeline 月 tick 中推进：每月检查到达年月，到达即触发**现有的
     攻城结算代码**（DispatchResolver 里既有的交战/攻陷/弹回分支，重构为可被
     「到达事件」复用，不许复制一份战斗逻辑）。
   - 行军中军团不可再下 Dispatch（校验拦截并给明确错误码）。
   - **途中拦截首版不做**，但在路径服务与行军字段处留注释标明扩展点。
4. 存档兼容：新字段必须能序列化/反序列化；旧存档缺字段时按「不在行军中」默认值
   处理，WebHost 的 /api/load 不许崩。

## 三、硬性约束（六条铁律 + 本轮附加）

1. 只有 StateApplier 能改状态，Resolver/System 只产 StateDelta。
2. 禁用 Random.Shared / DateTime.Now / Guid.NewGuid，随机走注入的 IRandom。
3. 比例一律万分比整数，除法向下取整。
4. 改了 Contracts 必须跑 `分发契约.sh`，并确认各消费方编译通过。
5. 数值进 BalanceConfig / 02 config.json；进不去的放 PlaceholderNumbers.cs。
6. 改公式/改规则必同步改测试期望值并在测试注释注明【第8轮】原因。
7. **不许碰**：SampleData.cs、02 的 JSON 数据（新参数需要加 config 键时，先在
   PlaceholderNumbers 落地并在汇报里列出「待 02 补的键清单」，由 00 另派 02 轮次）、
   04 智能体层、05A 表现层、06 的模拟器逻辑。
8. 测试数量只增不减：03 现有 241 项，受影响用例改写、新增即时指令与长途行军
   （多跳路径、粮草不足、到达攻城、行军中再下令、存档往返）用例，跑完全绿。
9. 不许引入新 NuGet 依赖；BFS 自己写。
