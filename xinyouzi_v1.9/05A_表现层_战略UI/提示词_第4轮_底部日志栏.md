# 提示词 · 05A 第 4 轮 · 底部日志栏

> 工作模式：本包独立对话，第一句「读 提示词_第4轮_底部日志栏.md，照它做」。

## 一、任务目标

把「指令结果」从一闪而过的 toast，升级成**底部常驻滚动日志栏**。

现状：现在 `Hud.toast()` 是短暂浮层（`Ui/Hud.ts` L439，最多 4 条、4.2 秒自动消失）。
玩家下完指令、推进回合后，结果提示一晃就没了，想回头看「刚才发生了什么」没有地方查。

目标：在屏幕底部加一个**常驻、可滚动、按时间倒序或正序**的日志栏，把每一条
「指令结果 / 结算摘要 / 错误提示 / 关键事件」都记下来，玩家随时能往上翻。

## 二、数据现状（不用改 Contracts / 后端）

- 指令结果已经由 `main.ts` 里的 `OrderSender` 回调 + `Hud.toast()` 承载，信息是现成的。
- 结算结果在 `doTick()`（`main.ts` L201）里，`tick.results` 是一个数组，每条有结果文本。
- 日志只需要**前端自己累积**，不需要后端加字段、不加端点。

执行第一步：先 `grep -n "toast\|tick.results\|showSettlement" client/src/Ui/Hud.ts client/src/main.ts`
确认现有信息从哪来，别臆造字段。

## 三、现有代码入口（先读懂再动手）

- `client/src/Ui/Layout.ts`：`buildLayout()` 是 HUD 的 DOM 骨架，`HudLayout` 接口定义所有元素。
  底部日志栏的容器节点加在这里（例如 `log`），并 append 进 root。
- `client/src/Ui/Hud.ts` L439 `toast()`：现有短暂浮层。**保留 toast 不动**（它适合即时反馈），
  新增一个 `log(entry)` 方法往日志栏追加；或让 `toast()` 内部同时写日志。
- `client/src/main.ts` L34 `OrderSender` 的 `notify` 回调、L201 `doTick()` 的结算分支：
  这是日志要接的两处信息源。
- `client/src/Ui/Theme.ts`：样式/颜色变量，日志栏配色从这对齐，别硬编码一堆新颜色。

**建议落点**（执行 AI 可调整，范围只限 05A 前端）：
1. `Layout.ts` 加一个底部日志容器 `log`（+ 可选「清空」「收起」按钮）。
2. `Hud.ts` 加 `log(entry)` 方法：追加一条日志，带时间戳（`年/月` 或实际时钟，见疑问条）、
   级别（info / ok / error，复用现有 toast 的三档配色）、自动滚动到底、设条数上限（防无限增长）。
3. `main.ts` 把 `notify` 回调、`doTick` 的结算结果（`tick.results` 逐条）喂进日志。
4. 底部日志栏常驻，不遮挡顶栏/侧栏；可以默认收起成一条小条、点开展开（桌面基准 ≥1280×720）。

## 四、范围与铁律

  - 不引入「关卡 / 局」概念、不做「亲征 / 第一人称」；

## 五、验收标准

1. `cd 05A_表现层_战略UI/client && npm install`（若 node_modules 缺失）后
   `npm run build` 与 `npx tsc --noEmit` **0 错误**。
2. `npm run dev`（:5173）或起后端 `dotnet run`（:5178）能正常加载。
3. 功能验证（无头浏览器或手测均可，但**不要要求用户手动测试**）：
   - 下一条指令（如征兵/兴建）→ 日志栏出现对应结果条目；
   - 推进下月 → 结算结果（`tick.results`）逐条写进日志，可上翻查看；
   - 错误场景（如银两不足下令）→ 日志里也有 error 级条目；
   - 日志栏默认不遮挡主界面，可收起/展开；旧 toast 仍正常。
4. 416 项后端测试不动、不变红（本任务不碰后端）。
