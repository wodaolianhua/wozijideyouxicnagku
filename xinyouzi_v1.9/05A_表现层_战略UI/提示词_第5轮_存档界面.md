## 一、任务目标

存档接口后端**已经全部就绪**（零后端改动需求），但前端**没有任何入口**：
玩家现在不能手动存 / 读 / 删档。本轮把「存档界面」补上，让玩家能：

1. **存一个档**（起名，不填名就用「存档X年Y月」默认名）；
2. **看到所有档的列表**（名称 / 游戏年月 / 城数 / 大小 / 保存时间，倒序）；
3. **读一个档**（载入后立刻恢复那局，无需刷新页面）；
4. **删一个档**（有二次确认）。

**只做前端，后端一行都不许动**——接口已经完备（见下）。

## 二、存档接口现状（已就绪，照着调即可，勿臆造）

> 后端在 `server/StrategyGame.WebHost/Program.cs`，以下端点均已实现并可用。

| 方法 | 路径 | 请求体 | 返回 |
|---|---|---|---|
| POST | `/api/save` | `{ name?: string }` | `{ id, name, file, size, year, month, cities }` |
| GET | `/api/saves` | — | `{ saves: [{ id, name, year, month, cities, size, savedAt }], total }`（按保存时间倒序） |
| POST | `/api/load` | `{ id: string }` | `{ loaded, id, name, state, meta }` |
| DELETE | `/api/saves/{id}` | — | `{ deleted, id }` |

要点：
- `id` 形如 `20261114-095430-存档名`（`yyyyMMdd-HHmmss-` 前缀 + slug），列表返回的 `id` 直接回传给 load / delete。
- 读档返回的 `state` / `meta` 结构与 `POST /api/new-game`、`POST /api/tick` 的 `state` / `meta` 完全同构，
  可以**直接用现成的 `store.applySnapshot(state, meta)`** 接住，然后照 `newGame` 那样 `buildWorld()` 重建场景。
- 删除有 `IsSafeSaveId` 校验，传列表里拿到的 `id` 即可。

   - 点「存档」→ 弹浮层，输入名字保存 → 列表里出现这条（名字 / 年月 / 城数 / 大小 / 时间正确）；
   - 不填名字保存 → 默认名「存档X年Y月」；

   - 删除一个档 → 二次确认后从列表消失，后端 `GET /api/saves` 也不再返回它；
   - 存档浮层不遮挡/破坏主界面，关闭浮层后游戏照常可玩。
