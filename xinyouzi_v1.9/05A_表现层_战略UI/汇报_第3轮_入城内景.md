## 4. 疑问条（所有偏离与决定，逐条写清原因）

1. **改了 `Scene/WorldScene.ts`**（提示词 §4 的「只动」清单里只点了 `Ui/Hud.ts` / `Core/GameStateStore.ts` / `main.ts`）。
   *原因*：提示词 §4 的铁律是「只动 `05A_表现层_战略UI/client/src/` 下的前端文件」，WorldScene 就在这个目录下。
   为了让「进城盖住疆域图」干净利落，加了 `setVisible()`：进城时疆域图 `display:none` 并停掉 RAF，
   否则底下那张图会 60fps 空转、事件也会穿透。**只加显隐开关，没碰任何绘制与交互逻辑。**

2. **返回按钮做在城内画布右上角 + Esc，没有加顶栏按钮**（提示词允许落点自定）。
   *原因*：顶栏已经是「日期 + 势力 chips + 5 个按钮」的单行布局，再塞一个会挤爆 1280px 桌面基准。
   画布右上角画一个金色描边的「← 返回疆域图」更显眼，也不用动 `Layout.ts`。

3. **进城后城池侧栏保持开着，城内画布自动向右避让面板宽度（实测避让 410px）**。
   *原因*：侧栏里能继续下令，玩家在城内也能经营，不必来回切。
   避让量按面板**实际 DOM 宽度**算（`CityInterior.sideInset()`），面板收起时画布自动回到全宽。

4. **只有「自己的城」有进入城内的入口**，非己方城的侧栏仍是只读（按提示词「点自己的城」）。
   *原因*：不擅自扩大可见范围；敌方城的建筑等级属于情报，未获授权不展示。

5. **工期进度用「分段格」而不是连续进度条**。
   *原因*：后端工期是整数月（`PlaceholderNumbers`：农田 1 / 兵营 1 / 城墙 2 / 市集 1），
   1 个月的工程完成度只可能是 0% 或 100%，连续进度条会给出虚假精度。
   分段格按「已过月数 / 总月数」画：城墙 2 格，剩 1 月时亮 1 格。口径与侧栏的「还需 N 个月完工」一致。

6. **「在建」的判定用 `upgradingBuilding >= 0 && upgradeMonthsRemaining > 0`**。
   *原因*：后端 `BuildResolver` 只在**结算时**才写 `upgradingBuilding`（下令只是入队），
   所以「刚点下兴建」的一瞬间城内还不会显示在建，要等下月结算。这与侧栏口径一致，没有另造一套语义。

7. **城墙画成环城一圈，而不是四格之一**；城墙等级 0 画木栅而不是墙。
   *原因*：四类建筑里城墙天然是围城的一圈；等级 0-5，0 级没有墙，木栅一眼能看出「还没修墙」。

8. **城墙的在建提示画在城墙铭牌上**（「城墙 Lv2 · 在建」+ 吊车 +「升 3 级 · 剩 2 月」+ 整圈流动金虚线）。
   *原因*：城墙没有独立分区，塞进四格布局会破坏「环城」的读感。

9. **城楼是装饰，不是第五种建筑**（不参与等级，也不显示等级格）。
   *原因*：契约里只有农田/兵营/城墙/市集四类。城楼大小随**四类等级之和**变化，
   用来一眼看出「这座城整体长到什么体量」，不伪造新数据。

10. **部署产物同步进 `server/.../wwwroot/` 并删掉旧 bundle**。
    *原因*：沿用 R2 的既有惯例（见 `汇报_第2轮_桌面化.md` §文件清单），这样单端口 5178 就能直接验。
    只动 `wwwroot/` 下的构建产物，**后端源码没动**。

11. **依赖安装与缓存全部指到 E 盘**（`npm --cache E:/npm-cache`、`DOTNET_CLI_HOME`/`TMPDIR` 指到 E 盘、
    `NUGET_PACKAGES` 沿用用户已有的 `E:\新建文件夹 (5)\dotnet-cache\.nuget\packages`）。
    *原因*：遵守「禁止向 C 盘写入」。本轮**未向 C 盘写入任何东西**（Chromium 的 user-data-dir 也在 E 盘）。

12. **没有新增任何项目内文件，除了 `CityInterior.ts` 和本汇报**；验证脚本、截图、日志全在缓存区。
    *原因*：不污染仓库，与 R2 的「缓存区放临时脚本与验收证据」做法一致。
