──────────────────────────────────────────────
一、这是个什么东西
──────────────────────────────────────────────

一个中国古代架空背景的策略游戏。不是三国，是架空的"先秦"味道：
七座城、三个势力（薪火 / 赤壤 / 苍岭），玩家执掌薪火，开局最弱（两座城）。

核心玩法：
  · 一张连续地图，视角能从一城看到整个天下
  · 玩家有一片疆域，用势力颜色标出，可点击
  · 五个部门（军事 / 内政 / 经济 / 科技 / 外交），要"用人"
    —— 任命谁当部门主官，直接决定这个部门的产出效率
  · 有资源数值；点"招贤"从在野人才里抽人；人才改名只能改一次
  · 点敌城可以出兵攻打，有上帝视角的"小人打架"演出
  · 进自己的城能看到建筑一格格长起来

三条硬性方向，接手的人不要改回去：
  1. 不要"局"的概念。开放沙盒，可以一直种田，也可以一直打仗，
     只有所有城都丢了才算输。
  2. 不要"亲征"（第一人称带队）。那是早期 3D 方案留下的东西。
  3. 不要 3D 地图。用户明确讨厌，要 2D 平面疆域图。

历史包袱提醒：
  这个项目方向漂移过三次（大战略回合制 → 3D 大地图 → 三国卡牌闯关）。
  01_设计规格层/ 和 00_项目管理/ 里有些文档是那三个旧方向留下的，
  看到"魏蜀吴""卡牌""3D"之类的描述，一律当历史资料，不要照着做。
  当前唯一准绳是这份文档 + 代码本身。

二、代码在哪（先看这段，别搞错）
──────────────────────────────────────────────

全部代码就在这个包的 xinyouzi/ 目录里（8 个包 + StrategyGame.Contracts + 分发契约.sh），无需从任何仓库拉取、也无需解压。

──────────────────────────────────────────────
三、五分钟跑起来
──────────────────────────────────────────────

需要：.NET 8 SDK、Node 20 以上。

1) 跑测试，确认你拿到的是好的

   cd xinyouzi/02_内容数据层/tests/StrategyGame.Data.Tests && dotnet test -c Release
   cd xinyouzi/03_规则内核层/tests                          && dotnet test -c Release
   cd xinyouzi/04_智能体层/tests/StrategyGame.AI.Tests       && dotnet test -c Release
   cd xinyouzi/06_工程与验证层/tests/StrategyGame.Sim.Tests  && dotnet test -c Release

   期望：110 / 241 / 30 / 35，合计 416，全绿。
   有一个红的就说明环境或包不对，别往下走。

2) 起后端

   cd xinyouzi/05A_表现层_战略UI/server/StrategyGame.WebHost
   ASPNETCORE_URLS=http://127.0.0.1:5178 dotnet run -c Release

3) 起前端

   cd xinyouzi/05A_表现层_战略UI/client
   npm install
   npm run dev
   浏览器开 http://127.0.0.1:5173

   也可以不起前端：后端 wwwroot 里放的是上次构建好的静态文件，
   直接开 http://127.0.0.1:5178 就能玩。改完前端要重新构建并拷贝：

   npx vite build && rm -rf ../server/StrategyGame.WebHost/wwwroot/* \
     && cp -r dist/* ../server/StrategyGame.WebHost/wwwroot/

4) 无头截图（服务器上验证画面用，没有显示器也能出图）

   xvfb-run -a --server-args="-screen 0 1600x1000x24" \
     chromium --headless=new --no-sandbox --disable-gpu-sandbox \
     --use-gl=swiftshader --enable-unsafe-swiftshader \
     --window-size=1600,1000 --virtual-time-budget=25000 \
     --screenshot=/tmp/shot.png "http://127.0.0.1:5178/"

   注意必须带 --use-gl=swiftshader，否则 WebGL 起不来，截图是全黑的。

四、八个目录各管什么
──────────────────────────────────────────────

xinyouzi/
├─ StrategyGame.Contracts/        唯一契约：枚举、模型、接口
├─ 01_设计规格层/                  旧方向文档，当历史资料
├─ 02_内容数据层/                  JSON 数据 + 校验 + 装配成 WorldState
├─ 03_规则内核层/                  纯规则：回合流水线、解析器、系统
├─ 04_智能体层/                    AI 决策
├─ 05A_表现层_战略UI/              网页前端 + ASP.NET Core 后端
├─ 05B_表现层_实时战斗/            只有 README，没有实现（未做）
└─ 06_工程与验证层/                模拟器 + 命令行工具 + 集成测试

逐层说明：

【Contracts】所有包共用一份。改这里等于改天下，改完必须跑
  bash 分发契约.sh  （在 xinyouzi/ 目录下执行）
  它会把三个文件拷到各包的 接口契约_共享类型/ 里。
  不跑这一步，各包各自引用旧副本，会出现"同一类型两个程序集"的诡异报错。

【02 内容数据层】
  assets/data/cities.json     7 座城
  assets/data/factions.json   3 个势力与开局资源
  assets/data/officers.json   18 名人才（13 名在编 + 5 名在野可招）
  assets/data/config.json     全部数值（BalanceConfig）
  src/Config/ConfigValidator.cs   数据校验，附错误码
  src/Assembly/WorldAssembler.cs  把 JSON 装配成 WorldState，
                                  并把势力兵源池摊到各城驻军
  改数据只需要动 JSON，不要动代码。改完跑 02 的测试。

【03 规则内核层】最重要的一层，也是改动最容易出事的一层。
  WorldState.cs        世界状态（唯一可变对象）
  TurnPipeline.cs      回合流水线，11 步，顺序不能乱
  Resolver*.cs         指令解析器，每个指令一个
  Systems/*.cs         每月的系统性结算（经济/士气/建筑/战斗/胜负…）
  StateApplier.cs      全项目唯一能改状态的地方
  PlaceholderNumbers.cs  还没搬进配置的数值，都标了 TODO(设计)

【04 智能体层】
  AiFactionPlanner.cs  敌方势力每月决策：征兵 / 屯田 / 修城 / 合兵 / 攻城

【05A 战略 UI】
  client/   TypeScript + three.js（即将换成 2D），Vite 构建
  server/   ASP.NET Core 8，端口 5178，托管静态文件 + 提供 API

  现有接口：
    POST /api/new-game              开新局 {seed}
    GET  /api/state                 当前完整状态
    GET  /api/preview-income/{id}   预览某势力本月产出（含部门效率）
    POST /api/order                 下指令（AppointDepartment 立即生效）
    POST /api/rename-officer        人才改名（一人一次）
    POST /api/tick                  推进一个月，返回结算明细

【06 工程与验证层】
  src/StrategyGame.Sim/     无头模拟器，可批量跑局、可导出 CSV
  src/StrategyGame.Tools/   命令行入口：simulate / analyze / replay
  tests/                    集成测试

  存档能力已经在这里了，别重复造：
    SaveSystem.cs       SaveFile 结构 + JSON 序列化 + 校验 + 读写文件
    SimulationHost.BuildSave()          导出当前局
    SimulationHost.Restore(save)        从存档恢复
  存档里带了随机源状态，所以读档后继续跑，结果和不存档完全一致。

──────────────────────────────────────────────
六、六条铁律（不遵守一定写坏）
──────────────────────────────────────────────

1. 只有 StateApplier 能改状态。
   解析器和系统只能产出 StateDelta 列表，不能直接改字段。
   所有 delta 最终由 StateApplier 统一应用，这是回放和测试的基础。

2. 禁止 Random.Shared、DateTime.Now、Guid.NewGuid。
   随机一律用注入的 IRandom（xorshift32，可存取状态）。
   时间一律用 WorldState 里的 Year / Month。
   破坏确定性 = 存档一致性测试、千局模拟全部作废。

3. 比例一律用万分比整数。10000 = 100%。
   不要出现 0.15 这种浮点比例。除法一律向下取整，全项目统一。

4. 契约只有一份。改 Contracts 之后必须跑 分发契约.sh。
   否则会出现类型重复定义的编译错误。

5. 数值不要散落在代码里。
   能进 BalanceConfig 的进配置，暂时进不去的放 PlaceholderNumbers.cs
   并标 TODO(设计)。接手的人要能一眼看出哪些数是拍脑袋的。

6. 改了公式，必须同步改测试期望值，并在测试里注明为什么改。
   现有 416 项测试是验收标准，不是障碍。红了的测试要么是 bug，
   要么是设计变了——两种都必须说清楚，不能直接删。

七、已经踩过的坑（别再踩）
──────────────────────────────────────────────

1. AI 出兵坐标错位
   原来先全局找"第一个相邻敌城"，再拿最强部队所在地当出发城，
   两者常不在同一处。千局 182 条指令有 114 条被"不相邻"驳回，
   看着天天出兵，实际一场没打。
   现在：以部队所在地为锚点，找它够得着的敌城。

2. 兵源刻度错十倍
   soldierPerPopPerMonth 配了 5000（=人口 50%/月），
   注释里写的却是 90/月。结果兵力膨胀到几十万，永远打不穿。
   现在 500，两处同步。

3. 稳定度是单向倒计时
   只衰减不回升，第 45 个月全势力兵源归零，世界直接死。
   现在：低于基准 60 每月回弹 +2；失城另扣 -8 稳定 / -5 民心。

4. 部队打光后永久无兵
   补给逻辑把 Soldiers == 0 当"已覆灭"排除，
   于是池里明明有兵却没人能领，池永久卡满。
   现在：每城一个补给口，残部可重整。

5. 农田无上限
   基建每月 +1 级没有封顶，第 60 个月粮产 577 万。
   现在封顶 5 级。

6. 士气腐化死锁
   无战每月 -6，休整只回 +3，士气必然归零，AI 只会休整不打仗。
   现在：腐化到 40 就停，AI 阈值同步下调。

7. 合兵被"残部重整"抵消
   并进来的部队清零后又被当成新部队领兵，两个番号来回倒。
   现在：每城只有一个补给口，优先给已有兵的部队。

8. 城防上限过高
   城防超过 1200 会触发"攻方必被击退"，城变成永不可破。
   现在上限 800-1000。

9. 类型重复：02 层曾自带一份 Contracts
   导致两个同名程序集。现在 02 的引用已指向根目录那一份。

九、接手流程建议
──────────────────────────────────────────────

第 1 天：
  · 解压基线包，跑完 416 项测试，确认全绿
  · 起后端 + 前端，完整玩一局：任命五部门 → 征兵 → 出兵 → 打下城
  · 读 03 的 TurnPipeline.cs，把 11 步顺序搞清楚

第 2 天起，按第八节挑一个任务，只动该任务范围内的文件。
每个任务书末尾都写了"不要动什么"，那条比"要做什么"更重要。

提交方式：
  · 一个任务一个 zip，或 git format-patch 补丁
  · 附一句"改了哪些文件、测试跑了几项、有没有已知问题"

十、命令速查
──────────────────────────────────────────────

跑全部测试（四条命令，各自目录下执行）
  dotnet test -c Release

  cd 06_工程与验证层/src/StrategyGame.Tools
  dotnet run -c Release -- simulate --seed 7 --months 60

  dotnet run -c Release -- analyze --games 1000 --months 120 --out ../out

回放某一局
  dotnet run -c Release -- replay --seed 7

起后端
  cd 05A_表现层_战略UI/server/StrategyGame.WebHost
  ASPNETCORE_URLS=http://127.0.0.1:5178 dotnet run -c Release

前端类型检查 + 构建
  cd 05A_表现层_战略UI/client
  npx tsc --noEmit && npx vite build

  curl -X POST http://127.0.0.1:5178/api/new-game \
    -H 'Content-Type: application/json' -d '{"seed":12345}'

推进一个月
  curl -X POST http://127.0.0.1:5178/api/tick

    -H 'Content-Type: application/json' \
    -d '{"action":"AppointDepartment","targetId":1,"secondaryTargetId":2}'
