## 一、背景（为什么做这轮）

第 8 轮 03 实现了长途行军，两个行军参数因 BalanceConfig 暂无对应字段，临时落在
`03_规则内核层/StrategyGame.Core/src/PlaceholderNumbers.cs`（196-226 行「长途行军」段），
均带 TODO(设计) 与「待 02 补的键清单」：

| 占位常量（03 现状） | 当前值 | 语义 |
| --- | --- | --- |
| `MarchMonthsPerHop` | 1 | 每跳行军月数（绝对月数，非比率） |
| `MarchGrainPerSoldierPerHopPerMille` | 200 | 每兵每跳粮草消耗，万分比（200 = 0.02 粮/兵/跳） |

本轮把它们正式收进契约 `BalanceConfig` 与 `config.json`。**数值必须与占位值完全一致
（1 和 200），保证 B 阶段接线后游戏行为零变化**——本轮是「搬家」不是「调参」。

### 已确认的链路事实（00 已摸底，省得你重查）

- `config.json` 是唯一不使用信封结构的文件，由 `JsonConfigLoader.LoadBalance()`
  （JsonConfigLoader.cs:170-171）**直接反序列化为契约 `BalanceConfig`**，JSON 键名按
  camelCase 自动映射属性名，没有独立 DTO。所以加键 = 契约加属性 + JSON 加同名 camelCase 键。
- 契约 `BalanceConfig` 定义在根目录 `StrategyGame.Contracts/Interfaces.cs:158-289`
  （注意不在 Models.cs）。
- 校验入口：`ConfigValidator.ValidateBalance`（ConfigValidator.cs:180 起），
  比率类用现成 helper `CheckRatio(...)`，非负用 `CheckNonNegative(...)`，
  范围事故可参考同文件 259-267 行 fieldBattleLossFactor 的写法。
- 02 测试基线：**110 个测试方法**（ConfigValidatorTests 41、DataContractTests 21、

## 二、任务范围（只做这四件事）

### 1. 契约 BalanceConfig 新增两个属性

文件：`StrategyGame.Contracts/Interfaces.cs`，在 `SiegeDefeatRoutRate`（288 行）之后、
类结束括号之前新增，XML 注释写清语义与基准：

- `int MarchMonthsPerHop { get; set; }` —— 每跳行军月数（绝对月数）。基准 1：
  一条相邻边走一个月。
- `int MarchGrainPerSoldierPerHopPerMille { get; set; }` —— 长途行军每兵每跳粮草
  消耗（万分比）。基准 200，与 `ArmyMonthlyGrainPerSoldier` 对齐。

### 2. config.json 新增两个键

文件：`02_内容数据层/assets/data/config.json`，放在 `armyMonthlyGrainPerSoldier`
（69-70 行）附近成组，沿用现有「数值键 + `_c_` 说明键」体例：

- `"marchMonthsPerHop": 1`
- `"marchGrainPerSoldierPerHopPerMille": 200`

注意：PlaceholderNumbers 注释里写的 `march.monthsPerHop` 点号名是概念名，
**实际 JSON 键必须是平铺 camelCase**（本文件无任何点号键先例，嵌套只存在于
specialtyBonus/extendedBalance）。`_c_` 说明里要写清万分比口径与「仅长途行军
（跳数 ≥ 2）收取、相邻出兵不收」的第 8 轮口径。

### 3. ConfigValidator 增加两条校验

在 `ValidateBalance` 内、现有 CheckRatio 组（268-273 行一带）追加：

- `marchMonthsPerHop`：必须 ≥ 1。为 0 会让所有行军永远到不了，属配置事故，
  按 ZeroValue/ValueOutOfRange 口径报错，错误信息指名道姓。
- `marchGrainPerSoldierPerHopPerMille`：走 `CheckRatio`（合法区间 0-10000 万分比）。
  允许 0（表示行军不耗粮的合法配置），下限由 CheckRatio 现状决定，不要自创更严规则。

### 4. 测试与 fixture 维护

- ConfigValidatorTests 新增用例：两键合法值通过；`marchMonthsPerHop=0` 报错；
  耗粮系数越界（>10000 或负数）报错。测试方法注释标【第9轮A】。
- **重点坑（必查）**：`tests/StrategyGame.Data.Tests/bin/.../fixtures/` 有源 fixture
  目录（bad_adj_missing、bad_player_not_adjacent 等十余个，源文件在测试工程的
  fixtures 目录下，先在 tests 工程里定位源目录而不是改 bin 副本）。每个 fixture 都有
  自己的 config.json，反序列化后新属性缺省为 0，会触发你新加的
  `marchMonthsPerHop ≥ 1` 校验，可能让原本断言「只报某一个错」的 fixture 用例多出
  错误而失败。逐个 fixture 评估：**给每个 fixture 的 config.json 补上两个合法新键**
  （1 和 200），让它们原本的失败原因保持唯一；若某 fixture 的本意就是测 balance
  缺字段/非法值，则按该用例断言意图单独处理并在汇报里说明。
- DataContractTests 若存在 BalanceConfig 字段覆盖度/字段计数类断言，同步登记新字段。
- JsonRoundTripTests 若自动覆盖则无需改，跑绿即可，不许为凑绿删断言。
- 测试数量只增不减，跑完贴总数（应 ≥110）。
