## 三、玩法说明

### 地图能看什么、能点什么

- **悬停**：鼠标停在地图任意地标上，底部出现一句人话（"字迹磨平了，但还在"），不是属性数值。50+ 种地标各配 1~2 句。
- **切插画**：顶栏「地图 / 插画」标签切到抉择配图。插画有景深（越近的块越大）和前景人物剪影。
- **看状态**：「状态」按钮开属性雷达图 + 跨抉择趋势曲线。点雷达图的任一维度可单看它的走势。
- **看科技**：「科技树」按钮开 60 节点树。节点点亮与否由科技轨实际值决定，点节点看门槛与效果。
- **看自己**：「档案」按钮开「我是谁」——用 3 句话生成你这个文明的自我描述。

### 抉择怎么触发（召见制）

每个时代有 3 张抉择卡，但它们**不是全都能点的**：

| 卡片状态 | 表现 | 能否选 |
| :--- | :--- | :--- |
| 待决 | 自动展开全文与 3 个选项 | ✅ 能 |
| 已决 | 收起，显示你当初选了什么 | ❌ 只读 |
| 未来 | 只给一句话摘要 | ❌ 只读（可点开预览） |

这个设计来自《07/05》：事件发生时只出通知与一句话摘要，玩家主动决定何时听完整汇报。**90% 的情况不会因为拖延而错过。**

### 两个数值原则（玩家会感觉到）

1. **你的选择会衰减。** 第一时代的选择，到第十时代只剩约 6% 的影响力（`0.6^9`）。但**门闩不会衰减**——某些选择是永久的。
2. **门闩不给你百分比。** 拿到"排外传统"不是"+15% 外交"，而是**某些选项从此变灰**。这是《12》铁律 3。

### 为什么很多选择"看起来没影响"

这是故意的。《04》明说"没有完美结局"，有些代价要到三四个时代后才浮现。

## 四、自检（改代码后务必跑）

四套测试，共 200 项断言。**改任何数据或引擎代码后必须全通过再交付。**

```bash
node selftest.js      # 引擎层 39 项：数据完整性 + 五条铁律 + 结局可达性 + 分布覆盖度
node mosaictest.js    # 视觉层 41 项：确定性与几何 + 海陆可辨性 + 雾/山/岸线判据 + 政体区分
node uitest.js        # UI 层 57 项：启动路径 + 30 抉择 × 3 选项 + 12 结局 + 科技树 + 档案室
node stagetest.js     # 舞台层 63 项：离屏缓存 + 雷达图 + 趋势图 + 悬停命中 + 新闻条
```

### ⚠️ 最重要的一条纪律：Node 全绿 ≠ 浏览器能跑

这个项目已经踩过两次，都很贵：

1. **白屏**：模拟 DOM 的 `getElementById` 对任意 id 都返回假元素，掩盖了真实的取不到元素。
2. **黑屏**：迷雾渐变写成 `'rgba(' + mist.slice(1) + ',' + alpha + ')'`——`slice(1)` 去掉的是 `#`，
   拼出 `"rgba(110c0a,0.3)"`，真实浏览器抛 `SyntaxError`，整幅地图一笔都画不出来。
   **而当时 196 项断言全绿**，因为测试替身的 `addColorStop` 是个空函数。

修法已经写进 `mosaictest.js`：`addColorStop` 现在真的按浏览器规则校验颜色格式，并且有一条
`迷雾渐变色标全部可解析（十时代 × 三档已探索）` 守着它。
**教训：测试替身越"宽容"，越等于没有替身。**

### ⚠️ 第二条纪律：断言必须测真正关心的那个量

这一轮又踩了一次同一类错误的**另一面**。

**问题**：截图里海岸线几乎看不见。但已有断言是"描边遍数 ≥ 3"——那是**画了几次**，
不是**看不看得见**。对照实验（同种子同状态，`reveal=1` 与 `reveal=0` 各画一张）证明：
关雾时大陆外缘那圈亮线完整连贯，开雾时几乎被吞平。根因是雾的外圈 alpha 到了 **0.90**，
而海岸线恰恰画在大陆外缘——正好是雾最厚的地方。

**修法**：外圈 alpha 封顶 0.62。实测亮线保留率从 ≈0% 升到 **77%**。
新增断言 `迷雾外圈 alpha 封顶 0.62（不得吞掉海岸线）`，并用注入回溯验证过它真会报警。

**教训**：断言测的量必须和人在乎的量是同一个。
- "描边遍数" ≠ "看得见"
- "亮度分层数" ≠ "有立体感"
- "JSON 里有这个字段" ≠ "玩起来有这个东西"

**推论**：新加的断言必须做**注入回溯**——把 bug 改回去，确认它报警。
没验证过的断言，很可能只是个安慰剂。

### 视觉引擎调参也是靠实测，不是靠目测

判据（阈值全部实测得出，不是"我觉得"）：

| 判据 | 阈值 | 由来 |
| :--- | :--- | :--- |
| 海陆相对亮度差 | > 22% | 实测 5/10 个时代达不到，画出来是一整片糊掉的棕灰 |
| 海陆绝对亮度差 | ≥ 24 | 相对差达标但两者都很暗时，画面仍是一团黑 |
| 海岸线描边遍数 | ≥ 3（辉光/主线/浪花） | 《05》视觉节第一条 |
| 迷雾外圈 alpha | ≤ 0.62 | 超过就吞掉海岸线（见上） |
| 中立政体岸线明度 | 不得三分量全高 | 浅羊皮色混白后会成刺眼白边 |

**海陆亮度必须按 `drawMap` 的真实混色路径取值**：`mix(ground[0], ground[1], t*0.8)`。
早前测试取 `Math.max(...ground)`，算出来的是数组里最亮那一档，而屏幕上最亮的水格
是 `t≈1` 时的混色——两者不是一回事，调色时完全对不上。

### 三层阶梯山：可读的形状不能靠"亮一档暗一档"

山峰早前是"两块等宽暗矩形 + 几根亮竖条"，在土黄底上出来是一根**焦黑的 T 形**，
像烧焦的树枝。这不是"看不见"，是"看不出是什么"。

改成三层阶梯：山体 `-0.22` / 背光面 `-0.40` / 受光面 `litK`，最高处加雪顶。
**逐层收窄的轮廓才是"山"这个形状的定义**；明暗只是让它不消失。

两个配套修法也是实测逼出来的，不是设计出来的：

| 修法 | 实测发现 |
| :--- | :--- |
| 提亮量 `litK` 随底色自适应 | 羊皮纸时代陆相 L=200，`shade(+0.32)` 只能提到 218（+8.9%），受光面的提亮空间被压没了 |
| 受光面宽度有 2px 下限 | 顶层 `lw` 只有底层的 28%，时代 4~5 格宽才 9~10px，算下来 1.2px——亚像素，等于没有 |
| 抽样基数用「该类地形格数」 | 早前用 `cols*rows`，格小的时代分到同样多的山但每座更小，羊皮纸时代受光面亮像素只剩 3 个 |
| 系数 0.055 → 0.16，下限 6 座 | 0.055 是从像素数倒推的，时代 1 算下来只有 2~3 座山，放大截图里整片平原一座都没有 |

### 关于"给视觉缺陷写自动化断言"的一条教训

山峰那条断言换了**四版**才站住，四次都是想用「像素统计」代理「形状是否可读」：

1. 全图亮度分层 ≥5 —— 地形底砖本身就有五六种亮度，噪声淹信号，**注入回退仍全绿**
2. 绝对阈值 `L<26` / `L>120` —— 明亮时代整体误报
3. 以 `A.land` 为基准 —— 底砖早被政体染色，与本色差 40+ 亮度
4. 以同图陆面中位为基准、卡 1.18 倍率 —— 羊皮纸时代受光面**物理上限只有 1.197 倍**（183→219），
   卡 1.18 只剩 3 个像素过线；放宽到 1.10 又变成对噪声放行

最后改成数「符号层用了几档明度」——这是**定义本身**（三层结构必然产生 ≥3 档明度），
不是代理指标，因而不受面积、密度、底色深浅影响。

**教训**：判据本身也要评估价值。
为一个低频风险建一条需要四轮才能稳定的像素统计断言，是**负收益**——
真要防"有人把三层改回两层"，靠的是代码评审 + 注入回溯，不是这条断言。

### 视觉引擎调参也是靠实测，不是靠目测

几轮调参的判据都写成了断言，防止将来"顺手调色"又调回去：

| 判据 | 阈值 | 由来 |
| :--- | :--- | :--- |
| 海陆相对亮度差 | > 22% | 实测发现 5/10 个时代达不到（羊皮纸 9.5%、混凝土 14.1%），画出来是一整片糊掉的棕灰 |
| 海陆绝对亮度差 | ≥ 24 | 相对差达标但两者都很暗时，画面仍是一团黑 |
| 海岸线描边遍数 | ≥ 3（辉光/主线/浪花） | "看得见海岸线"是《05》视觉节第一条 |
| 中立政体岸线明度 | 不得三分量全高 | 浅羊皮色混白后会成刺眼白边 |

其中"海陆亮度"必须**按 `drawMap` 的真实混色路径取值**：`mix(ground[0], ground[1], t*0.8)`。
早前测试取 `Math.max(...ground)`，算出来的是数组里最亮那一档，而屏幕上最亮的水格是 `t≈1` 时的混色——
两者不是一回事，调色时完全对不上。

### 三个死条件（实测揪出）

结局判定里写了三条**永远不会成立**的判据——它们让"文明崩坏"实际只由剩下的条件决定：

1. `_maxStreak >= 4` —— 引擎只在遇到非暴力选项时清零连击，**不按时代重置**；而每时代仅 3 个抉择，实测 `_maxStreak` 自然上限就是 3。已改为不再使用该字段（保留为观测量）。
2. `s.c.dissonance >= 6` —— `s.c` 是 `counts` 的代理，而引擎只写 `counts.dissonanceFlag`，真正的失调值在 `derived('dissonance')` 里。**读错对象，恒为 0。**
3. `violence >= 8 && trust < 30` —— 加了信任慢回归后实测区间是 34~65，`< 30` 永不成立。

修正后的三条判据经 6000 局标定，并逐条验证**不误吞其他 11 个结局**（阈值不能低于 12：铁血征服的 `dissonance` 恰为 10，`>= 10` 会把它吃掉）。

### 核选项问题

原判据 `核使用者 && env < 35` 配合 `核废土 && violence >= 4`：第八时代那个核选项 C 会把环境指数直接砸到 12 左右，于是**两条判据必然同时成立**——随机游玩 33.5% 的对局被一个选项锁死。
现改为"用核是崩坏的**必要**条件，不是充分条件"：必须叠加认知失调极端才成立。

**其中「三个死条件」和「核选项」是真正的设计缺陷**，不是代码 bug——它们让游戏"无论怎么玩都同一个结局"，等于不可玩。

## 五、当前设计参数（实测数据，非估算）

**随机未覆盖：神权复兴、生态回归** —— 这是**设计意图**，不是缺陷。《04》明写"文化同化需要在至少 6 个时代中选择文化/包容类选项"，即稀有结局本就需要玩家主动去选。

### 行为基准（比随机分布更能说明问题）

| 玩法 | 结局 | 关键数值 |
| :--- | :--- | :--- |
| 全程只选暴力/核选项 | **文明崩坏** | violence 17、dissonance 32、trust 35 |
| 全程只选非暴力非核选项 | **文化同化** | violence 0、inclusion 11、trust 57 |

这两行是本轮最重要的验证：**极端路线和温和路线通向完全不同的结局**，说明属性系统真的在起作用，而不是"怎么选都一样"。

铁血征服 0.3% 偏低，若正式版需要提高，可把判定从 `inclusion<=1` 放宽到 `inclusion<=2`。

## 七、文件结构

```
可玩原型/
├── index.html      界面骨架 + 全部样式（原生 CSS，无框架）
├── data.js         数据层：30 抉择 / 12 结局 / 属性 / 标记 / 接触纪元
├── engine.js       引擎层：五条铁律 / 结局判定 / 存档 / 属性快照序列
├── mosaic.js       视觉引擎：地形噪声 / 十时代配色 / 地貌 / 海岸线 / 地标 / 插画
├── stage.js        舞台层：离屏缓存 / 悬停 / 雷达图 / 趋势图 / 科技树 / 档案室
├── ui.js           界面层：渲染与交互
├── selftest.js     引擎自检（39 项）
├── mosaictest.js   视觉自检（39 项）
├── uitest.js       UI 自检（57 项）
├── stagetest.js    舞台自检（63 项）
└── README.md       本文件
```

### 三层分工

```
ui.js  ── 怎么玩：渲染、点击、弹窗
   ↓
stage.js ── 画什么、画在哪：离屏缓存、图表、科技树、悬停命中
   ↓
mosaic.js ── 怎么画：地形噪声、配色、地貌、海岸线、地标、插画
```

`stage.js` 是中间层，存在的原因是**地图很贵**（一次约 16000 个 `fillRect`）。
悬停时不能重画全图，所以底图只在状态变了时画进离屏 canvas，悬停只把离屏图 blit 上来 + 画高亮圈。
地图与插画必须用**两块独立**的离屏画布——早前共用一块导致"画地图→切插画→切回地图"时把插画当地图 blit 出来。

### 视觉引擎的三个可调判据

`mosaic.js` 里的配色不是目测定的，每条都有实测判据（详见第四节表格）：

```js
/* 海陆相对亮度差 > 22%：早前 10 个时代有 5 个达不到，画出来是一整片糊掉的棕灰 */
/* 海陆绝对亮度差 >= 24：相对差达标但都很暗时，画面仍是一团黑 */
/* 海岸线描边 >= 3 遍：辉光托底 + 主线 + 浪花 */
```

政体色的分工也定死了，混淆过两次：

| 层 | 跟谁走 | 为什么 |
| :--- | :--- | :--- |
| 底砖染色 | **政体**（铁血红 / 融合紫，权重 0.62 / 0.42） | 让玩家一眼看出自己选了什么路线 |
| 海岸线 | **政体**（有立场时）/ **时代**（中立时） | 有立场才让政体接管；否则用时代岸色 |
| 地貌符号 | **该格实际底色**提亮/压暗 | 否则两种政体下的符号对比度不一样，其中一种必糊 |
| 河流 | **时代陆相**提亮 | 河是陆地上的东西；用海色会变成一条抢眼的冷蓝带 |
| 迷雾 | **径向渐变**，取该时代天空色 | 均匀铺黑会把画框四周压成死黑 |
