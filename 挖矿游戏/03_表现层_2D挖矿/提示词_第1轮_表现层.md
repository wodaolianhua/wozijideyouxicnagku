## 要做的界面与交互

1. **2D 剖面地图**：横版格子视图，程序化画法。不同材质不同颜色（空气透明/土/石头/基岩/矿脉），矿物用颜色区分（煤黑/铁灰/铜橙/银白/金黄金/稀有晶体紫），越深越暗。角色用简单方块/圆点表示（不搞建模、不做写实美术）。
2. **操作**：方向键（或点击相邻格）移动；按方向键 + 挖键（或点击相邻格）挖掘。**交互要有明确引导**——打开就提示"方向键移动，空格挖，走到地表按 S 卖矿"，别让用户找不到交互（这是旧项目反复踩的坑）。
3. **HUD 常显**：当前钱数、体力条、背包占用（X/Capacity）、当前工具、深度。
4. **背包面板**：列出背包里各矿物数量 + 按单价估算的总价值（用 02 的 IBackpackPolicy.Valuation）。
5. **商店面板**：工具（镐/电钻/挖掘机）、机器/雇工，显示价格/能力，点击购买（走 02 的购买逻辑）。买不起要有提示。
6. **卖矿与收入提示**：回地表卖矿后，明确显示"本次卖出收入 ¥N + 明细"（读 `AdvanceResult.Outcomes[].Sale`），钱数同步增加。**收入必须来自后端返回的 Sale.Income，前端不自己算**。
7. **快进**：一个"快进到背包满/体力耗尽"按钮，调 02 的 FastForward。
8. **自动化展示**：后期买机器/雇工后，地图上有它们的标记，每步自动产出有可见反馈。

## 硬性要求

- **算法外包**：挖掘/移动/背包/卖矿/购买/自动产出/快进全部调 02 库的接口。前端只负责"把数据显示出来 + 把玩家操作变成 GameAction"。**禁止在前端重写游戏逻辑**。若 02 接口还没接上，用本地 mock 顶住，但接口签名按 02 的来。
- **数据外包**：地图/单价/商店表从 01 的 JSON 读，不硬编码在代码里。
- **数据契约（唯一权威，禁手抄）**：前端类型用分发副本 `接口契约_共享类型/Contracts.ts`（拷进 src 或配路径引用），字段/枚举与 .cs 一一对应。**禁止自己另写一套前端类型**——手抄字段对不上会静默出错。
- **JSON 全链 PascalCase**：API 收发、前端解析字段名都用 PascalCase（`MinerX`/`Backpack`/`CurrentTool`），枚举按数值解析（不要当字符串）。后端保持 .NET 默认序列化，不配 camelCase。
- **单端口可跑**：后端一个进程同时托管前端静态文件和 API，起服后浏览器开一个地址就能玩；`.glb` 之类不用（2D 无模型），但注意静态文件 MIME 要能服务前端资源。
- **交互引导**：首次打开有操作提示，避免"打开不知道干嘛"。

## 环境坑（曾踩过）

- `dotnet` 命令一律用 **PowerShell**（Git Bash 跑 dotnet 崩）。
- 单端口托管时，前端构建产物要放到后端 `wwwroot/`，确保起服能读到。
