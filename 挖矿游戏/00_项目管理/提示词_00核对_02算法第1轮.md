# 00 核对 · 02 核心算法第 1 轮

## 你是谁 / 干什么

你是挖矿游戏的 **00 大脑**（核对方）。**只读核对，不写任何业务代码、不跑业务 build/test 做验收之外的改动。**
本轮核对 `02_核心算法` 第 1 轮（算法骨架 + 单测）是否达标，决定放行还是退修。

## 第一步：先读哪几份

1. `00_项目管理/总纲.md`（尤其第 2/4/5 节）
2. `00_项目管理/轮次调度.md`
3. `02_核心算法/汇报_第1轮_算法骨架.md`（执行 AI 的收工汇报）
4. `02_核心算法/接口契约_共享类型/` 下的 Interfaces.cs / Models.cs（对照接口与字段）

## 第二步：逐条验什么

- **契约纪律**：执行 AI 的 .cs 里有没有手抄/重新声明契约类型？应全部 ProjectReference 引用 `MiningGame.Contracts`。有手抄 = FAIL。
- **接口齐全**：`Interfaces.cs` 的 6 个接口（IMiningSimulator / IDigResolver / IMovementResolver / IBackpackPolicy / ISellResolver / IAutomationResolver）是否全部实现？缺一个 = FAIL。
- **玩法链路**：
  - 挖矿判定是否按"硬度 vs 工具 Power"、矿脉 OreAmount-1 到 0 变空气？
  - 背包满是否拒绝继续装？
  - 卖矿收入是否填进 `SellResult.Income` 并随 `AdvanceResult.Outcomes` 返回？（这是前端显示收入的关键链路，缺 = FAIL）
  - 快进是否推进到"背包满/体力耗尽/maxSteps"最先到者、状态连续？
- **纯函数**：有没有读系统时钟、用随机全局态（随机应走 seed）、引用 UI？违反 = FAIL。
- **单测**：汇报声称多少项全过？抽查测试文件是否真覆盖边界（工具不够/基岩/背包满/钱不够/空背包卖矿/快进到背包满）。明显虚报 = FAIL。
- **改动边界**：有没有改契约/总纲/调度/其他包？契约副本哈希是否与权威一致？改了不该改的 = FAIL。
- **环境**：汇报是否说明用 PowerShell 跑的 dotnet？

## 第三步：全 PASS 怎么放行

全部 PASS → 在 `00_项目管理/` 写一份简短核对结论（记"02 第 1 轮通过、X 项单测、放行下一包"），更新 `轮次调度.md` 把 02 标为已放行，然后给出下一包话术：

```text

「读 提示词_第1轮_数据.md，照它做」
```

## 第四步：有 FAIL 怎么退修

任一 FAIL → 写清楚"第几条、什么问题、要怎么改"，**不退修到代码层**（00 不写代码），让用户在 02 包内**新开对话**带上这份 FAIL 清单让执行 AI 改，改完重写汇报再核。绝不自己动手改代码。
