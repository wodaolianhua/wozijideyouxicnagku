## 一、这是什么（一句话）

**2D 挖矿经营游戏**：在一座山头的地下剖面里挖矿，矿装进背包（容量有限），装满/想收工就回地面把矿卖掉换钱，攒钱买更好的工具、机器和雇工，越挖越深、矿越值钱。
**玩家亲手挖**（不是纯指挥、不是看着机器人干活）——早期徒手/镐，后期才逐步上机器和雇人自动化。画面是 **2D 剖面**（像横版挖矿），不是 3D、不是小人打架。

---

## 二、核心玩法（用户已确认，不许改）

1. **开局给一笔启动资金**（数据层定数值），角色站在山头地表井口。
2. **亲手下井挖**：上下左右移动到相邻格、朝某方向挖开格子。挖土软、挖石头硬（工具等级不够挖不动）、挖到矿脉出货。
3. **背包容量有限**：挖到的矿进背包，装满了就挖不动（得先回去卖）。这是"何时回地面"的核心张力。
4. **回地面卖矿**：角色回到地表（或用"回地面"操作），把背包里的矿按单价卖掉换钱。越深的矿（金/稀有晶体）单价越高。
5. **攒钱升级**：
   - 买工具（镐 → 电钻 → 挖掘机）：能挖更硬的格子、更深的矿；
   - 买机器/雇人（机器人 / 雇工）：**后期**自动定时帮挖，雇工要付工资（持续成本）；
   - 扩背包（若数据层设了）——让用户决定，先留字段。
6. **真实矿物**：泥土/煤/铁/铜/银/金/稀有晶体，按深度分层——越深越值钱、越硬、工具要求越高。
7. **时间推进**：每个操作算一步；自动化单位每 N 步产出一次。玩家决定一步步挖还是快进到背包满。

|---|---|---|

| `01_矿物与地图数据` | 山头剖面网格（格子/矿脉分布/硬度）、矿物单价表、工具与雇工商店表、启动资金/背包容量/体力数值 | JSON 数据 + 数据校验 |

| `03_表现层_2D挖矿` | 2D 剖面渲染、方向键/点击操作、背包与钱显示、商店面板、卖矿收入提示、快进 | 前端 + 后端宿主 |

**依赖方向**：01 提供数据 → 02 消费数据跑算法 → 03 调 02 的接口做展示。02 是纯函数，**不依赖 03**；03 只调接口，不重写算法（"规则层零引擎依赖"铁律）。

### 契约工程铁律（沿用成熟模式，禁手抄）

- 所有共享类型只在 `MiningGame.Contracts` 定义一次，各包通过 ProjectReference 引用。**严禁手抄/重新声明**——两套类型编译必失败。
- 契约变更后跑 `bash E:/挖矿游戏/分发契约.sh` 同步只读副本到各包（含前端 `Contracts.ts`）；编译自检**用 PowerShell**（Git Bash 跑 dotnet 崩）。
- **前端 TS 也走同一套契约**：`Contracts.ts` 与 .cs 一一对应（字段名 + 枚举数值严格一致），03 直接用分发副本，禁止自己另写。
- **JSON 全链统一 PascalCase**：数据/API/前端字段名都用 PascalCase（大写开头，与 .cs 属性名一致：`MinerX`/`Backpack`/`CurrentTool`）。.NET 默认就是 PascalCase，零配置、不静默丢数据。**禁止改 camelCase**，枚举传数值。
- **收入要能传回前端**：卖矿收入填在 `SellResult.Income`、随 `AdvanceResult.Outcomes` 返回；前端靠这个显示"本次卖了多少"。忘了填前端就没数据。
- 状态字段全能存中间进度（位置/体力/钱/背包/工人都在 `GameState`），分步推进/快进不丢进度、不需重复下令。
- 觉得契约有问题 → 提变更申请到 `00_项目管理/变更申请/`，由 00 统一改，执行 AI 不自己改。

## 五、算法清单（02 包的重头，必须单测）

| 算法 | 说明 | 验收 |
|---|---|---|
| 移动 | 上下左右走一格，实心格挡住、空气可过、越界拒绝 | 三种结果码正确 |
| 挖掘 | 目标格硬度 vs 工具 Power，判定能否挖、挖到什么、体力消耗；矿脉 OreAmount-1，到 0 变空气 | 工具不够/基岩/背包满/越界都返回明确码不崩溃 |
| 背包 | 容量检查、装矿、装不下拒绝；估值（背包矿按单价算） | 装满拒绝、估值正确 |
| 卖矿结算 | 地表卖背包全部矿，按单价表算收入+明细，背包清空 | 空背包返回 0；收入确定可复现 |
| 购买/雇佣 | 钱够扣钱加工具/工人，钱不够返回 NotEnoughMoney | 钱不够不扣钱 |
| 自动产出 | 机器/雇工每 Interval 步挖一次、工资扣除（纯函数确定性） | 到点才产出、工资正确扣 |
| 快进判定 | 推进到"背包满/体力耗尽/maxSteps"最先到者 | 到点即停、状态连续 |

全部为**纯函数**：相同输入必得相同输出，不碰 UI、不读系统真实时钟、随机走 seed。

## 六、技术原则

- **画面**：2D 剖面（横版格子视图），程序化画法、格子清晰、矿物用颜色区分即可，不引入外部模型/贴图包。文件夹叫"2D挖矿"。
- **算法优先**：挖掘/背包/结算/自动产出逻辑集中在 `02`，纯函数、可单测。
- **单端口可跑**：后端一个进程同时托管前端和 API，起服后浏览器开一个地址就能玩。
- **环境坑**：`dotnet` 命令一律用 PowerShell（Git Bash 跑必崩）；仓库根无 .sln，测试直接指定 .csproj。

## 七、工作模式（铁律）

1. **00 是大脑，只写文档**：写提示词 + 调度 + 总纲，**不写业务代码、不跑 build/test 做验收**。
2. **一包一对话**：每个执行包开一个新对话，第一句固定「读 `提示词_第N轮_xxx.md`，照它做」。执行 AI 自己读代码、写代码、跑测试、写汇报。
3. **收工交汇报**：执行 AI 在包内写 `汇报_第N轮_xxx.md`，00 做**只读核对**后放行下一轮。
4. **绝对红线**：不写 C 盘；不动系统进程；不删东西（只挪）；不碰旧项目；未查证不承诺。
