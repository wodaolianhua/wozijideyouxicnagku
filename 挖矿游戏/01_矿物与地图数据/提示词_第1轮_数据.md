## 要造的数据

1. **山头剖面网格**（对应契约 `MineGrid` / `Cell`）：
   - 一张 2D 剖面（建议宽 30~40、高 25~35 格），`SurfaceY` 为地表行、`ShaftX` 为初始井口 X。
   - 地表以上是空气；往下分层：浅层泥土/煤 → 中层铁/铜 → 深层银/金 → 最底稀有晶体。
   - 格子要填 `Tile`（空气/土/石头/基岩/矿脉）、矿脉的 `Mineral`、`Hardness`（硬度，越深越硬）、`OreAmount`（产量）。
   - 底部和左右边界用基岩封住，防止挖穿。
   - **矿脉分布要有层次、有规律**：越深矿物越值钱，别把所有矿随机糊一起。
2. **矿物单价表**（`GameState.Prices`：矿物枚举数值 → 单价）：泥土便宜、煤铁递增、金和稀有晶体最贵。数值要能形成"挖深更划算但更难"的取舍。
3. **工具商店表**（`ToolSpec`）：徒手(0元)/镐/电钻/挖掘机，Power 递增、Price 递增。Power 要能对上格子 Hardness（镐挖得动浅层、电钻挖得动深层）。
4. **雇工/机器商店表**（`WorkerSpec`）：机器人 / 雇工，Power、Interval（几步挖一次）、Wage（雇工有工资、机器人可为 0）、Price。
5. **开局数值**：启动资金（够买第一把镐但要省着花）、背包容量、体力上限、体力消耗/恢复。写在一份 `开局数值说明.md` 里。

## 硬性要求

- **JSON 能直接反序列化成契约类型**：字段名一个不差、PascalCase（大写开头，`MinerX`/`SurfaceY`/`OreAmount` 这种）。**禁止 camelCase**——.NET 默认 PascalCase，改了会静默丢数据。枚举传数值（如 `Gold` = 5）。
- **数据契约（唯一权威，禁手抄）**：类型来自契约工程 `MiningGame.Contracts`，本包已同步只读副本在 `接口契约_共享类型/`（先读）。**禁止在本包重新声明/手抄类型**；字段对不上要提变更申请给 00，不自己改。
- **数据校验脚本**：写个校验脚本（PowerShell 或 C# 皆可），检查：网格尺寸与 Cells 数量一致、坐标不越界、有地表和井口、每种矿物都出现、单价表覆盖全部矿物、商店 Power 能挖到对应深度、路网/矿脉可达（不存在完全封死的孤岛）。脚本要能跑并报告 PASS/FAIL。
- **自包含**：数据文件 + 校验脚本 + 数值说明都放本包，不写别的包。
