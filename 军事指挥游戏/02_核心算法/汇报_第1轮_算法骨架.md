## 二、接口实现

| 接口 | 实现类 | 说明 |
|---|---|---|
| `IPathFinder` | `PathFinder` | Dijkstra，按 `MapEdge.Cost` 加权，无向边；不可达返回空列表不抛异常；`FindPathVia` 逐段求解并去重衔接点，任一段不可达则整条返回空 |
| `IMarchSimulator` | `MarchSimulator` | `Advance` 推进 N 步 / `FastForward` 停在遭遇点或 maxSteps；输出新状态 + `MarchTrail` 轨迹 + `EncounterEvent`；不改入参 state |
| `IEncounterDetector` | `EncounterDetector` | 快照式检测（当前位置接战距离）；`Advance` 内部用单步轨迹扫描，迎面擦过也能抓到 |
| `ILossResolver` | `LossResolver` | 按兵力/兵种/地形防御/伏击加成结算，确定性、无随机 |
| `IVisibilityPolicy` | `AlwaysVisiblePolicy` | 第一阶段恒 `true`，迷雾阶段可换实现不动调用方 |

规则数值集中在 [MarchRules.cs](file:///E:/军事指挥游戏/02_核心算法/StrategyGame.Core/MarchRules.cs)：兵种速度、道路/山路与地形耗时倍率、地形防御、基础损失率、伏击系数。

## 三、关键行为约定（供 03 对接）

- **续走**：`orders` 非空 = 先把 Order 寻路写入 `PlannedPath/PathIndex` 再推进；`orders` 为空 = 沿已有 `PlannedPath` 继续走。单测已覆盖“下令一步、后续不下令继续走”。
- **单步推进**：进度增量 = 兵种速度 ÷（边 Cost × 边类型倍率 × 进入节点地形倍率）；支持一步内跨多条短边；到达终点后 `PathIndex` 指向末节点、`EdgeProgress=0`。
- **轨迹**：每条 `MarchTrail` 首点是本次推进起点的当前位置，之后每步记录末位置（含中途到达节点），前端可直接连成折线箭头。
- **遭遇**：仅玩家 vs 敌军算敌对（中立不参战）；默认接战距离 `0.5` 世界单位，可在 `MarchSimulator`/`EncounterDetector` 构造器调。事件尽量在**同一步**内比对轨迹（重叠时间段的最近接近点），错步经过同一节点不误触。
- **伏击**：遭遇点在山地/森林，且一方原地驻扎、另一方在移动 → 驻扎方为伏击方，写入 `IsAmbush/AmbusherId`。
- **损失**：遭遇事件内部已调用 `ILossResolver` 并填好 `EncounterEvent.Loss`（`Detect` 也填）；`Advance` 同时把累计损失扣到返回状态的 `Strength`（入参状态不变），同一步多场遭遇不会重复扣同一条损失。
- **结果码**：无路 → `NoPath`，目标不存在 → `InvalidTarget`，已在终点 → `AlreadyArrived`；这些情况仍继续推进其他部队，不抛异常。

## 六、疑问条（不阻塞，请 00 定调）

1. **损失是否要扣进状态**：本轮按“规则层权威”把损失扣到返回状态的 Strength 上。若 00 希望 02 只出事件、由 03 决定是否应用，改一行即可。
2. **多支部队同点遭遇**：现为两两配对出事件（每事件 2 个 ArmyId）。若后续要做多方混战合并成一条事件，需要契约层约定，当前不改。
3. **行军中改令**：新命令从当前路段起点节点重新寻路（`EdgeProgress` 归零，会回跳到所在边起点）。若要“从边上当前位置继续”，需要契约提供“边上临时起点”语义，当前按上述简化实现并在代码注释标明。
4. **地形对寻路权重**：契约注释写明寻路只按 `Edge.Cost` 加权，因此地形/边类型倍率只作用于行军耗时，不参与选路。如需“山路更贵所以绕路”，应在 01 数据层把差异做进 Cost。
5. **seed 当前未参与计算**：损失结算完全确定性，seed 仅透传保留，方便后续需要随机时接入；如要求“必须用 seed 产生扰动”，请给规则口径。
