## 要造的数据

一张**架空古代背景**的作战地图（延续"架空、非三国"的调性，别用魏蜀吴）：

1. **路网**：若干地点（城/关隘/要地）作为节点，节点之间用**道路 / 山路**连接成网。每条边标注类型（road 道路 / mountain 山路）和行军代价（山路更慢）。**路网必须连通**（任意两点可达），不能有孤岛。
2. **地形**：节点/区域标注地形（平原/丘陵/山地/河流等），用于影响行军速度和战斗。
3. **初始兵力**：至少 2 个势力（玩家方 + 敌方），各若干支部队，标初始所在节点、兵力数、类型。玩家方起手弱一点（延续"没落贵族、以弱对强"的调性）。
4. **节点坐标**：每个节点必须填 `X`/`Y` 数值（用于前端把地图画出来）。坐标要跟路网拓扑大致对应——相连的点在坐标上也靠近，别让相连节点天南地北。

> 注：遭遇不靠预先标"要地"，而是由 02 算法按部队位置相遇/接战距离动态判定。所以数据里**不需要**"遭遇要地"这种字段，别自己加。

## 数据结构对齐（唯一权威，禁手抄）

地图/节点/边/部队/势力的类型**全部来自契约工程 `StrategyGame.Contracts`**。本包已同步一份只读副本在 `接口契约_共享类型/`（先读它，尤其 `Enums.cs` 和 `Models.cs` 的 `WorldMap / MapNode / MapEdge / Army`）。

- 造的 JSON 要能**直接反序列化成契约里的类型**，字段名一个都不能差、不能自己另起一套。
- **字段名一律 PascalCase**（大写开头，如 `Id`/`NodeId`/`Terrain`/`Strength`，与契约 .cs 属性名一模一样）。.NET 默认按 PascalCase 反序列化，用小写开头的 camelCase 会导致字段读进来是空值（静默出错）。枚举字段填数值（如地形 Mountain=2），不要填字符串。
- **禁止**在本包重新声明这些类型或手抄一份；禁止修改副本文件。
- 觉得契约字段不够/不对 → 提变更申请给 00，不自己改。

## 硬性要求

- **数据自洽**：路网连通、引用有效（部队所在节点必须存在）、数值合理（兵力/代价为正）。
- **校验脚本**：写一个能检查上述自洽性的脚本（Python 或 Node 均可），跑一遍全过，汇报里写明。
- **体量适中**：一张能玩起来的地图即可（比如 12–20 个节点），不要贪多造几百个。
