# 第 3 轮 · 行军过程可视化 + 状态反馈（03 包）

## 背景

第 2 轮把底图视觉做完了（地形浮雕/河流/地名/军名条/粗曲线箭头），但用户实机试玩反馈「玩不明白」。本轮不碰美术，专修**行军这个核心玩法"看不懂、没过程、状态乱"**的问题。

## 试玩反馈（原始痛点，逐条对应，别跑偏）

1. 点「下令行军」后，部队不会自己走；即便推进，也看不到部队「动」的过程。
2. 点「快进」后，瞬间糊出一堆弯弯绕绕的线，完全看不懂发生了什么。
3. 点不同部队，有的动了有的没动、谁在半路、下一步去哪，完全搞不清。

## 病根（先读懂再动手）

- 现在「推进 1 步 / 快进」都是**瞬移**：后端状态更新后前端直接重绘，部队位置从 A 直接跳到 B，没有任何补间动画。
- 「快进」一次性推进到终点/遭遇点，所有部队轨迹瞬间叠加，所以糊成一团。
- 「下令」和「推进」是分离的：用户以为下令=走，实际还要再点推进/快进才动，认知断裂。

## 本轮范围（严格）

只改 `StrategyGame.Presentation\wwwroot\` 下的 `app.js` / `index.html` / `styles.css`。
**禁止改**：`Program.cs`、`WorldStore.cs`、`自测_HTTP.ps1`、`01_地图数据`、`02_核心算法`、`StrategyGame.Contracts`。后端 `/api/advance`、`/api/fastforward` 接口已够用，不要动。

## 要做的三件事

### 1. 连续行军动画（核心，最重要）

- 部队位置从旧点**平滑滑动**到新点（补间动画，单步约 300–600ms，缓动 easeInOut），**沿弯曲路线滑动**，不是瞬移。
- 点「推进 1 步」：播放这一步的动画。
- 移动中的部队：标记/名条加高亮或脉冲强调，让人一眼看出「这支在走」。
- 动画期间禁用再次下令/推进，避免状态错乱（动画播完才可再操作）。

### 2. 快进改为「加速播放」，别糊

- 快进不再瞬间糊满轨迹，改为**快速连续推进**（每步短动画，如 120–250ms/步），让用户看着部队「走完」。
- 途中遭遇敌军 → 立刻停下，弹出遭遇战报（复用现有遭遇面板，无 A/B 选项）。
- 抵达终点 → 停下。
- 若总步数过多（如 >300 步），可跳到「结果态」，但必须清晰标注：停在哪、为什么停（遭遇/抵达）、走了多少步。
- 全程轨迹分阵营清晰：我方蓝、敌军红；已走轨迹 / 部队当前位置 / 计划路径三者视觉可区分。

### 3. 状态反馈清晰（一眼看懂）

- 选中部队：高亮极其明显（粗描边 + 外发光 + 名条变色）。
- 下令后：底部/命令区明确显示「已下令：A → B → C」。
- 每支部队名条/标记上常显当前状态：**待命 / 行军中 / 已抵达 / 遭遇中**。
- 正在移动的部队，与待命部队视觉上能立刻区分。

## 交互语义调整

- **允许**：下令后部队自动开始连续行军（前端循环推进 + 动画），直到抵达 / 遭遇 / 玩家暂停——这符合用户「下令就动」的期待，是本轮重点。
- **保留不变**：点选、单点 `MoveTo`、多点 `MoveVia`、`Enter` 提交、右键/`Backspace` 撤回、`Esc` 清空、遭遇面板、重开。
- 不新增玩法；如自动行军需要，可加一个「暂停/继续」按钮（可选，不算新玩法）。
