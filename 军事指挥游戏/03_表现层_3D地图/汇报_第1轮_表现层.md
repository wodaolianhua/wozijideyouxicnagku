## 一、这轮做出来的东西

一个**单进程可跑**的行军指挥沙盘：后端宿主（net10.0）持有世界状态并调用 02 算法，前端零构建（原生 JS + Canvas 2D）负责呈现与交互。

- 地图：程序化绘制。地形用按最近节点划分的 Voronoi 色块（平原/丘陵/山地/森林/河流），路网分两种线型——**道路实线暖黄、山路虚线褐色**，节点画圆点 + 中文地名。
- 部队：我方蓝色、敌军红色圆标，标内是兵种字（步/骑/弓/器），标下是实时兵力数字；悬浮显示名称/兵种/兵力。
- 点选下令：点我方部队选中（脉冲双环 + 虚线弧），再点地图任意位置**自动吸附最近节点**（吸附点有扩散环 + 从点击点指向节点的虚线，绝不"点了没反应"）。
  - 单点 → `MoveTo`；连续点多个节点 → 路线预览虚线 + 编号目标 → `MoveVia`（按点击顺序）。
  - 按 `Enter` 或点「下令行军」提交；右键 / `Backspace` 撤回上一个点；`Esc` 清空或取消选中；再点同一部队取消选中。
  - 未选中部队时点地图只吸附查看，不下令（首次会提示先选部队）。
- 行军轨迹：每次推进后把 `AdvanceResult.Trails` 累加进前端轨迹层，按势力颜色画折线 + 沿路方向箭头；己方虚线显示"当前执行中的计划路径"。
- 推进：顶栏「推进 1 步」逐步观察，「快进」调 `FastForward`（MaxSteps=200）；时间步数字变化时高亮闪烁。
- 遭遇展示：停下后弹「遭遇战报」——位置/地形、伏击判定、双方参战部队损失（**只读 `EncounterEvent.Loss.LossByArmy`**）、战后剩余兵力、敌军位置与规模。**没有 A/B 选项**，只有「知道了，关闭战报」，关闭后由玩家重新点部队下令。
- 重开：顶部「重开」带二次确认，后端从 01 的 JSON 重新加载，回到 t=0。

截图说明：浏览器自动化工具截图通道被节流，改用 DOM 快照、网络请求与 canvas 像素采样验证（详见自测结果）。

## 三、调了 02 的哪些接口

| 用途 | 调用 |
|---|---|
| 行军推进 | `new MarchSimulator().Advance(state, orders, steps, seed=1)` |
| 快进 | `new MarchSimulator().FastForward(state, orders, maxSteps, seed=1)` |
| 路径预览（只读） | `new PathFinder().FindPath(...)` / `FindPathVia(...)` |

- 宿主用 `ProjectReference` 引用 `02_核心算法\StrategyGame.Core\StrategyGame.Core.csproj`，直接 `using StrategyGame.Contracts`，**没有手抄任何契约类型**。
- 世界状态由后端内存持有；`Advance/FastForward` 返回值直接替换当前状态，重启回到初始态。默认构造、零参数（接战距离 0.5 用默认值）。
- `orders` 非空才寻路写 `PlannedPath`，为空就是续走——前端"下令一次，之后只推进"完全按这个语义用。
- 损失不自己算，遭遇面板里的 `-177` 等数字直接来自 `LossByArmy`，兵力剩余来自返回状态的 `Strength`（已扣减）。

后端 API（均为 PascalCase JSON、枚举数值）：

- `GET /api/world` → `WorldState`
- `POST /api/advance` `{ Orders: Order[], Steps: int }` → `AdvanceResult`（Steps 夹到 1..50）
- `POST /api/fastforward` `{ Orders: Order[], MaxSteps: int }` → `AdvanceResult`（MaxSteps 夹到 1..2000）
- `POST /api/preview` `{ ArmyId, Waypoints }` → `{ Path, Code }`（只读，不改状态）
- `POST /api/reset` → 重新读取 01 数据后的 `WorldState`
- `GET /api/health` → `{ Status, Port }`

## 四、自测结果

### HTTP 自动化（`自测_HTTP.ps1`，27/27 通过）

实测覆盖（不是手工点，是脚本打 HTTP 断言）：

1. 静态入口 `GET /` 200、`app.js` 200；
2. `GET /api/world`：18 节点 / 29 边 / 9 部队、我方总兵力 2600、字段为 PascalCase；
3. `POST /api/preview` 折线 N02→N06：`Code=Ok`、路线从当前节点 N01 起，且**预览不改变世界状态**；
4. `POST /api/advance` 下达 `MoveTo N06` + 1 步：`Code=Ok`、时间步变 1、返回 9 条轨迹、我方轨迹≥2 个点、`PlannedPath` 写入且 `EdgeProgress>0`；
5. `POST /api/fastforward` 空命令续走：推进到 N06、返回 9 条轨迹；
6. 遭遇链路：重开后下令去 N05 再快进 → 停在时间步 13、`Encounters≥1`、事件带时间/节点、`LossByArmy` 同时含 `A_P01` 与 `A_E01`，且**兵力扣减额与损失合计一致**（800→623，损失 177）；
7. `POST /api/reset`：时间步回 0、兵力恢复 800。

### 浏览器实测（browser_use）

- 页面渲染：无 JS 报错，战况显示"我方 4 支 · 2600 兵 / 敌军 5 支 · 5000 兵"，时间步 0，画布铺满视口并绘出节点与 9 个部队标记（修掉了两个真实 bug：`world.map`→`world.Map`、canvas 固定定位导致只有 300×150）。
- 下令流程：选中青弋残军 → 底部显示"青弋残军 · 步兵 · 800 兵 · 位于 雁回城" → 点节点出现编号目标与虚线 → 点「下令行军」后时间步 0→1。

## 六、设计取舍与疑问条

1. **点击 vs 确认**：为了同时满足"单点终点"和"连续点多点折线"，我做成——点节点只累积目标并即时预览，`Enter`/按钮统一下令（1 点 `MoveTo`，≥2 点 `MoveVia`）。如果 00 认为"单击节点必须立刻出发"，当前实现会让第二个点来不及点；需要改成"单击即出发 + Shift 追加"请告知。
2. **敌军箭头**：前端轨迹层对敌我一视同仁，但 01 初始数据里敌军没有计划路径、本轮也没有敌军 AI，所以敌军标记原地不动、暂无敌军轨迹箭头。等后续轮次给敌军下 `Order`（或接 AI）后会自动画出，无需改前端。
3. **时间显示**：按提示词底层用整数 `Time`，界面只显示"时间步 N"，没有换算成"第几日"。
4. **重复遭遇**：部队停在敌军所在节点且不改命令时，继续推进会按 02 的判定再次触发遭遇（每次损失都照实展示）。这是算法现状，不是前端重复显示。
5. **推进步数上限**：`advance` 单次最多 50 步、`fastforward` 最多 2000 步（防误触卡死），默认前端分别用 1 和 200。
6. **自测脚本编码**：`自测_HTTP.ps1` 用 UTF-8 **带 BOM** 保存，否则 PowerShell 5 会把中文读成乱码并解析失败——后续改这个脚本时请保持 BOM。
