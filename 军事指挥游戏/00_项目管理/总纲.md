## 一、这是什么（一句话）

**纯战略军事指挥游戏**：你是指挥官，在地图上用**箭头**指挥部队行军、包抄、遭遇敌军、做决断。
**看不到小人打架**——没有单兵肉搏、没有亲征、没有第一人称。玩家看到的是部队标记和行军箭头，像看战局态势图。

---

## 二、核心玩法（用户已确认，不许改）

1. **开局有己方部队**（若干支部队，标记在地图上）。
2. **点选部队 → 下令移动**，两种下令方式都要支持：
   - **多点路径**：连续点好几个点，部队先从 A 走到 B，再从 B 拐弯走到 C——自己画折线做包抄/迂回。
   - **单点终点**：只点一个终点，部队自己沿道路/山路走到目的地。
3. **道路/山路是设计出来的**（数据层定义路网），不是随便穿地。
4. **时间推移时，箭头显示行军轨迹**：己方部队怎么走、敌军怎么动，都用箭头画出来。
5. **快进**：
   - 你觉得稳，就把时间往后推——途中若**没有遭遇**，直接跳到部队抵达终点的时间点；
   - 途中若**遭遇敌军/伏击**，时间停在事发点，把情况摊开给你（我方损失多少、敌军在什么位置、什么规模）。
6. **遭遇后不做"重大抉择弹窗"**（不弹 A/B 选项让你点）。玩家**自己决定怎么应对**——重新点部队、重新下令，是撤是绕是顶，玩家自己操作。
7. **敌军行军可见性（分两阶段）**：
   - **第一阶段（当前做）**：敌军行军**全程可见**，你能看到敌军箭头怎么动。
   - **第二阶段（难度分级时做）**：高难度下敌军行军不可见，只有己方侦察/情报探到才显示（战争迷雾）。现在先把接口留好，不实现。

## 四、分包与职责（契约工程 + 3 个执行包，工作模式不变）

| 包 | 职责 | 产出 |
|---|---|---|
| `StrategyGame.Contracts` | **唯一契约权威**：所有枚举/数据结构/接口 | .cs 契约源文件 |
| `01_地图数据` | 地图、路网（道路/山路）、初始兵力、地形、节点坐标 | JSON 数据 + 数据校验 |
| `02_核心算法` | 寻路、时间推进、行军插值、遭遇检测、损失结算、可见性接口 | 纯函数 C# 库 + 单元测试 |
| `03_表现层_3D地图` | 地图渲染、箭头行军、点选/多点下令、快进、遭遇情报展示 | 前端 + 后端宿主 |

**依赖方向**：01 提供数据 → 02 消费数据跑算法 → 03 调 02 的接口做展示。02 是纯函数，**不依赖 03**；03 只调接口，不重写算法（沿用旧项目的"规则层零引擎依赖"铁律）。

### 契约工程铁律（沿用旧项目，禁手抄）

- 所有共享类型（枚举/Models/Interfaces）**只在 `StrategyGame.Contracts` 定义一次**，各包通过 ProjectReference 引用。
- **严禁**在任何包手抄/重新声明这些类型——会出现两套类型，编译必失败。
- 契约变更后跑 `bash E:/军事指挥游戏/分发契约.sh` 同步只读副本到各包（含后端的 .cs 和前端的 `Contracts.ts`）；编译自检**用 PowerShell**（Git Bash 跑 dotnet 崩）。
- **前端 TS 也走同一套契约**：`Contracts.ts` 与 .cs 一一对应（字段名 + 枚举数值严格一致）。03 包直接用分发副本，**禁止自己另写前端类型**。
- **JSON 全链统一 PascalCase**：数据 JSON、后端 API、前端解析的字段名都用 PascalCase（大写开头，与 .cs 属性名一致：`NodeId`/`PlannedPath`）。.NET 默认就是 PascalCase，零配置、不静默丢数据，**禁止改 camelCase**。枚举传数值。
- **Army 带计划路径**：`PlannedPath` + `PathIndex` 存在状态里，下令一次即可分步推进续走，不需重复下令——02 算法必须按这个契约实现。
- 觉得契约有问题 → 提变更申请到 `00_项目管理/变更申请/`，由 00 统一改，执行 AI 不自己改。

## 五、算法清单（本项目的重头戏，必须单测）

用户原话："图画美术不行，算法什么的总行了吧。" → **算法是核心竞争力，美术是最弱环节**，投入比例往算法倾斜。

`02_核心算法` 必须实现并测试：

| 算法 | 说明 | 验收 |
|---|---|---|
| 寻路 | 路网上 A* / Dijkstra，支持"单点终点"自动找路；支持"多点路径"逐段求解 | 不同地形权重下路径正确；无路可走有明确返回 |
| 行军推进 | 按时间步长沿路径插值部队位置，速度/地形影响耗时 | 给定时间能算出部队精确位置 |
| 遭遇检测 | 同一时刻多支部队位置相遇/进入接战距离则触发 | 相遇必触发、错开不误触 |
| 损失结算 | 遭遇按兵力/地形/是否伏击算双方损失，**结果填进 `EncounterEvent.Loss` 随事件返回前端** | 数值确定可复现（纯函数）；前端拿得到损失显示情报 |
| 快进判定 | 从当前时间跳到"下一事件发生时刻"或终点，中间无遭遇则直达 | 有遭遇停在遭遇点、无遭遇直达终点 |
| 可见性接口 | 定义"敌军是否可见"的查询接口，第一阶段恒返回可见 | 接口存在，第二阶段可切换实现 |

全部为**纯函数**：相同输入必得相同输出，不碰 UI、不碰时间系统真实时钟。

## 六、技术原则

- **视觉方向（2026-11-22 用户定稿，覆盖此前"淡化美术"表述）**：地图按"军事态势图"做——**地形浮雕底图（山体阴影 + 高程配色 + 青色河流）+ 地名常显 + 军队名条常显（彩色底 + 白字）+ 粗曲线行军箭头（大箭头）**。仍**不引入外部 3D 模型/贴图包**；底图用程序化高程/噪声生成，节点坐标自动对齐。文件夹叫"3D地图"只是沿用名，2D 俯视即可，以"看得清行军"为准。
- **算法优先**：所有战斗/行军/遭遇逻辑集中在 `02`，纯函数、可单测。
- **单端口可跑**：后端一个进程同时托管前端和 API，起服后浏览器开一个地址就能玩。
- **环境坑**：`dotnet` 命令一律用 PowerShell（Git Bash 跑必崩）；仓库根无 .sln，测试直接指定 .csproj。

## 七、工作模式（铁律）

1. **00 是大脑，只写文档**：写提示词 + 调度 + 总纲，**不写业务代码、不跑 build/test 做验收**。
2. **一包一对话**：每个执行包开一个新对话，第一句固定「读 `提示词_第N轮_xxx.md`，照它做」。执行 AI 自己读代码、写代码、跑测试、写汇报。
3. **收工交汇报**：执行 AI 在包内写 `汇报_第N轮_xxx.md`，00 做**只读核对**后放行下一轮。
4. **绝对红线**：不写 C 盘；不动系统进程；不删东西（只挪）；不碰旧项目；未查证不承诺。
5. **每轮收工必须交两份话术**：执行包的「读 `提示词_第N轮_xxx.md`」+ 00 的「读 `提示词_00核对_xxx第N轮.md`」。00 提示词必须写明先读哪几份、逐条验什么；只给执行包话术视为交接未完成。
