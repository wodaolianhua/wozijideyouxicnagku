## 1. 设计原则

数值框架只服务一件事：**让玩家因为"我理解了什么"而赢，不因为"我抽到了什么"而赢。**

推导出四条硬规则：

1. **确定性**：相同输入必得相同输出。随机性只允许出现在"闪避""随机事件"这类明确的随机层，且必须对双方对称。
2. **可推导**：玩家看到自己的兵是 1000、对方是 1000、地形是平原，应该能自己算出大致结果。做不到这一点说明信息不足或公式过于隐蔽。
3. **克制必须显著**：净收益 ≥25%。低于这个数字，决策噪声大于决策价值，玩家会觉得"打谁都一样"。
4. **规模无关**：战斗结果与兵力规模无关（线性模型）。这条是大地图复用同一套公式的前提——5 人的遭遇战和 5 万人的会战用同一个公式，只是数字不同。

## 2. 单位与时间约定

| 概念 | 单位 | 说明 |
|---|---|---|
| 兵力 STR | 战力点（单个士兵） | 不是人数。人数单独传 |
| 士气 MOR | 0~100 | 初始值见§3 |
| 体能 STA | 0~100 | |
| 防御 DEF | 0~100 | |
| 士兵血量 | 10 HP（`SOLDIER_HP`） | |
| 伤害 | HP 点 | |
| 一个回合 | 10 秒（`TURN_SECONDS`） | |
| 局部交战时长 | 1~6 分钟 | 对应单场会战 5~10 分钟 |

**为什么回合定为 10 秒**：太短则玩家来不及做战术决策（显得在乱点），太长则战斗变成数值对撞。10 秒刚好够下一个命令并看到结果。

## 3. 兵种基础值

```
SOLDIER_HP   = 10.0
DAMAGE_SCALE = 0.115
ROUT_MORALE  = 20.0     # 士气低于此值溃退
ROUT_STRENGTH= 0.25     # 战力剩余比例低于此值溃散
TURN_SECONDS = 10.0     # 一个回合代表 10 秒实时战斗
```

| 兵种 | 兵力 STR | 士气 MOR | 体能 STA | 基础命中 | 防御 DEF | 征兵成本 |
|---|---|---|---|---|---|---|
| **步兵** | 10 | 60 | 50 | 0.45 | 8 | 1 |
| **弓兵** | 7 | 52 | 40 | 0.55 | 5 | 1 |
| **骑兵** | 12 | 72 | 80 | 0.40 | 7 | 2 |

**设计意图（每一条都有测试守着）**：

- 骑兵面板最高（兵力 14、体能 80），但**成本 2 倍且被步兵克制**——高风险高回报
- 步兵是**性价比锚点**（成本 1、防御最高 8），克骑兵但被弓兵克
- 弓兵是**脆皮输出**（命中最高 0.55，兵力最低 7，防御最低 4）——必须被保护

对应测试：`test_design_intent_panel_consistency`、`test_archer_is_glass_cannon`

## 4. 公式

### 4.1 有效战斗力（输出侧）

```
有效战斗力 = 兵力 × (1 + 士气/100) × (1 + 体能/200)
             × 地形系数 × 将领加成
```

代码：`effective_power()`

### 4.2 命中率（只取决于攻方）

```
命中率 = 基础命中率 × 地形修正    结果夹在 [0.05, 0.95]
```

代码：`hit_rate()`

> **⚠️ 这条是修正过的设计。** 初版公式是 `命中率 = 基础命中 × 地形 × (1 - 对方士气/200)`，实测发现问题：守方士气高会同时压低命中率和减伤，导致**高士气兵种把克制收益全部抵消**。实测步兵对骑兵的相对伤害优势只剩 4%，克制形同虚设。
> 现改为：士气只影响「输出」（§4.1）和「减伤」（§4.4），不进入命中率。
> 回归测试：`test_morale_only_affects_output_and_mitigation_not_hit`、`test_counter_cannot_be_nullified_by_enemy_stats`

### 4.3 兵种系数（克制）

```
攻方克守方：  系数 = 1.30
攻方被守方克：系数 = 1 / 1.30 ≈ 0.769
同类或无关：  系数 = 1.00
```

代码：`counter_factor()`

> **⚠️ 这条也是修正过的。** 初版同时维护两张表（`COUNTER` 给 1.30 增益、`COUNTERED_BY` 给 0.80 惩罚），同一组合被重复计算，净收益只剩 `1.30 × 0.80 = 1.04`。现改为**从单一来源派生**，数学上保证 `f(a,d) × f(d,a) = 1`。
> 回归测试：`test_counter_matrix_symmetric_inverse`、`test_counter_margin_significant`

实测矩阵（行=攻方，列=守方）：

| 攻方＼守方 | 步兵 | 弓兵 | 骑兵 |
|---|---|---|---|
| **步兵** | 1.000 | 0.769 | **1.300** |
| **弓兵** | **1.300** | 1.000 | 0.769 |
| **骑兵** | 0.769 | **1.300** | 1.000 |

### 4.4 守方减伤

```
减伤 = (1 - 防御/200) × (1 - 士气/200)
```

代码：`damage_mitigation()`

**验证**：任何兵种、任何士气值下，减伤系数严格落在 (0, 1] 区间（`test_mitigation_always_positive_and_below_one`）。否则高防兵种会被算出负伤害或超神。

### 4.5 每回合伤害

```
每回合伤害 = 有效战斗力 × 兵种系数 × 命中率 × 守方减伤 × DAMAGE_SCALE
```

代码：`damage_per_turn()`　返回**单兵口径**（与人数无关）

> **⚠️ 第三处修正。** 初版把参战人数混进了这个函数，导致单兵伤害随兵力规模变化。批量结算必须走`伤亡比例 × 人数`，否则量纲混乱、无法验证规模无关性。
> 回归测试：`test_casualty_rate_is_scale_free`、`test_battle_scale_invariance`

### 4.6 伤亡比例与批量结算

```
伤亡比例 = 每回合伤害 / SOLDIER_HP

每回合双方伤亡：
  攻方伤亡 = 守方伤亡比例 × 守方存活人数
  守方伤亡 = 攻方伤亡比例 × 攻方存活人数
```

代码：`casualty_rate()`、`resolve_duel()`

### 4.7 战斗结算与溃退

```
循环：
  若 攻方剩余/初始 < 0.25 或 守方剩余/初始 < 0.25 → 结束
  双方同时结算伤亡
  回合数 += 1

判定：
  一方溃退 → 另一方胜
  双方同时溃退 → 同归于尽
  达到 300 回合 → 未决（timeout）
```

代码：`resolve_duel()`，**纯函数无随机**，同输入必同输出。

### 4.8 士气变化

```
每 10% 伤亡 → 士气 -3
获胜 → 士气 +5
失败 → 士气 -12
结果夹在 [0, 100]
```

代码：`morale_after_combat()`

**败绩打击（-12）大于胜利激励（+5）**，这是"打了败仗就崩"的设计基础。对应测试：`test_morale_loss_exceeds_win_gain`

### 4.9 行军粮耗

```
粮耗 = 距离(km) × 地形行军倍率 × 人数 / 1000
```

代码：`march_cost()`

### 4.10 攻城效率

```
攻城系数 = (1 - 0.12 × (据点等级 - 1))    据点等级夹在 1~5
骑兵额外 × 0.85
最终夹在 ≥ 0.20
```

代码：`siege_modifier()`

### 4.11 就地取给

```
每 1000 人日耗 10 单位粮
surplus_food ≥ 人数/1000 × 10  →  可就地取给
```

代码：`supply_capacity()`

## 6. 战斗时长实测（平原 1000 v 1000）

| 交战 | 结果 | 回合 | 时长 | 剩余兵力 |
|---|---|---|---|---|
| 步兵 vs 步兵 | 双方均被打散 | 20 | 200 秒 | 237 / 237 |
| 步兵 vs 弓兵 | 弓兵胜 | 16 | 160 秒 | 223 / 463 |
| **步兵 vs 骑兵** | **步兵胜** | 13 | 130 秒 | 461 / 250 |
| **弓兵 vs 步兵** | **弓兵胜** | 16 | 160 秒 | 463 / 223 |
| 弓兵 vs 弓兵 | 双方均被打散 | 24 | 240 秒 | 237 / 237 |
| **弓兵 vs 骑兵** | **骑兵胜** | 7 | 70 秒 | 208 / 826 |
| **骑兵 vs 弓兵** | **骑兵胜** | 7 | 70 秒 | 826 / 208 |
| 骑兵 vs 骑兵 | 双方均被打散 | 17 | 170 秒 | 233 / 233 |

**验证到的三件事**：

1. **克制真实改变结局**（`test_counter_decides_actual_battle`）——不是只改数字，是真的打赢
2. **地形真实改变结局**（`test_terrain_decides_actual_battle`）——山地让骑兵崩
3. **兵力优势可抵消地形劣势**（`test_mass_advantage_can_override_terrain`）——平原骑兵 4:1 碾压步兵；山地 4:1 骑兵崩，8:1 才翻回来。地形重要但不是决定一切

### 6.1 调平记录（v1.0 → v1.1）

**问题**：v1.0 实测发现「骑兵 vs 弓兵 6 回合（60 秒）结束」，而同兵种要 23~27 回合。根因是1.30 克制增益叠在骑兵面板优势（兵力 14 vs 7，正好 2 倍）上，等效于 3.6 倍输出，弓兵还没来得及发挥就被秒。

**根因分析**：克制系数（1.30）和面板差异（2 倍）叠乘，单一组合的等效输出可达 3.6 倍。这不是克制的问题，是**面板差距与克制增益的乘积没有上限约束**。

**修法（三步，逐步收窄）**：

| 步骤 | 改动 | 骑兵 vs 弓兵回合数 |
|---|---|---|
| v1.0 初值 | 骑兵 14/70/6，弓兵 40/4 | 6 回合 |
| ① 降骑兵兵力 | 14 → 12 | 7 回合 |
| ② 提弓兵生存 | 士气 40 → 52，防御 4 → 6 | 8 回合（防御过高连带触发另一项断言） |
| ③ 定稿 | 弓兵防御 6 → 5，骑兵士气 72/ 防御 7，`DAMAGE_SCALE` 0.1 → 0.115 | **7 回合，70 秒** |

**最终取舍**：接受 70 秒这个数值。理由——骑兵对弓兵的碾压本身就是设计意图（"骑兵必须被步兵护着"，见 §3），70 秒的窗口正好是玩家下令"弓兵退后、步兵上前"的反应时间。如果压到 20 回合以上，克制就失效了。

**同时保证**：同兵种对拼 17~24 回合（170~240 秒），单兵对决仍在 8~20 回合区间内（`test_same_class_duel_turns_in_range`）。

## 7. 验证标准与执行结果

44 项测试，全部通过。分五类：

| 类别 | 项数 | 覆盖内容 |
|---|---|---|
| **单调性** | 6 | 士气/体能/兵力/将领加成/地形——任何一项上调，输出必须上升 |
| **量级** | 6 | 单兵对决 8~20 回合；单回合伤亡 4%~25%；局部交战 1~6 分钟 |
| **方向性** | 8 | 三角克制三向成立 + 反向受罚 + 互为倒数 + 净收益≥25% + 地形偏好 + 克制不被属性抵消 |
| **边界鲁棒性** | 15 | 无负伤害、命中率不越界、减伤合法、士气夹紧、零兵力安全、越界输入夹紧、未知配置显式报错、全组合无 NaN/Inf |
| **战斗结算** | 9 | 规模无关性、时长区间、克制与地形真实改变结局、溃退触发 |

**三条防假阴性设计**（防止"实际有问题报全绿"）：

1. `test_morale_only_affects_output_and_mitigation_not_hit` —— 固定住这次发现的"士气重复计算"缺陷，防止改回去
2. `test_counter_cannot_be_nullified_by_enemy_stats` —— 固定住"克制净收益只剩4%"的缺陷
3. `test_battle_scale_invariance` —— 50 人和 50000 人必须得到完全相同的回合数，否则说明公式里混进了规模

## 8. v1.1 自审：仍存在的问题

| # | 问题 | 我的判断 |
|---|---|---|
| 1 | 「骑兵 vs 弓兵 7 回合」仍短于同兵种（17~24 回合）| **已处理，接受**。见 §6.1 调平记录。70 秒是玩家下令"弓兵退后"的反应窗口，压更长则克制失效 |
| 2 | 「双方均被打散」在实际游戏中无法区分是谁先崩的 | **已改表述**，不再叫"同归于尽"。原型需在界面上明确显示先崩溃的一方 |
| 3 | `DAMAGE_SCALE = 0.115` 与 `SOLDIER_HP = 10` 两个常量共同决定回合数，改一个就要重调另一个 | **建议合并为单一常量** `TURN_DAMAGE_BASE`，让回合数只由一个参数控制。当前已由测试锁定在合理区间，但设计上仍是隐患 |
| 4 | 士气只在战后结算，战斗中看不到士气变化，玩家感受不到"局势在恶化" | **待原型验证**。可能的方案是每回合广播士气变化事件，但会增加战斗层实现复杂度 |
| 5 | 只测了三兵种互克，没有测混编部队（如 600 步兵 + 400 骑兵） | **下一段做**。混编是实际游戏的主要形态，纯兵种对拼是特例 |
| 6 | 所有地形都在平原基准上做加减，没有绝对基准校验 | 平原即基准（系数全 1.0），该假设已由 `test_terrain_favors_expected_classes` 锁定 |
| 7 | AI 副将的"不犯错但也不冒险"尚未量化 | **待做**。需定义 AI 决策规则表：什么条件下它会做出错误决策 |
| 8 | 伤亡比例极值差距达 3.4 倍（骑兵打弓兵 12.5% vs 骑兵山地打步兵 3.7%） | **暂接受**。这个差距正是"地形与克制决定战局"的设计意图。若原型实测发现玩家完全无法预判，需收窄地形系数区间 |

## 9. 下一段工作

**混编部队的批量结算模型 + 测试**。理由：实际对局不会是一个兵种对另一个兵种，而是"你带了 3 个编制"。这是数值模型从"对拼表"变成"可支撑一整场会战"的最后一块。

产出：`resolve_engagement()` —— 接受双方多编制配比，返回分兵种伤亡明细与战果判定；配套测试覆盖比例缩放、兵种搭配、溃退传导（一个编制崩溃是否拖垮全队）。
