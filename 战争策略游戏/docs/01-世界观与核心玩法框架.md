# 战争策略游戏 · 世界观与核心玩法框架 v0.2

## 0. v0.1 裁定结果（已定稿，不再讨论）

| # | v0.1 提出的问题 | 裁定 |
|---|---|---|
| 1 | 双视角两套操作逻辑易做成两个半成品 | **保留双视角，原型期切换后的两套操作都用最简形式**，不追求两边都精 |
| 2 | 延迟下令 + AI 副将保守的惩罚可能太重 | **延迟设 30 秒；AI 副将定位为「不犯错但也不冒险」**，参数靠实测调 |
| 3 | 六维属性过多，新手难上手 | **原型砍到四维**：兵力 / 士气 / 体能 / 地形适应。指挥加成并入体能，兵种相性独立成克制表 |
| 4 | 小队级操控抽象、士兵级太琐碎 | **取消小队级操控**，改士兵级 + 框选群体下令。这是明确取舍 |
| 5 | 单季 5 小时节奏太重 | **原型会战压到 5~10 分钟，一季 6 场，总时长 1 小时内** |
| 6 | 士兵级到 20 万人会战是巨大技术跨度 | **接受，但强制数据抽象向上兼容**：士兵数据结构必须设计成可聚合为小队/部队，避免推倒重来 |
| 7 | 强叙事 vs 纯系统驱动 | **偏后者：纯系统驱动**。不做强叙事，情感由系统涌现（你的兵败了就是败了，不用剧情解释） |

**由第 7 条推导出的设计准则（后续所有文档遵守）**：
- 不写人物剧本、不写有名战役、不做剧情过场
- 将领是**数值+标签**，不是角色（详见 §3.4）
- 世界观只提供"这套系统为什么成立"的解释，不承担叙事任务
- 所有乐趣来自系统本身：选择 → 后果 → 反直觉但可推导

**新增范围（项目概览更新后并入）**：本项目除战斗与战略外，还包含**基建、经济、民生、以及各类任务系统**。v0.1 把经济整体砍到后期是错的——它不是后期内容，它是与战斗并列的第二条主循环。v0.2 起补齐，见 §5。

## 1. 一句话定位（不变）

**你是一位有实权的将领：既能站在战线最前面带着几千人冲阵，也能把手下的整个军镇交给幕僚，自己坐在大地图上调动十万大军。**

核心张力：**视角切换本身就是代价**。亲自上阵 = 你在战场上但远离大地图；坐镇中军 = 你看得见全局但战线胜负依赖 AI 副将的执行力。

## 2. 世界观框架（不变）

### 2.1 年代与质感

低魔、近历史。唐末到五代十国的质感，混少量火药器械。

| 层 | 内容 |
|---|---|
| 时代质感 | 类唐末五代十国，或三国 + 少量火药器械 |
| 超自然 | **几乎没有**。有，但不作为战斗机制——只作为"名将"个人威望的解释 |
| 战争规模 | 一场会战 3万–20万人；一个大势力 30万–80万人 |

**为什么这样定**：真实战争史里的决定性因素（后勤、地形、士气、指挥、情报）已经足够复杂，加魔法会让数值框架变成"法师对轰"，丢掉战争策略的质感。

### 2.2 世界结构：三层嵌套

```
世界层：5~7 个大势力（强弱分明，有吞并关系）
  └ 战役层：一季 6 场会战，构成一场战争
      └ 战斗层：一场会战内的实时对抗
```

### 2.3 势力设计骨架

每个势力的"性格"由 5 个标签决定：

| 标签 | 含义 | 对玩法的影响 |
|---|---|---|
| 兵种专精 | 强在哪（如"骑兵最强"） | 决定该势力在什么地形/对手面前有优势 |
| 统帅质量 | 将领平均水平 | 决定 AI 部队的自动战斗表现 |
| 组织度 | 后勤与行政能力 | 决定能打多长的持久战 |
| 民心可用度 | 能否强行征兵 | 决定短时间内能爆多少兵 |
| 地缘 | 所在位置 | 决定扩张方向与被夹击风险 |

**设计意图**：让玩家在第 2 局就发现"我不该打这个对手"——用地缘和兵种克制制造非对称决策。

## 3. 核心玩法拆解

### 3.1 双视角切换（招牌机制）

| | 个人视角（上阵） | 战略视角（运筹） |
|---|---|---|
| 视角 | 第一/第三人称，贴地 | 上帝视角，地图 + 3D 缩略 |
| 你能做 | 亲自冲锋、局部调度、鼓舞士气 | 调动全军、后勤、编制、任务 |
| 你不做 | 看不到远方战场 | 无法影响单场战斗里的具体操作 |
| 失败代价 | 你阵亡 = 战役失败 + 角色永久重伤 | 前线溃败 = 丢地盘 |

**切换代价（防止玩家全程用战略视角躺着赢）**：
- 上阵期间，战略视角的指令下达有 **30 秒**游戏内延迟
- 你不在中军时，AI 副将「不犯错但也不冒险」——不会打妙手，也不会送兵
- 转场有**行军时间**（战略视角移动 = 个人视角也要跑）

### 3.2 四个操作循环

**循环 A · 战术层（秒级，战斗中）**
编队 → 选目标 → 下令 → 微调 → 撤退/追击

**循环 B · 战役层（小时级，一次会战）**
侦察 → 定目标 → 排兵布阵 → 下令推进 → 临机换阵 → 收尾追杀

**循环 C · 经营层（天级，战斗中也在跑）**
基建 → 征兵 → 补给 → 民心 → 任务（见 §5）

**循环 D · 战略层（天级，一季）**
养兵练兵 → 外交离间 → 情报刺探 → 决定开战对象 → 分配兵力 → 结算扩张

**关键设计**：循环 C 与循环 A **同时运行**。你在战场上指挥千军万马的同时，后方的基建进度、民心下降、补给线在被消耗。这让"上阵"和"经营"不是两个游戏，而是一个游戏的两面。

### 3.3 系统清单（已更新）

| 系统 | 原型阶段 | 后期 |
|---|---|---|
| 实时战斗（士兵级战术） | ✅ 必需 | + 士气/地形/天候细化 |
| 兵种与编制 | ✅ 必需（3 兵种） | + 兵种树、装备、后勤等级 |
| 双视角切换 | ✅ 招牌，必须 | + 行军中的遭遇战 |
| **基建系统** | ✅ **必需（简版）** | + 城池等级、设施树 |
| **经济/资源系统** | ✅ **必需（简版）** | + 贸易、市场波动 |
| **民生/民心系统** | ✅ **必需（简版）** | + 人口结构、迁徙、灾荒 |
| **任务系统** | ✅ **必需（简版）** | + 任务链、失败后果、剧情化（与纯系统驱动准则冲突则不加剧情） |
| 大地图（势力、地形、行军） | 简化（静态图 + 行军） | + 围城、补给线网络 |
| 将领与武将 | 数值+标签（无剧情） | + 技能树、性格、忠诚度 |
| 外交与情报 | ❌ 先砍 | + 情报网、离间、伪造 |

**取舍说明**：基建/经济/民生/任务在原型期做"简版"——只保留能支撑"你在前线打仗，后方在消耗"这一条核心感受的系统，不做完整模拟。

### 3.4 将领系统（按"纯系统驱动"重定义）

将领不是角色，是**一组数值 + 若干标签**：

```
将领 = {
  统率: 1~10,   # 影响部队整体作战效率
  武力: 1~10,   # 影响个人上阵时的战斗力
  智力: 1~10,   # 影响情报、外交、任务成功率
  体力: 1~10,   # 影响行军速度、可连续作战场次
  特长: [标签]  # 如"骑战" "伏兵" "水战"
  性格: [标签]  # 如"激进" "持重" "残暴" —— 影响 AI 决策倾向
}
```

**性格标签是"纯系统驱动"的关键设计**：将领的 AI 决策完全由性格标签决定，不写任何剧情。"残暴"将领的部队在获胜后士气涨得快但民心掉得快——这是一条可推导的规则，不需要任何故事来解释。

## 4. 战斗系统与数值框架

### 4.1 三层单位

| 单位 | 规模 | 存在于 | 由谁指挥 |
|---|---|---|---|
| 士兵 | 1 人 | 个人视角 | 你（直接操作） |
| 部队 | 500~3000 人 | 战略视角 | 你 / AI 副将 / 敌将 |

**按裁定 #4**：取消 20~50 人小队级单位。士兵数据结构预留聚合接口（裁定 #6），但原型不暴露小队层操控。

### 4.2 数值框架：四维（裁定 #3 砍维）

| 属性 | 简写 | 作用 |
|---|---|---|
| 兵力 | STR | 攻击与防御的基础量 |
| 士气 | MOR | 减伤、抗负面、逃跑阈值 |
| 体能 | STA | 持续作战能力、疲劳衰减 |
| 地形适应 | TER | 在该地形上的效率加成 |

**已合并**：
- 原「指挥影响 CMD」→ 并入 STA（将领统率通过提升部队 STA 生效）
- 原「兵种相性 ARM」→ 独立为三角克制表，不再作为个体属性

**有效战斗力与伤害公式（初版，待实测调）**：

```
有效战斗力 = 兵力 × (1 + 士气/100) × (1 + 体能/100 × 0.5) × 地形系数 × 兵种系数 × 将领加成
命中率    = 基础命中率 × (1 + 地形修正) × (1 - 对方士气/200)
每回合伤害 = 有效战斗力 × 命中率 × (1 - 对方防御/200)
```

### 4.3 兵种三角克制

```
步兵 → 克 骑兵（长枪拒马）
骑兵 → 克 弓兵（机动冲击）
弓兵 → 克 步兵（远程消耗）
```

外加**地形修正**：山地骑兵重罚、森林弓兵加成、城攻防战大幅加成。

**设计意图**：三角 + 地形 = 决策深度足够，且玩家能记住。复杂相克表会让玩家查表instead思考。

### 4.4 数值节奏基线

| 阶段 | 时长占比 | 玩家该感受到什么 |
|---|---|---|
| 接触前 | 10% | 紧张、侦察、布置 |
| 初期接触 | 20% | 试探、消耗、小规模交锋 |
| 主力决战 | 40% | 高强度、看指挥能力 |
| 追击/溃败 | 30% | 收割或止损，判断何时收兵 |

单场会战 5~10 分钟（裁定 #5）。

## 5. 经营层：基建 / 经济 / 民生 / 任务（v0.2 新增）

这是本项目的**第二条主循环**，与战斗并列，不可后置。

### 5.1 三种资源

| 资源 | 主要来源 | 主要消耗 | 关联玩法 |
|---|---|---|---|
| **粮** | 农业产出、缴获 | 养兵、行军、攻城 | 行军距离上限、部队规模 |
| **金** | 工商业、贸易 | 装备、赏赐、基建 | 基建速度、装备采购 |
| **兵源** | 人口 × 民心可用度 | 征兵 | 战斗兵力上限 |

**硬约束**：粮不足 → 行军距离受限、士气下降。粮为 0 → 部队溃散。**这条是整个经营层的支点**，让"你可以打这场仗"变成一个真实的问题，而不是无限资源下的表演。

### 5.2 基建系统（简版）

```
据点等级 1~5，每级提供：
  - 驻军上限
  - 屯兵量（战前集结上限）
  - 防御加成（守城战）
  - 基建产出速率
```

**简版规则**：每级升级需要「金 + 粮 + 时间」，时间按游戏内天计。升级中该据点防御下降 20%（不能无脑连升）。

**设计意图**：基建是"投资 vs 战线"的时间博弈——你现在升级据点，前线就少一个能打的兵。

### 5.3 民生 / 民心系统（简版）

```
民心 ∈ [0, 100]，初始 50

民心下降来源：
  - 强征兵（超过人口 10% 的征召）
  - 战败（尤其是己方将领阵亡）
  - 税收过高（税率 > 可承受线）
  - 长期无战事且无犒赏（ boredom）

民心上升来源：
  - 战后犒赏
  - 减免赋税
  - 胜利 + 低伤亡
```

**关键规则**：民心 = 兵源上限 × 民心可用度系数。

```
可征兵数 = 人口 × 0.10 × (民心 / 50)
```

**这条规则让"打赢了但把民心打没了"成为一个真实的失败路径**——纯粹的胜利数字高但玩不下去。

### 5.4 任务系统（简版）

三类任务，构成日常节奏：

| 任务类型 | 内容 | 奖励 | 失败后果 |
|---|---|---|---|
| **军事任务** | 剿匪、守城、护粮道 | 兵源、金 | 民心下降 |
| **经营任务** | 建据点、开垦、修渠 | 粮、金 | 无（安全） |
| **内政任务** | 征兵演练、整顿吏治 | 民心、组织度 | 民心下降 |

**任务的作用不是"做"，是"选"**：每个时段只能推进 1~2 个任务，选军事就放弃发展，选发展就可能错过战机。

**失败后果的设计意图**：这是"纯系统驱动"的重要体现——任务失败不触发剧情，只给数字惩罚和下一段的连锁影响（民心低 → 可征兵少 → 下次战斗兵力不足）。

### 5.5 经营层与战斗层的耦合（最重要的设计点）

这是让"战争策略"而不是"战争模拟 + 放置游戏"的关键：

```
你上阵时（战斗层运行中）：
  → 后方基建进度继续推进（但你看不到，无法调整优先级）
  → 粮持续消耗（行军 + 养兵）
  → 民心缓慢下降（久无进展）

你不上阵（战略视角）：
  → 可以调整基建优先级、征兵、谈判
  → 但战斗层的战斗由 AI 副将打，胜率下降（裁定 #2）
```

**一句话总结耦合设计**：**你在战场上的时候做不了决策，不在战场上的时候打不了胜仗。**

## 6. 原型阶段的最小可玩目标（MVP）

范围界定：

**战斗侧**
- 1 张会战地图（约 2km × 2km，含山地/平原/林地/河谷 4 种地形）
- 3 兵种（步兵 / 弓兵 / 骑兵）
- 士兵级操控 + 框选群体下令
- 1 个敌方势力（AI 指挥，规模略大于玩家）

**经营侧（简版）**
- 3 种资源（粮/金/兵源）
- 1 个据点，可升级 1~3 级
- 民心值 + 简化收支
- 3 类任务各 1~2 个

**视角**
- 双视角切换（个人 ↔ 战略），两套操作都做最简形式

**不做**：完整大地图、多势力、外交、装备科技、复杂兵种树。

**为什么先做这些**：战斗系统技术风险最高、数值一旦错后面全歪。经营侧只做能支撑"后方在消耗"这一条核心感受的最小闭环，不做完整模拟。

## 7. v0.2 自审：我认为仍然不合理的点

| # | 问题 | 我的判断 |
|---|---|---|
| 1 | 「任务失败只给数字惩罚」在纯系统驱动下可能缺少情绪反馈，玩家会麻木 | **接受**。麻木是策略游戏的常态，不是缺陷。但任务失败时应给**清晰的因果链**（"你征兵过度 → 民心崩 → 下次只能带 8000 人 → 打不过 12000 人"），让玩家自己得出结论 |
| 2 | 基建"升级中防御 -20%"可能成为玩家无脑追求的漏洞（升级前先被打一次） | **需要在实测中调**。若确实是最优解，改为"升级中不可调兵"，更干净 |
| 3 | 民心公式线性（民心/50），意味着民心 100 = 人口 20% 的兵源，可能过于重要 | **待实测**。若发现民心成了唯一瓶颈，改为分段递减（如 50 以上收益递减） |
| 4 | 简版任务系统可能变成"每天点一下领奖励"，失去决策感 | **设计上已用"同时只能推进 1~2 个"来制造取舍**，但需要在原型中验证取舍是否真实存在 |
| 5 | 双视角切换 + 经营层同时运行 = 玩家在战场上还要惦记粮够不够，操作负担可能是全项目最重的 | **待实测**。若负担过重，一个方案是把粮的消耗改为"战斗开始前一次性结算"，减少实时牵挂 |
| 6 | 纯系统驱动下没有强叙事，"情感涌现"能否真的成立仍未验证 | **这是最大风险，但无法靠讨论解决，只能靠原型实测**。第 5 条 MVP 做完后就能验证 |

**下一段工作**：战斗系统的详细数值表（三兵种基础值、四维属性区间、地形系数表、克制倍率、伤害公式的完整参数），并用确定性纯函数 + 单测验证公式的量级和单调性。这份表格是原型代码的直接输入。
